## Goal

Wire the complete-but-dead `PickerModel` (`internal/chat/picker.go`, 237 lines, zero
references outside its own file — re-confirmed at `b998200`) into a new
`PhasePickConversation` so a returning user can browse stored conversations and replay one,
read-only, with an honest banner. Branch stays disabled (action swallowed, code kept). The
stored-message → renderable-message mapping (`ReplayMessages`) follows shim dossier A.3
verbatim, and decode fixtures byte-synced with the shim's own tests lock the cross-repo
contract before #351 lands.

## Approach

**Branch and merge protocol.** Branch `cockpit/replay` off chat-patterns `main @ b998200`.
Sibling in flight: **#353 (token footer, `cockpit/footer`)**, specified concurrently — no
spec posted on #353 yet. Expected shared files: `internal/chat/model.go` (#353 may extend the
capture fields / totals near L222-229; this PR adds `ReadOnly` to the same struct and a
short-circuit in `submit()` L622-655) and `internal/chat/view.go` (#353 owns the status-line
slot in `View()` L71-93; this PR touches only `RenderHeader()` L116-153). Different regions,
trivial rebase. Per plan §1: open against `main`, no stacking, first-approved merges first,
the other rebases and lets CI re-run. Merges strictly serial.

**Contract lock — golden fixtures (the hard edge to #351).** The Go side must not invent its
own idea of the shim's wire format. Two fixture files land under
`internal/httpclient/testdata/`:

- `shim_conversations_list.json` — a bare top-level array of two summaries (different
  agents), snake_case keys exactly as shim dossier **A.1** emits them (`id`, `agent_name`,
  `model`, `state`, `exchange_count`, `total_input_tokens`, `total_output_tokens`,
  `created_at`, `updated_at`; **no** `branched_from_id` — its absence is part of the
  contract: the `*T`+`omitempty` Go fields must decode nil).
- `shim_conversation_detail.json` — one detail object per **A.2**: camelCase dashboard keys
  *plus* the additive aliases (`agent_name`, `state`, `exchange_count`, `created_at`,
  `updated_at`) and inline `messages[]` with `sequence` = array index and parts
  `{type, content, metadata}` — covering `user_prompt`, `text`, and a content-null
  `state_delta` carrying `metadata.event` (e.g. `"backpack.drop"`).

**Sync discipline** (JSON forbids comments, so it lives in a sibling
`internal/httpclient/testdata/README.md`): the source of truth is the TS shim's test
expectations in `packages/agent-server/src/__tests__/conversations.test.ts` (extended by
#351 per shim dossier A.4 #2/#4). Until #351's PR opens, the fixture bytes are authored from
shim dossier A.1/A.2 directly. The `cockpit/replay` PR carries a mandatory checklist item:
*"fixture bytes reconciled against #351's merged test seeds (or #351 confirmed unmerged and
the dossier remains authoritative)"*. Any later shim change that alters these shapes must
update both repos' fixtures in the same review cycle — the README names this rule and both
file paths. If spec/impl for #351 posts fixture seeds before this PR merges, byte-copy
theirs.

**App flow (`internal/app/model.go`).** New `PhasePickConversation` between
`PhaseSelectAgent` and `PhaseScopeSetup` (order: SelectAgent → PickConversation →
ScopeSetup(new-only) → Chat).

- **Agent-select enter** (`updateAgentSelect`, L332-355): extract the current body of the
  enter case — chat construction (L335-336), `loadErr` reset (L337), and the three-way scope
  entry decision (L339-354) — into a helper `startNewConversation(agent types.AgentSummary)`,
  *unchanged in behavior*. The enter case now stores `m.replayAgent = agent` and fires
  `client.ListConversations(ctx, "")` as a `tea.Cmd` returning `chat.ConversationsLoadedMsg`.
  **No `?agent_name=` filter (R3-1, locked)**: the shim filters on the store's
  `agentName` (= `role.name`), not the registration name — rows self-label instead
  (`picker.go:188` renders each row's own `AgentName`).
- **Deliberate deviation from the dossier sketch**: the phase does NOT flip on enter.
  We stay in `PhaseSelectAgent` until `ConversationsLoadedMsg` arrives, then decide.
  Rationale: R3-2 (skip on empty-or-error, locked in the issue) would otherwise flash a
  loading picker and bounce for every empty history. The list call is a local-server
  round-trip; the wait is imperceptible, and a repeat enter while in flight is harmlessly
  idempotent (last response wins).
- **`ConversationsLoadedMsg` handling** (new typed case in `Update`, alongside L211-301):
  `Err != nil` **or** zero rows → `startNewConversation(m.replayAgent)` — identical UX to
  today, which is the degradation contract for 503 persistence-off, nil/nil transports
  (cliclient/execclient/demo all return empty), and old servers 404ing. Rows present →
  `m.picker = chat.NewPicker(m.replayAgent.Name)`, `m.picker.SetSize(m.width, m.height-5)`,
  forward the msg into `m.picker.Update` (it consumes it, `picker.go:62-70`), set
  `m.phase = PhasePickConversation`.
- **`ConversationSelectedMsg`** (new typed case): `ActionNew` →
  `startNewConversation(m.replayAgent)` (scope entry decision runs exactly as today).
  `ActionContinue` → fire `client.GetConversation(ctx, msg.ConversationID)` as a `tea.Cmd`
  returning app-local `conversationLoadedMsg{Detail, Err}`. **`ActionBranch` → swallowed**
  (empty case with a comment; the picker's `b` key at `picker.go:105-116` becomes a no-op at
  the app boundary — picker code kept, shim leaves branch fields omitempty → nil, badge
  never renders).
- **`conversationLoadedMsg`** (new app-local msg): `Err != nil` → set `m.loadErr`, back to
  `PhaseSelectAgent` (renders in the existing error block, L427-432). Success →
  `m.chat = chat.New(m.client, msg.Detail.AgentName, m.registry)`; `SetSize`;
  `SetConversationID(msg.Detail.ID)`; append `chat.ReplayMessages(msg.Detail)` via
  `AppendMessage`; `m.chat.ExchangeCount = msg.Detail.ExchangeCount` (the never-assigned
  header badge, `view.go:133-139`, finally gets a writer); `m.chat.ReadOnly = true`; append
  one system line `"read-only replay — the server cannot resume stored conversations yet"`;
  `GotoBottom()`; `m.phase = PhaseChat`.
- **Phase plumbing**: `updatePicker` arm in the phase dispatch (L303-310) forwarding
  `tea.KeyPressMsg` to `m.picker.Update`, with `esc` → back to `PhaseSelectAgent`;
  `WindowSizeMsg` case (L161-179) additionally resizes the picker; `View()` (L390-397) gains
  a `PhasePickConversation` arm rendering `m.picker.View()`; `renderLegend` (L478-501) gains
  the hint `"j/k: navigate  enter: open  esc: back"` (no `b` — branch is disabled this
  round).

**Replay renderer — new `internal/chat/replay.go`.** Pure function, mapping per shim A.3
(see Interfaces): `kind "request"` → `RoleUser`, `"response"` → `RoleAssistant`;
`user_prompt`/`text` → `PartText` (skip empty content); `state_delta` → `PartStatus`
`"Δ <metadata.event>"` (metadata-less → `"Δ state change"`); `tool_call` → defensive
`PartStatus` (never persisted today — `_persistExchange` writes only
`user_prompt|text|state_delta`, `agent-runtime/src/conversation/conversation.ts:359-390`);
unknown types → labeled `"[<type> part]"` degradation, never crash; messages with zero
rendered parts dropped; input order preserved (shim guarantees ascending `sequence` = array
order). All parts `Complete: true` (chat `MessagePart` fields verified at
`chat/model.go:118-126`).

**Read-only stance (R3-3, locked).** New `chat.Model.ReadOnly bool` — doc comment must
distinguish it from the existing per-card `InputRequestPart.ReadOnly` (`chat/model.go:93-96`,
which means "transport can't answer HITL"): the model-level flag means "replayed
conversation; server cannot resume stored ids (in-memory registry — a send would 404,
`agent-server/src/routes/conversations.ts` per gap-analysis §1.9)". In `submit()`
(`chat/model.go:622`), short-circuit **before** `m.input = ""` (L628) and **only for
non-slash input**: trimmed text not starting with `/` while `ReadOnly` → append the system
line `"read-only replay — the server cannot resume stored conversations yet"`, rebuild
viewport, return with the input buffer *intact* (the user's typed draft is never burned —
they can copy it out). Slash commands flow through unchanged (`/help`, `/agents`, `/scope`
all behave; `/scope` honestly answers "(no scope bound)" since no 201 echo exists for a
replayed conversation). Render a `replay` badge in `RenderHeader` (`view.go:116-153`), same
`atoms.BadgeData` outline idiom as the `IsBranch` badge at L141-147. Lift trigger stays as
plan §7: a server-side rehydrate route.

**Wire decode.** One struct change: `types.MessagePart` (`internal/types/types.go:224-227`)
gains `Metadata map[string]any \`json:"metadata,omitempty"\`` — the only way to label
`state_delta` parts (their `content` is deliberately null) and to hydrate future `tool_call`
detail (shim A-3 emits `metadata` now precisely so no second server PR is needed).
`Conversation` (L188-199), `ConversationDetailResponse` (L202-213), `ConversationMessage`
(L216-221), endpoint defaults (`/conversations`, `/conversations/{id}`, types.go:240-241),
and both httpclient methods decode the shim shapes **as-is** — verified field-by-field
against A.1/A.2.

## Interfaces

```go
// internal/app/model.go
const (
    PhaseSelectAgent Phase = iota
    PhasePickConversation // NEW — browse stored conversations (skipped when list is empty/errored)
    PhaseScopeSetup
    PhaseChat
)

// conversationLoadedMsg carries a fetched conversation detail for replay (app-local).
type conversationLoadedMsg struct {
    Detail *types.ConversationDetailResponse
    Err    error
}

// startNewConversation runs the (unchanged) #348 entry decision for a fresh
// conversation: immediate create (nil scope), DefaultScope bypass, or PhaseScopeSetup.
func (m Model) startNewConversation(agent types.AgentSummary) (tea.Model, tea.Cmd)

// internal/chat/replay.go
// ReplayMessages converts a stored conversation detail into renderable messages.
// Mapping is shim dossier A.3 verbatim; unknown part types degrade labeled, never crash.
func ReplayMessages(d *types.ConversationDetailResponse) []Message

// internal/chat/model.go — Model gains (distinct from InputRequestPart.ReadOnly, which
// means "transport cannot answer HITL"):
// ReadOnly marks a replayed conversation: the server's registry is in-memory and
// cannot resume stored ids, so submit() short-circuits regular messages with an
// honest system line (slash commands still work). Lifted when a rehydrate route exists.
ReadOnly bool

// internal/types/types.go
type MessagePart struct {
    Type     string         `json:"type"`
    Content  *string        `json:"content,omitempty"`
    Metadata map[string]any `json:"metadata,omitempty"` // NEW — labels state_delta (metadata.event), future tool_call detail
}
```

## Tests

All offline (`just quality` green in CI is the required status); the live leg is demo-gated
on #351.

1. **`internal/chat/replay_test.go`** (pure): request→user / response→assistant;
   `user_prompt`+`text` → `PartText` with content; empty/nil content skipped;
   `state_delta` + `metadata.event: "backpack.drop"` → `PartStatus "Δ backpack.drop"`;
   metadata-less `state_delta` → `"Δ state change"`; `tool_call` → defensive status;
   unknown type → `"[x part]"`; message whose parts all skip → dropped; ordering preserved;
   every part `Complete: true`.
2. **`internal/chat/model_test.go`**: `ReadOnly` submit with typed text → **zero** client
   calls (stub whose `SendMessage` fails the test) + system line appended + input buffer
   preserved; `/help` still executes under `ReadOnly`.
3. **`internal/app/replay_test.go`** (extend `fakeClient`): agent enter →
   `ListConversations` called with `""`; `Err` → straight to entry decision (no
   `PhasePickConversation`); empty rows → same skip; rows → `PhasePickConversation`; enter
   on a row → `GetConversation` called → `PhaseChat` with `ExchangeCount` set and
   `ReadOnly` true; `b` on a row → no client call, phase unchanged; `esc` in picker → back
   to `PhaseSelectAgent`; `ActionNew` with an `instantiation.available` agent →
   `PhaseScopeSetup` (entry decision intact — regression guard on the extraction).
4. **`internal/httpclient/client_test.go`** (fixture decode = the contract lock):
   `httptest.Server` returns the golden fixture bytes verbatim; `ListConversations` →
   2 rows, every field non-zero, `BranchedFromID`/`BranchedAtSequence` nil;
   `GetConversation` → detail with `Messages[].Parts[].Metadata` populated for the
   `state_delta` part and `Content` nil for it; `Sequence` ascending. (Zero-value decode
   was N3's silent failure mode.)
5. **Live acceptance (deferred until #351 merges + `AP_PERSISTENCE` on; needs an LLM
   key)**: create → one keyed turn → restart TUI → picker shows the row with
   `exchange_count 1` → replay renders both turns + `replay` badge + read-only banner;
   typed text bounces with the system line; `/help` works. Recorded here for #357's
   walkthrough, not CI.

## Out of scope

- **Branch UI** (`b` key action, branch badges) — swallowed at the app boundary; picker
  code kept; shim omits the fields (plan §7, re-entry: server-side branching).
- **Rehydrate/resume** — `ReadOnly` lifts when a server rehydrate route exists (plan §7).
- **`StoredConversationSummary` token-split** (A-1) — route-level N+1 accepted at picker
  scale; server-side concern anyway.
- **`?agent_name=` filtering** (R3-1) and a `/history` command to re-open the picker
  mid-chat — revisit if the unfiltered list gets noisy.
- **Esc-from-replay returning to the picker** — esc follows today's path to
  `PhaseSelectAgent` (`updateChat` L363-376 unchanged); re-stashing picker state is
  plumbing with no locked requirement (see Open questions).
- Any TS-repo change — #351 owns the shim; this PR must not require a server release.

## Open questions

- **Q1 — esc from a replayed chat**: lands on `PhaseSelectAgent` (existing path), not back
  in the picker. Acceptable for MVP? (Recommend yes — one extra enter re-opens the picker;
  keeping picker state adds a stash/restore path for marginal gain.)
- **Q2 — `chat.Model.ReadOnly` naming**: collides conceptually with the pre-existing
  `InputRequestPart.ReadOnly` (HITL-transport semantics, #350). The issue text locks
  `chat.Model.ReadOnly`; spec keeps it with a disambiguating doc comment. Confirm, or
  prefer a rename to `Replay` while the field is fresh?
- **Q3 — fixture reconciliation timing**: #351's spec had not posted when this spec was
  written; fixtures are authored from shim dossier A.1/A.2 and the PR checklist forces
  reconciliation against #351's merged test seeds. If #351's spec lands first and ships
  differently-shaped seeds, byte-copy theirs and note the delta in the PR. OK as the
  protocol of record?
- **Q4 — stay-in-SelectAgent-until-loaded** (deviation from the dossier's
  set-phase-immediately sketch, forced by locked R3-2 skip semantics): confirm the
  no-loading-flash tradeoff — the enter feels instant against a local server, but there is
  no spinner if the list call is ever slow.
