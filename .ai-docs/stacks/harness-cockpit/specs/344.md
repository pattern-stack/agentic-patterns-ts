## Content requirements

### 1. Fix #1 — send path + body key

Exactly the dossier §1.1 diff: default path `"/conversations/{id}/send"` →
`"/conversations/{id}/messages"` (code catches up to its own `types.go:178` comment —
resolves N6), and `SendMessageRequest{Content: content}` marshaling `{"content"}`. Legacy
posture (OD §7.4, locked): the *path* stays overridable via `EndpointConfig.SendMessage`;
the *body key* is canonical-only — the legacy `/send`+`{"message"}` pairing dies with no
compat flag.

### 2. Fix #2 — create body `agent_name` → `agent_id`

Dossier §1.2 core diff only: DTO field rename + marshal-site update (`client.go:171`).
Kills the misleading N2 404 (server looks up `undefined`). The response decode is already
safe (only `.ID` read; `Greeting` stays empty and is only rendered when non-empty).
**Do NOT add the `Scope` field or `CreateOptions` param here** — that interface ripple
(6 implementations) is #348.

### 3. Fix #3 — role-object decode, in BOTH httpclient and contracttest

**Site A** (`client.go` ListAgents): decode via the dossier's `wireAgent` DTO:

```go
// wireAgent matches GET /agents from the agentic-patterns TS server
// (agent-server/src/routes/agents.ts:76-93). role is {id,name} | null.
type wireAgent struct {
	ID          string `json:"id"`
	Name        string `json:"name"`
	Description string `json:"description"`
	Role        *struct {
		ID   string `json:"id"`
		Name string `json:"name"`
	} `json:"role"`
}
```

Mapping to `AgentSummary`: `Role` (the picker display string) = `Description`; if empty and
`Role != nil`, fall back to `role.Name`; else `""` (OD §7.3, locked — description is
always present on the TS wire, `agents.ts:78`). Decode gate mirrors the current one
(`err == nil && len(wire) > 0 && wire[0].ID != ""`); on failure fall through to the
untouched `[]string` legacy path. Note: payloads shaped `[{"role":"a string"}]` (the stale
mock's invention — never served by any real backend) intentionally lose support (OD §7.4).

**Site B** (`contracttest/validate.go:50-54`): `Role json.RawMessage` with a comment
`// object | string | null — contract only asserts ID`. Shape-agnostic on purpose.

### 4. contracttest hardening — fifth check + mock truth + live runner

- **Fifth check (N5/#234 tripwire).** The SendMessage subtest reads the entire response
  body (server closes the stream after `done`; the suite's existing 30s ctx bounds it) and
  collects `event: <name>` lines in order. A new fifth subtest (suggested name
  `StreamContent`) asserts: **at least one `event:` line whose name is not `done` exists,
  and if a `done` line is present, at least one non-`done` event precedes it.** A torn
  stream (empty, or done-only — the N5 signature) fails loudly; a legacy stream with no
  `done` still passes via the ≥1-non-done rule.
- **Mock truth.** `mockAgent` serves `"role": {"id": "...", "name": "..."}` (+ a
  `description` field), and the mock stream appends `event: done` /
  `data: {"run_id":"run-mock-1"}` after `message.complete` — the mock models the real
  terminator so the fifth check exercises the real ordering. `ValidateBackend` must pass
  against this updated mock.
- **Live runner.** In contracttest:
  `func TestLiveBackend(t *testing.T)` — `url := os.Getenv("CHAT_BACKEND_URL"); if url == "" { t.Skip(...) }; ValidateBackend(t, url)`.
  Skipped in CI (env unset); run manually against `ap playground` at
  `http://localhost:3456`.
