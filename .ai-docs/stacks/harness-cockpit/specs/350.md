## Goal

The Gate C closer. When the server parks a turn on `input.request`, the cockpit renders an
**inline transcript prompt card** (D4 — not a modal), routes keys to it, answers over #349's
return leg, and renders every resolution path calmly:

1. All three kinds (D3): **approval** via `ConfirmPrompt` with **default DENY**
   (fail-closed zero-value), **select** via `RadioSelect` + value, **text** via a TextBuf.
   Unknown kinds fall back to the approval affordance.
2. **Trap 1 / Risk 5 (BINDING):** a deny's consequence arrives as
   `error {error_type:"ToolCallBlocked"}` — never `tool.rejected` — and renders as the calm
   `⊘ blocked:` outcome, not a red client bug.
3. **Trap 2 / Risk 6 (BINDING):** the enter-to-skip drain must not deadlock on a parked
   gate — `skipStreaming` breaks on the input-request chunk, restores streaming, re-arms
   the reader. Dedicated test whose failing mode is a test timeout.
4. **Auto-dismissal:** timeout auto-deny / own deny / teardown stamp
   `⊘ auto-denied (run ended)`; orphaned answer (404) stamps `(expired)`; other POST errors
   keep the prompt pending for retry. No client-side countdown (timeout is not on the wire —
   plan §7 deferred).
5. **Shell guards:** Esc while parked never bails to agent-select (the run would park
   forever); the abort/approval race renders as *cancelled*, not error; status line shows
   `⏸ awaiting your decision`; legend advertises the decision keys; read-only transports
   show "awaiting decision elsewhere".

## Approach

### 1. Consumed surface — what #349 (hitl-wire) provides

#349 owns the parser case, chunk vocabulary, and client method. Its strategy **posted
during this spec's authoring** (specs/349.md; still awaiting its own Gate 1) and settles
the names consumed here — if Gate 1 revises #349, the implementer reconciles mechanically
(compile errors, not design changes):

- `types.ChunkInputRequest`: prompt in `Content`; `CorrelationID` (the `requestId` alias
  is resolved **parser-side** into this one field — #349 Q1); `InputKind`
  (`approval|select|text`, unknown passed through); `Options`; the existing tool fields
  (`ToolName`, `ToolCallID`, `Arguments`) reused. `Done == false` — the reducer tail
  re-arm at `chat/model.go:767-768` fires as usual.
- `types.InputResponder` (optional capability in #347's `TurnCanceller` mold — not a
  `Client` widening) with `RespondInput(ctx, conversationID, InputResponse)`; implemented
  by `HTTPClient` only, fail-closed (empty decision → `"deny"`), always POSTing to the
  stream's own `:id` (plan §4 — B3 turns any global-key shortcut into a 404). Non-HTTP
  transports don't implement it — that IS the read-only branch.
- `ErrInputOrphaned` for the 404 no-pending-input outcome.
- Forward-compat passthrough (plan §4 R2 seam, locked): `AvailableDecisions` + raw
  `InputPayload` ride the chunk; this spec renders decision choices from
  `AvailableDecisions` when non-empty (§7), else the approve/deny pair. Decision strings
  are forwarded unvalidated (#349 Q3), so new kinds need no client release.

Nothing in this PR touches `internal/sse/`, `internal/httpclient/`, or `internal/types/` —
if implementation finds a gap there, it's a #349 change, not scope creep here.

### 2. State — part, card, single pending ref

`internal/chat/model.go`:

- New part type next to `:36-42`: `PartInputRequest PartType = "input_request"`; new
  pointer field `InputReq *InputRequestPart` on `MessagePart` (`:88-95`).
- `InputRequestPart` (next to `ToolCallPart`, `:56`): correlation id, kind, tool name,
  arguments, options, plus caller-owned interaction state — `Selected int` (approval:
  0=deny/1=approve, **zero-value 0 = fail-closed deny**; select: option index),
  `TextBuf string`, `Resolution string` ("" while pending), `Busy bool` (POST in flight).
  The part stays in the transcript after resolution as a historical card.
- Model fields (struct `:150-190`): `pendingInput *pendingRef`
  (`{msgIdx, partIdx int; correlationID string}`) and `denyExpected bool` (turn-scoped: set
  by our own deny and by auto-dismissal; discriminates §4's calm-blocked render). Both
  reset in `submit()` (`:568-600`).
- Invariant: at most one pending per stream (runner parks inside `bus.publish`;
  server invariant `conversations.ts:386`) — but **always echo the stored
  `correlationID`, never assume**. Belt-and-braces: a duplicate correlation id is dropped;
  a *different* correlation id while one is pending stamps the old card `⊘ superseded` and
  adopts the new one.

### 3. Arrival + auto-dismissal (reducer changes)

**Arrival** — new `case types.ChunkInputRequest:` in `handleResponse` (switch `:618-744`),
modeled on `ChunkDelegationStart` (`:659-663`), appended to the **top-level** assistant
message (not `targetParts` — the prompt must be answerable at top level):
`ensureAssistantMessage()`; replace a lone `PartWaiting` (same swap as `:661-663`); append
the part; set `pendingInput`; `m.viewport.GotoBottom()` (the prompt must be visible to be
answerable). Fall through to the tail — `readStream` re-arms, **required** because the
timeout auto-deny frames arrive on this same channel with no client action.

**Auto-dismissal** — at the **very top** of `handleResponse`, before the `chunk.Error`
early-return (`:607-612`; *(post-#347)* that arm is the aborted/serverCancelled
discriminator):

```
if pendingInput != nil && (chunk.Error != nil || chunk.Done):
    stamp Resolution "⊘ auto-denied (run ended)"; clear pendingInput; denyExpected = true
```

Covers all three unsolicited enders (dossier §3.D3): server timeout auto-deny, our own
deny's consequence frames, stream teardown (channel close → `readStream` synthesizes
`Done`, `:1066-1074`).

**Calm blocked (Risk 5, BINDING):** in the error arm, after *(post-#347)*
`aborted || serverCancelled → "⊘ stopped"` is checked and declined: if
`chunk.Error` is the `APIError` with `Type == "ToolCallBlocked"` **and** `denyExpected`,
render a tertiary system line `⊘ blocked: <message>` (the run genuinely ended —
`conversation.end{reason:"error"}` + `done` follow) instead of the red
`"Error: …"` message. An unexpected `ToolCallBlocked` (no deny of ours, no pending card —
e.g. another client denied) keeps the existing error render. Ordering matters: an
Esc-abort race lands in the `aborted` arm first → `⊘ stopped` wins, never a red error
(locked abort/approval race disposition; #347's teardown deny-sweep does the server side).

### 4. Key routing (D4)

`handleKey` (`:420`): keep the scroll-key block first (`isScrollKey` is only
pgup/pgdown/shift+up/down/ctrl+u/d, `:412-418` — plain up/down are free for the cursor),
then insert **before** the `m.streaming` branch (`:434-441`; *(post-#347)* it also has
`case "esc" → AbortStream`):

```go
if m.pendingInput != nil {
    return m.handlePendingInputKey(msg)
}
```

`handlePendingInputKey` (new, ~60 LOC), per kind:

- **approval / unknown** (React precedent: unknown → approval): `left/right/h/l/tab`
  toggle `Selected`; `y` approve now; `n` deny now; `enter` submits current selection
  (default **deny** — zero-value); `esc` → deny (scout D4; but see §6 — the app shell
  intercepts Esc first, so in the cockpit Esc aborts; the chat-level binding serves
  standalone embedding. Open question Q1).
- **select**: `up/down/j/k` move the cursor over `Options`; `enter` → approve with
  `Value = Options[Selected]` (matches React: option click posts
  `{decision:"approve", value: opt}`); `n` deny; `esc` deny.
- **text**: printable keys append `msg.Text`; `backspace`/`alt+backspace`/`ctrl+w` edit via
  the existing `deleteChar`/`deleteWord` helpers; `enter` non-empty → approve with
  `Value = TextBuf`; empty `enter` no-op; `esc` deny. (`ctrl+u/d` were consumed by the
  scroll block while streaming — acceptable; documented, not fought.)
- While `Busy`: decision keys are swallowed (no double-submit); scroll still works.

Enter never reaches the `:436-439` skip branch while pending — routing above makes the
skip path unreachable, which is exactly the guard direction the dossier requires.

### 5. Enter-to-skip drain deadlock guard (D5 — Risk 6, BINDING)

`skipStreaming` (`:893-976`) blocking-drains `m.streamCh` on the UI goroutine. If the user
hits enter-skip **before** the gate fires, the drain swallows the input-request chunk and
then blocks forever on a parked channel — the runner never emits again until someone
answers (only the server timeout rescues). Fix:

- Signature changes to `func (m *Model) skipStreaming() tea.Cmd`; call site `:437-438`
  becomes `return *m, m.skipStreaming()` (normal drains return nil; *(post-#347)* the
  drain also has a `ChunkCancelled` case — disjoint, keep both).
- New `case types.ChunkInputRequest:` in the drain switch: perform §3's arrival append
  (state + `pendingInput`), **break out of the drain**, leave `m.streaming = true`,
  rebuild the viewport, and return `readStream(m.streamCh)` so the prompt is answered
  interactively and the resolution frames flow.
- **Dedicated test whose failing mode is a test timeout** (§ Tests, case 10): drive
  `skipStreaming` with a channel that delivers the input chunk then blocks.

### 6. Resolution round-trip + shell guards

**Submit** (`resolveInputCmd(decision, value)`): type-assert the #349 responder capability.
Not implemented (stdio/cli/exec/demo/stub) → swap the card's hint to
`awaiting decision elsewhere (client cannot respond)`, keep `pendingInput` set (server
timeout/teardown backstops; mirrors React's read-only branch), return nil. Implemented →
set `Busy`, capture `ref`/`conversationID`, return a Cmd that POSTs and yields
`InputResolvedMsg{CorrelationID, Decision, Value, Err}`. Deny submissions also set
`denyExpected = true` before the Cmd fires (the consequence frames can win the race).

**`InputResolvedMsg` handling** (new case in `Update`, `:392+`); stale messages
(pendingInput nil or correlation mismatch — the auto-dismissal race) are no-ops:

- `Err == nil`: stamp `✓ approved` / `✓ <value>` / `⊘ denied`, clear `Busy` +
  `pendingInput`, rebuild viewport. The stream then delivers the consequence through the
  already-armed reader (approve → `tool.start/…`; deny → §3's calm-blocked path).
- `Err` is #349's orphan sentinel: stamp `⊘ auto-denied (expired)`, clear pending — the
  explaining frames are already in flight (404 shape live-verified).
- Other `Err` (network / 501): clear `Busy`, append a `PartError` with the error, **keep
  the prompt pending** for retry.

**App shell** (`internal/app/model.go`): *(post-#347)* the Esc guard comes free —
`updateChat` checks `m.chat.IsStreaming()` **first** (`:282-283` on `cockpit/abort`) and a
parked turn is still streaming, so Esc → `AbortStream()`: cancel-route + ctx-cancel →
server teardown deny-sweeps the pending input (`conversations.ts:434-448`) → card stamps
`⊘ auto-denied (run ended)`, terminal line `⊘ stopped` — **cancelled rendering, not
error** (locked). Esc can no longer bail to agent-select while pending, with zero new app
code. This PR adds only: new accessor `HasPendingInput()` on `chat.Model`, and the legend
(*(post-#347)* `:403`) gains a pending variant:
`y approve · n deny · enter confirm · esc stop`. `ctrl+c` stays quit (`:166-167`) —
process exit drops the connection ⇒ server teardown deny.

**Status line** (`internal/chat/view.go:71-77`): when `m.pendingInput != nil`, replace the
streaming `"  ..."` with `⏸ awaiting your decision` (CatAgent/Running style) so the state
is visible even when scrolled up.

```mermaid
sequenceDiagram
  participant S as server stream
  participant R as reducer
  participant K as keys
  participant P as POST /input (#349)
  S->>R: input.request {correlation_id, kind, prompt}
  R->>R: card appended, pendingInput set, reader re-armed
  alt approve (y / enter on yes)
    K->>P: {decision: approve}
    P-->>R: InputResolvedMsg → ✓ approved
    S->>R: tool.start → tool.end → … → done
  else deny (n)
    K->>P: {decision: deny} (denyExpected=true)
    P-->>R: InputResolvedMsg → ⊘ denied
    S->>R: error ToolCallBlocked → calm "⊘ blocked:" → done
  else timeout (no action)
    S->>R: error ToolCallBlocked (auto-deny)
    R->>R: dismissal stamps ⊘ auto-denied (run ended); calm blocked line
  else Esc (abort — app shell, #347)
    K->>R: AbortStream → teardown; deny-sweep server-side
    R->>R: card ⊘ auto-denied (run ended); terminal ⊘ stopped
  end
```

### 7. Render (F)

`internal/chat/view.go` — new case in `renderPart` (`:289-380`, after `PartStatus`),
delegating to `renderInputRequestPart`:

- **Resolved** (`Resolution != ""`): collapses to `⏸ <prompt>` + the resolution string
  (tertiary) — one historical line.
- **Pending approval/unknown**: header `⏸ <prompt>` + tool badge when `ToolName` set;
  bounded args via the existing `formatArgsExpanded` (`:546-562`); then
  `molecules.ConfirmPrompt(ctx, ConfirmPromptData{Question: "", Selected: p.Selected == 1})`
  — `Selected=false` renders the **no** badge filled/error-red
  (`molecules/confirmprompt.go:36-47`): the correct default-deny affordance — plus a
  tertiary hint `y approve · n deny · enter = <current>`.
- **Pending select**: `molecules.RadioSelect(ctx, RadioSelectData{Label: prompt, Options:
  mapped, Selected: p.Selected})` (`radioselect.go:25-71`; map `[]string` →
  `[]RadioOption{Label: s}`) + hint.
- **Pending text**: prompt + `> <TextBuf>_` + hint.
- **Busy**: hint swaps to `answering…`. **Read-only**: hint is the awaiting-elsewhere line.
- **Forward-compat seam (locked):** when the chunk's `AvailableDecisions` (#349) is
  non-empty, render it via `RadioSelect` in place of the yes/no pair and POST the chosen
  decision string verbatim; else approve/deny. When #328 lands, new decision kinds are
  strings, not code.

No click `Region` for the part — regions drive expand/collapse only; the prompt is
keyboard-driven and always the tail part while pending. Both molecules are pure renderers
already shipped (used only by the gallery today) — no molecule changes.

## Interfaces

```go
// internal/chat/model.go

// InputRequestPart is a HITL prompt awaiting (or having received) a decision.
type InputRequestPart struct {
	CorrelationID string
	Kind          string // "approval" | "select" | "text"; unknown → approval affordance
	ToolName      string
	Arguments     map[string]any
	Options       []string
	// caller-owned interaction state (molecules are pure renderers)
	Selected   int    // approval: 0=deny (zero-value, fail-closed), 1=approve; select: index
	TextBuf    string // kind "text"
	Resolution string // "" while pending; "✓ approved" / "⊘ denied" / "⊘ auto-denied (…)" …
	Busy       bool   // POST in flight
}

// InputResolvedMsg carries the RespondInput outcome back into Update.
type InputResolvedMsg struct {
	CorrelationID string
	Decision      string
	Value         string
	Err           error
}

// HasPendingInput reports whether a HITL prompt is awaiting a decision.
func (m *Model) HasPendingInput() bool

// skipStreaming drains the stream after enter-skip. It now returns a tea.Cmd:
// non-nil only when the drain hit an input.request and re-armed the reader.
func (m *Model) skipStreaming() tea.Cmd
```

Consumed from #349 (names per its approved spec): the input-request chunk type + HITL
chunk fields; `types.InputResponder` / `types.InputResponse`; the orphan-404 sentinel.

## Tests

`internal/chat/model_test.go` (white-box, existing convention; fake client implementing
the #349 responder capability, recording calls) — the dossier §5.D 11-case plan:

1. Arrival: part appended, `pendingInput` set, waiting placeholder replaced, returned cmd
   re-arms the reader (non-nil).
2. Dedupe: same correlation id twice → one part. (Plus: different id supersedes.)
3. Approval keys: `y` → fake receives `{c1, approve, ""}`; `n` → deny; bare `enter` →
   **deny** (fail-closed default); toggle then `enter` → approve.
4. Select: `down`+`enter` → `{decision:"approve", value:"optB"}`.
5. Text: type + `enter` → value round-trips; empty `enter` no-op.
6. `InputResolvedMsg{Err:nil}` → `Resolution` stamped, `pendingInput` nil; prompt keys no
   longer intercept.
7. Orphan error → `⊘ auto-denied (expired)`, pending cleared.
8. Auto-dismiss: pending + `ResponseMsg{Error: ToolCallBlocked, Done:true}` → stamped,
   calm `⊘ blocked` line (no red "Error:"), `streaming == false`.
9. Channel close while pending (synthesized Done) → auto-denied stamp.
10. **Deadlock guard: enter-skip drain hits the input chunk → drain stops, prompt pending,
    `streaming` still true, cmd re-arms the reader — failing mode is a test timeout.**
11. Read-only client (no responder) → awaiting-elsewhere hint, still pending, no panic,
    no cmd.

Plus abort-integration: pending + `AbortStream()` + teardown frames → card
`⊘ auto-denied (run ended)`, terminal `⊘ stopped` (not error) — pins the locked race.
And: network-error resolve keeps the prompt pending + renders a `PartError`.

`internal/chat/render_demo_test.go` (golden): pending approval renders prompt + yes/no
badges with **no**-selected default; pending select renders cursor on `Selected`; resolved
renders the single outcome line.

`internal/app/model_test.go`: with a parked stub stream, Esc keeps `phase == PhaseChat`
(routes to abort, not picker); legend shows the pending hint.

**Live e2e (Gate C exit, real key):** `AP_APPROVAL_TOOLS=bash AP_APPROVAL_TIMEOUT_MS=30000
ap playground` → approve run (tool executes, `✓ approved`), deny run (calm `⊘ blocked`),
timeout run (untouched prompt auto-dismisses `⊘ auto-denied (run ended)`), dashboard

## Open questions

1. **Esc semantics while parked — two-level split (recommended as specced):** app-level
   Esc = `AbortStream` (free from #347's `IsStreaming` interception; renders cancelled —
   the locked disposition), chat-level `esc` in `handlePendingInputKey` = deny (scout D4;
   reachable only in standalone embedding). Alternative: bind chat-level esc to abort too,
   making deny reachable only via `n`. Gate call on whether the split is acceptable or the
   uniform abort is preferred.
2. **`denyExpected` discriminator** (recommended): one turn-scoped bool set by own-deny +
   auto-dismissal, gating the calm `⊘ blocked` render; unexpected `ToolCallBlocked` stays
   a red error. Alternative: always render `ToolCallBlocked` calmly (simpler, but hides
   genuinely unexpected gate blocks).
3. **Text kind ships** (recommended IN, ~40 LOC): no wire producer exists today (approval
   gate is the only one) — locked D3 says cut text first under pressure, never approval.
   Confirm it stays in scope for this PR.
4. **Superseded-card policy** (recommended): a second, different correlation id stamps the
   old card `⊘ superseded` and adopts the new prompt — belt-and-braces for a server
   invariant that "should" never break. Alternative: drop the new request (strict
   single-pending), which risks an unanswerable park.
