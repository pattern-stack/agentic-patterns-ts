# Spec — N5 torn-stream fix: `error` + `done` frames on pre-token runner failure

## Goal

When the runner throws **before its first token** (model-resolution reject, provider
construction failure, any pre-yield setup throw), the SSE stream from
`POST /conversations/:id/messages` currently **tears**: hono swallows the rejection,
no `error` frame is written, no `done` terminator arrives, and every lenient client
renders an empty *successful* reply. Add the missing `catch` between the drain loop's
`try` and `finally` so a failed turn is honestly failed on the wire:

```
conversation.start → conversation.end {reason:"error"} → error {error_type, message, recoverable:false} → done {}
```

Companion (D5, locked in-PR): stop `Conversation.stream` from recording a phantom
empty exchange for a zero-output errored turn — today it pollutes both session replay
and `_toMessageHistory()` (the empty assistant turn is fed back into every subsequent
LLM call of that conversation).

This is wave-1 pre-work for the harness cockpit (epic #339): the Go TUI (R1+) and the
`contracttest` suite code against this exact four-frame contract. Ships the permanent
`broken-model` canary fixture used by Gate A and R1's contracttest.

## Locked dispositions (do not re-derive; state verbatim in the PR body)

- **#234 confound** — N5 and the bun/hono stall share the identical 14-byte
  torn-stream signature (`data: {"conver`) but are **two defects**: N5 = missing
  catch in the drain loop (this issue); #234 = bun/hono transport stall. Acceptance
  requires the manual four-frame repro under **node AND bun**. PR body states:
  *"N5 fixed; #234 is the transport half, tracked separately"* — unless the bun repro
  passes post-fix, in which case this PR closes #234. Either way this PR *references*
  #234; also cites #293 (failure-branch test backfill).
- **File-collision protocol** — `packages/agent-server/src/routes/conversations.ts`
  is edited by this issue, #341 (cancel), #351 (shim), #296, and #328. **This issue
  lands FIRST in the strict serial chain n5 → cancel → shim.** The PR states its
  ordering vs whatever of #296/#328 has landed at open time.
- **Do NOT use hono's `streamSSE` onError argument.** It writes its own
  `event: error` frame whose data is the **raw message string** (non-JSON) — the
  dashboard's `parseFrame` drops unparseable frames and the Go parser expects JSON.
  Catch inside the callback and own the frame shape.
- **Frame order is not negotiable-into-niceness**: `error` arrives *after*
  `conversation.end` because the wrapper yields its end before rethrowing. Clients
  fold on `error` regardless of position; do not reorder.

## Approach

### 1. Server — the catch (the N5 fix proper)

`packages/agent-server/src/routes/conversations.ts` — insert a `catch (err)` between
the existing `try` (:391) and `finally` (:407):

- Compute `message = err instanceof Error ? err.message : String(err)` and
  `errorType = err instanceof Error ? err.name : "Error"`.
- Write two frames, in order, inside a nested `try { … } catch { /* client gone */ }`:
  1. `event: "error"`, data `JSON.stringify({ error_type: errorType, message, recoverable: false })`
     — byte-compatible with `toSSEMapping`'s `agent.error` payload
     (`sse-formatter.ts:301-309`), which the dashboard already decodes and
     chat-patterns parses as an `error` event.
  2. `event: "done"`, data `JSON.stringify(turnRunId ? { run_id: turnRunId } : {})`
     — same expression as the happy-path done at :403-406. Pre-token failure ⇒
     `turnRunId` undefined ⇒ `done {}` (correct: no `agent.message.start` was ever
     observed). Mid-stream throw ⇒ `done {run_id}`.
- Then **swallow** — the failure is on the wire; hono's `run()` must not also
  `console.error` + tear. The nested try is belt-and-braces only: under hono
  4.12.31 `StreamingApi.write` swallows write errors (`catch {}` in
  `dist/utils/stream.js`).
- No double-done: the try-path `done` runs only when the loop completes; the
  catch-path `done` only on throw.
- The `finally` block (run-metadata stamp, unsubscribe, deny sweep) is untouched.

**Recommended (bus visibility, non-load-bearing):** in the same catch, publish a
synthesized `agent.error` on `eventBus` so the admin firehose/collector/exporters see
the failure (today a pre-token throw never reaches the bus — no exporter records
anything). Guard on `turnTraceId !== undefined` (set from the first forwarded event —
`conversation.start` always arrives, :393). Capture `turnBusRunId ??= event.runId`
alongside the existing traceId capture to have a runId for `createEvent` (it will be
the conversation wrapper's runId — no run row exists for it; exporters treat it as
trace-level). `createEvent` is exported from `@agentic-patterns/runtime` (the
server's own tests import it, `conversations.test.ts:13`). The wire fix must not
depend on this — see Open question 1.

### 2. Server — fix the stale disconnect comment

`conversations.ts:414-415` claims "a client disconnect (`stream.writeSSE` rejects
mid-loop)" — false under hono 4.12.31: `StreamingApi.write` swallows all write
errors; on disconnect the drain loop keeps pulling runner events to completion.
Rewrite that clause to state the real teardown model (writes are silently swallowed;
the loop drains to completion; #341's `onAbort` wiring is what will actually stop
the runner). The surrounding rationale for stamping in `finally` (error path throws
out of the `for await`) stays — it remains true, now with our catch in between.
An accurate comment here is load-bearing for #341's implementation.

### 3. Runtime — D5 companion: no phantom empty exchange

`packages/agent-runtime/src/conversation/conversation.ts`, `stream()`:

- Guard the bookkeeping at :290-306: when `error !== undefined && fullResponse === ""`
  (the turn produced **nothing**), skip the Exchange build, the `_history.push`, and
  `_persistExchange`, and revert the `this._exchangeCount += 1` from :219
  (`this._exchangeCount -= 1;` in the skip branch) so numbering stays dense.
- **Partial-text errored turns keep recording** (the user saw those tokens — matches
  React's aborted ≠ error posture, and #341 relies on partial exchanges being kept).
- `conversation.end {reason:"error"}` (:309-315) and the rethrow (:317-319) are
  untouched — the wire contract above does not change.
- This makes `stream()` consistent with its sibling `send()`, which throws before
  building an Exchange (nothing recorded).

## Decisions (resolved here, per scout Part A)

- **Catch-in-callback, not hono `onError`** — locked (non-JSON frame hazard).
- **D5 companion ships in this PR** — locked by the issue text ("recommended in-PR");
  without it, test 1 would have to assert the polluted behavior as "expected".
- **Skip-guard condition is `error !== undefined && fullResponse === ""`** — text is
  the discriminator; a turn that errored after tool activity but produced no text is
  also skipped (nothing to replay, nothing to feed back into history).
- **`done` payload logic reused verbatim** from the happy path (`turnRunId` ternary).

## Open questions (for the Gate 1 reviewer)

1. **Synthesized `agent.error` bus publish — include or drop?** Scout and issue mark
   it optional-but-recommended. Cost: capturing a second first-event field
   (`turnBusRunId`) and publishing an event whose runId has no run row (pre-token ⇒
   no `agent.message.start` ⇒ RunStoreExporter never created one) — collectors must
   tolerate a row-less runId. Recommendation: **include**; observability of exactly
   these failures is why Gate A exists.
2. **`broken-model` visible in the playground picker permanently** — a deliberately
   broken agent will sit in every `ap playground` agent list. Recommendation: ship
   it (self-evident name + header); it is the R1 contracttest canary and the Gate A
   repro. Alternative (env-gated fixture) adds machinery for no test value.
3. **D5 edge**: a turn with `totalInput/totalOutput > 0` but empty text (tokens
   billed, nothing rendered) is skipped by the `fullResponse === ""` guard —
   token accounting for that exchange is lost from history. Acceptable? (Scout says
   yes; flagging since it is the only information-losing branch.)
