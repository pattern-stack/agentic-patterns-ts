## Goal

Give the Go TUI (chat-patterns) a history surface it can decode with **zero client-side
EndpointConfig overrides**, without touching a single byte the React dashboard depends on:

1. **New bare `GET /conversations`** — snake_case summary rows as a bare top-level JSON array
   (`httpclient.ListConversations` decodes exactly that; its default path is exactly
   `/conversations`, dossier A-4), optional exact-match `?agent_name=` filter.
2. **`GET /conversations/:id` — additive aliases + inline `messages[]`** — every existing
   camelCase key stays byte-identical (dashboard regression guard); snake_case aliases and the
   inline message/part tree are appended. Zero extra store calls: `store.getMessages(id)` is
   already in hand at `routes/conversations.ts:265` and currently discarded after aggregates.
3. **Golden fixtures as the cross-repo contract** — the shim's own tests byte-lock the two
   response bodies against checked-in fixture files; #354 (Go picker/replay) vendors those same
   bytes as its decode fixtures. The fixtures ARE the contract lock (plan.md:56).

Cross-repo edge: Go `replay` (#354) is buildable in parallel against these fixtures; demoable
only after this lands with `AP_PERSISTENCE` on.

### 1. New `GET /conversations` list route

Insert directly **above** the `GET /admin/conversations` block (`routes/conversations.ts:241`).
Guard with the existing file-local `notConfigured(c)` (:659) first, like every read route.

Shape per dossier A.1 — for each summary from `store.listConversations()` (newest-first is the
store contract), after applying the optional exact-match filter
(`summaries.filter((s) => s.agentName === agentName)` when `?agent_name=` is non-empty):

| Wire key | Source | Notes |
|---|---|---|
| `id` | `s.conversationId` | |
| `agent_name` | `s.agentName` | |
| `model` | `s.model` | extra for the Go list struct (ignored) — detail wants it |
| `state` | `s.status` verbatim | `active\|completed\|error`; picker renders uninterpreted |
| `exchange_count` | `messages.filter((m) => m.kind === "request").length` | |
| `total_input_tokens` | `messages.reduce((n, m) => n + m.inputTokens, 0)` | NOT the combined `tokenCount` |
| `total_output_tokens` | `messages.reduce((n, m) => n + m.outputTokens, 0)` | |
| `created_at` | `s.startedAt.toISOString()` | RFC3339 — Go `time.Time` parses it |
| `updated_at` | `(s.lastMessageAt ?? s.startedAt).toISOString()` | |
| `branched_from_id` / `branched_at_sequence` | **omitted** | plan §7 deferred; Go fields are `*T,omitempty` → decode nil |

`messages` = `await store.getMessages(s.conversationId)` per row — the deliberate in-route N+1
(A-1, locked): `StoredConversationSummary` (`agent-runtime/src/conversation/store.ts:64-73`)
has no kind/token split, and extending it forces a runtime-protocol change + `bump-both` for a
server-only feature. Picker scale is tens of rows against local SQLite/in-memory. The
summary-projection extension is the named follow-up if list latency ever matters. Flag the N+1
in the PR description. Response: `c.json(rows)` — bare array, no envelope.

Route-conflict status re-verified at main@2411fc8: the only `"/conversations"`-prefixed
registrations anywhere in `routes/` are in this file — `POST /conversations` (:75, differs by
method), `GET /conversations/:id` (:258), `GET /conversations/:id/messages` (:291),
`POST .../messages` (:343), `POST .../cancel` (:592), `POST .../input` (:612). A bare exact
`GET /conversations` conflicts with none. Docs: route groups mount at `"/"` (`app.ts:35-58`)
and docs routes introspect `app.routes` last — the new route auto-appears in `/openapi.json`,
no docs change. `__tests__/docs.test.ts` builds stub apps with explicit route lists — cannot
break.

### 2. Detail route — additive snake_case aliases + inline `messages[]`

Extend the existing `GET /conversations/:id` handler (:258-287) — keep every current camelCase
key **byte-identical** (`id, agentConfigId, status, agentName, model, tokenCount, messageCount,
startedAt, completedAt, error, createdAt, updatedAt`), append:

```
agent_name:          conv.agentName
state:               "active"                       // same constant as camelCase `status` (:269)
exchange_count:      messages.filter(m => m.kind === "request").length
total_input_tokens:  messages.reduce((n, m) => n + m.inputTokens, 0)    // DELTA-1
total_output_tokens: messages.reduce((n, m) => n + m.outputTokens, 0)   // DELTA-1
created_at:          conv.createdAt.toISOString()
updated_at:          (lastMessage?.createdAt ?? conv.updatedAt).toISOString()   // mirrors camelCase updatedAt
messages:            messages.map((m, i) => ({
                       id: m.id,
                       kind: m.kind,               // "request" | "response" — verbatim (A-2)
                       sequence: i,                // store has no sequence column; array order IS the order
                       parts: m.parts.map(p => ({
                         type: p.type,             // user_prompt | text | state_delta (all that _persistExchange writes today)
                         content: p.content ?? null,
                         metadata: p.metadata,     // included per A-3 — Go drops unknown keys today, future-proofs tool_call detail
                       })),
                     }))
```

`id` and `model` already exist camelCase-free (same spelling) and satisfy the Go tags as-is.
Existing 404 (:263-264) and 503 behavior untouched. Zero extra store calls — `messages` is the
:265 fetch.

**DELTA-1 (deliberate addition over dossier A.2):** the dossier's alias list omitted
`total_input_tokens` / `total_output_tokens` on the detail response — but Go's
`ConversationDetailResponse` (chat-patterns `internal/types/types.go:141-152`) embeds the same
field set as the list row, which declares both. Without them the decoded detail struct carries
zeros, violating #354's "decode fixtures … every field non-zero (N3 regression lock)"
acceptance. Two lines, values already computed for `tokenCount`. Confirm at the gate (Open Q1).

**No TS vocabulary translation** (A-2, locked): `kind` stays `request|response`; the Go replay
renderer owns the `user`/`assistant` mapping and the part-type table (dossier A.3). Translating
in TS would make this wire diverge from `GET /conversations/:id/messages`, which already emits
`kind` verbatim (:297).

### 3. Golden fixtures — THE contract lock (location + enforcement)

**Canonical home (this repo is the source of truth):**

```
packages/agent-server/src/__tests__/__fixtures__/chat-patterns-shim/
  conversations-list.json     # exact GET /conversations response body + one trailing \n
  conversation-detail.json    # exact GET /conversations/:id response body (conv A) + one trailing \n
  MANIFEST.sha256             # sha256sum-format digest of both fixture files
```

The `__fixtures__` segment is load-bearing: `biome.json` `files.ignore` includes
`**/__fixtures__/**` (verified), so `bun run check` can never reformat the contract bytes.
The path convention already exists 3× in the repo (`agent-runtime/src/runner/__fixtures__` etc.).

**Determinism** (fixture bytes must be reproducible from the seed):
- `vi.useFakeTimers()` + `vi.setSystemTime(...)` — the store stamps `new Date()` internally.
- `vi.stubGlobal("crypto", { ...globalThis.crypto, randomUUID: () =>` counter-based
  `` `00000000-0000-4000-8000-${(++n).toString().padStart(12, "0")}` `` `})` — the store reads
  `globalThis.crypto` at call time (`store.ts:12-17`), so `stubGlobal` intercepts cleanly.
  `afterEach`: `vi.useRealTimers()` + `vi.unstubAllGlobals()`.

**Seed table** (pinned; mirrors production `_persistExchange` faithfully — request messages
carry `runId` only, response messages carry `runId + inputTokens + outputTokens`, `state_delta`
parts precede the terminal `text` part):

| Op | Time (UTC 2026-07-24) | Detail |
|---|---|---|
| create conv A | 12:00:00.000 | `alpha-agent` / `test-model-a` |
| A req 1 | 12:00:01.000 | part `user_prompt "hello alpha"`; `{runId:"run-a-1"}` |
| A resp 1 | 12:00:02.000 | parts `state_delta` (NO content, `metadata:{event:"backpack.drop"}`) + `text "hi from alpha"`; `{runId:"run-a-1", inputTokens:11, outputTokens:7}` |
| A req 2 | 12:00:03.000 | `user_prompt "again"`; `{runId:"run-a-2"}` |
| A resp 2 | 12:00:04.000 | `text "alpha again"`; `{runId:"run-a-2", inputTokens:13, outputTokens:9}` |
| create conv B | 12:00:05.000 | `beta-agent` / `test-model-b` |
| B req/resp ×2 | +1s each | same shape; resp tokens `17/5`, `19/8` |

⇒ list fixture: 2 rows newest-first (B then A), `exchange_count: 2` each, A totals `24/16`,
B totals `36/13` — every Go-decoded field non-zero. Detail fixture: conv A — 4 messages,
`sequence` 0..3, one `content: null` part (the content-less `state_delta`).

**Enforcement — three layers (state these verbatim in the PR):**
1. **TS byte-equality (this PR):** the test asserts `(await res.text()) + "\n"` strictly equals
   the committed fixture bytes for both routes. Any contract change — key order, a new field, a
   float format — fails CI until the fixture is deliberately regenerated. Regeneration:
   `UPDATE_SHIM_FIXTURES=1` env makes the same test write fixtures + recompute `MANIFEST.sha256`
   instead of asserting (explicit, dependency-free snapshot-update idiom); a second manifest
   assertion (node:crypto) keeps fixture bytes and manifest in lockstep in-repo.
2. **Shared manifest across repos (#354's side):** the Go slice vendors both fixture files AND
   `MANIFEST.sha256` verbatim (suggested `internal/chat/testdata/shim/`); its decode test
   re-hashes its vendored copies against the vendored manifest. Cross-repo drift is then a
   one-file diff (`MANIFEST.sha256` here vs there) — auditable at a glance, and any regeneration
   here makes the Go copy visibly stale on next sync.
3. **Live backstop:** Gate D e2e (#356) runs the real cockpit against the released server.

**This section is the canonical statement of the fixture home — #354's spec must reference
this path** (it is being specified concurrently; flagged to the conductor).

## Wire contract (what #354's Go client codes against)

- `GET /conversations` → `200` bare array of rows (table §1) | `503 notConfigured` shape
  (`{error:"persistence not configured", hint:"…AP_PERSISTENCE != 0…"}` — Go renders any
  non-200 as `list conversations: HTTP 503`, acceptable honest degradation, no special-casing).
- `GET /conversations?agent_name=X` → exact-match filtered rows; unknown name → `[] 200`,
  never 404. (Go MVP sends no filter per #354's R3-1 — the parameter ships anyway per this
  issue's acceptance.)
- `GET /conversations/:id` → `200` camelCase-superset object (§2) | `404` unknown id | `503`.
- Live-but-unpersisted conversations 404 on detail — correct: the Go picker only lists
  persisted conversations (registry is in-memory; replay is read-only in #354).
- Timestamps RFC3339 via `.toISOString()`. Branch fields never emitted.

## Tests (acceptance-mapped — dossier A.4 five-case plan + contract locks)

1. **503 shape:** `GET /conversations` with no store → `notConfigured` body (mirror
   `conversations.test.ts:89-96` idiom).
2. **Seeded 2×2 list:** bare-array envelope (no wrapper key); newest-first (B before A);
   snake_case keys exact; `exchange_count === 2` per row; `total_input_tokens` /
   `total_output_tokens` equal the seeded sums (NOT the combined `tokenCount`);
   `expect(row).not.toHaveProperty("branched_from_id")` (and `branched_at_sequence`).
   **Byte-lock:** response text + `"\n"` === `conversations-list.json` bytes.
3. **Filter:** `?agent_name=alpha-agent` → only A's row; `?agent_name=nobody` → `[]` with
   status 200.
4. **Detail superset:** `Object.keys(body).sort()` pins the exact union of the 12 pre-existing
   camelCase keys + the 8 additions (regression guard both directions); `messages[]` inline
   with `sequence` 0..3; `kind` verbatim; the content-less `state_delta` part serializes
   `content: null` with its `metadata` intact. **Byte-lock:** conv A detail vs
   `conversation-detail.json`.
5. **Empty conversation:** created, zero messages → `exchange_count: 0`, both totals `0`,
   `updated_at === created_at`; detail `messages: []`.
6. **Manifest lockstep:** sha256 of each committed fixture file matches `MANIFEST.sha256`
   (in-repo half of enforcement layer 2).

`bun run check` green (build + typecheck + lint + test). Manual (pre-Gate-D smoke, optional):
`AP_PERSISTENCE=1 ap playground`, one keyed turn, `curl /conversations` shows the row.
