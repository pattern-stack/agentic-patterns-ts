## Goal

Make a streaming turn stoppable, three ways at once:

1. **Runtime seam** — `RunOptions.abortSignal`: cooperative abort plumbed into `AgentRunner.stream`
   and `Conversation.stream`. On abort the **runner** emits `agent.message.cancel` +
   `agent.conversation.end {reason:"cancelled"}` and **returns — never throws** (locked D1).
2. **Explicit contract** — new `POST /conversations/:id/cancel`: `404` unknown / `409` idle /
   `202 {ok, run_id?}` (locked D3). This is the contract the Go TUI codes against in R1.
3. **Disconnect hardening (safety net)** — `stream.onAbort` in the messages route aborts the run
   and immediately deny-sweeps pending inputs, fixing two live defects: token burn after React
   Stop (client-only fetch abort today) and the forever-hang when a client disconnects during a
   gate-blocked approval.

Gate-A acceptance: curl cancel → 202, open stream winds down `message.cancel … done`; the React
dashboard Stop button actually stops the runner.

**Abort/approval race rule (locked):** stream teardown auto-denies pending inputs; a cancelled
turn renders as *cancelled*, never as a server error.

## Approach

Both halves in one PR — Option 2 (explicit route) as the contract, Option 1 (`onAbort`) as the
safety net. They share ~90% of the machinery (one `AbortController` + one deny sweep). Scout
dossier Part B (B.2–B.3) is the spec of record; this section pins it to current main.

### 1. Runtime — `RunOptions.abortSignal`

`packages/agent-runtime/src/runner/types.ts` — `RunOptions` starts at :118; add after
`parentSpanId` (:135-136):

```ts
/**
 * Abort the run cooperatively: forwarded to the provider call
 * (`streamText({ abortSignal })`) and checked at the top of each iteration
 * and before each tool dispatch. On abort the runner emits
 * `agent.message.cancel` + `agent.conversation.end {reason:"cancelled"}`
 * and returns — it does NOT throw. Currently honored by `stream()` only;
 * `run()`/`runStructured()` ignore it (see Open questions / doc note).
 */
abortSignal?: AbortSignal;
```

### 2. Runtime — `AgentRunner.stream` (`agent-runner.ts`, stream() begins :1087)

Five touches, one shared emission helper:

- **Pass the signal**: `abortSignal: options?.abortSignal` in the `streamText` call (:1190-1195).
- **`case "abort":`** in the fullStream switch (drain loop :1219; `case "error"` is :1295) —
  ai@5 (`^5.0.0`, fullStream `'abort'` part per dossier) emits it when the signal fires
  mid-provider-call. Set `aborted = true` local, `break` out of the switch; after the fullStream
  drain, if `aborted` → cancel-and-return block.
- **Top-of-iteration guard** — loop head :1158: `if (options?.abortSignal?.aborted)` →
  cancel-and-return block (prevents a second `llm.start` after an abort landed between
  iterations).
- **Pre-tool-dispatch guard** — tool loop `for (const tc of pendingToolCalls)` :1432, before
  `toolExecutor.execute` (:1491): same check → cancel-and-return (never dispatch a tool for an
  already-cancelled turn).
- **Belt-and-braces**: wrap the fullStream drive so a provider that throws `AbortError` instead
  of emitting the abort part (`err.name === "AbortError"`) routes into the same
  cancel-and-return block, not the error path.

Cancel-and-return block (single private helper; runner owns emission — locked D1, so
bus/exporters/collector see it on every transport):

```ts
const cancelEv = createEvent("agent.message.cancel", {
  traceId: effectiveTraceId, runId, parentSpanId: rootSpanId,
  reason: "cancelled by client",
});
await this.emit(cancelEv); yield cancelEv;
const convEnd = createEvent("agent.conversation.end", {
  traceId: effectiveTraceId, runId, conversationId, reason: "cancelled" as const,
});
await this.emit(convEnd); yield convEnd;
return;
```

Event vocabulary is already cancel-shaped with zero production emitters — this lights up existing
consumers for free: `MessageCancelEvent` (`events/types.ts:259-262`, `reason?: string`),
`ConversationEndEvent.reason` includes `"cancelled"` (:252), wire mapping `message.cancel`
(`transport/sse-formatter.ts:187-188`, name map :479), collector transition
(`admin/collector.ts:335` → `_onMessageCancel` :454). No formatter/collector changes needed.

### 3. Runtime — `Conversation.stream` (`conversation/conversation.ts:211-213`)

- Widen the options bag: `options?: { eventBus?; maxIterations?; signal?: AbortSignal }`.
- Forward into the runner call (:255-267): `...(options?.signal ? { abortSignal: options.signal } : {})`.
- Stamp the trailing `conversation.end` honestly (:313):
  `reason: error ? "error" : options?.signal?.aborted ? "cancelled" : "completed"`.
- Cancelled turn takes the **happy path**: runner returns (no throw), the partial-text Exchange
  is recorded (:290-302) and persisted — aborted ≠ error, matching React's posture.
- The wire keeps carrying two `conversation.start/end` pairs (Conversation's + runner's).
  **Do not dedupe** in this arc (dossier B.3-3).

### 5. Server — messages route (`conversations.ts:331-445` on main; offsets shift after #340)

- **409 concurrency guard** (locked into acceptance, resolves D2): before `streamSSE` (:363), if
  `entry.activeTurn` is set → `409 {"error":"a turn is already streaming for this conversation"}`.
  This also keeps `activeTurn` singular/unambiguous for the cancel route.
- Top of the streamSSE callback: `const controller = new AbortController();`
  `entry.activeTurn = { controller, startedAt: Date.now() };`
- Mirror the runId when captured (:394-395): `entry.activeTurn.runId = turnRunId;`
- Pass the signal: `conversation.stream(content, { eventBus, maxIterations, signal: controller.signal })`.
- **`onCancel`** (one function, two registrations):
  `controller.abort()` + immediate deny sweep `for (const id of pendingForTurn) inputRegistry?.resolve(id, { decision: "deny" })`.
  - `stream.onAbort(onCancel)` — client disconnect. Critical: a gate-blocked run is parked inside
    `bus.publish`, the drain loop never settles, so the existing `finally` deny sweep (:438-442)
    never runs on disconnect today — that's the hang this fixes.
  - `controller.signal.addEventListener("abort", onCancel, { once: true })` — route-initiated
    cancels must also unpark blocked gates.
- `finally`: `delete entry.activeTurn` (the existing sweep + unsubscribe stay as the
  natural-completion belt).
- While in the file: fix the stale comment at :414-416 (“`stream.writeSSE` rejects mid-loop”) —
  false under hono 4.12.31, `StreamingApi.write` swallows write errors; misleading for exactly
  this change.

### 6. Server — cancel route (new, beside the input route :454)

```ts
// POST /conversations/:id/cancel — abort the in-flight turn, if any.
// 404 unknown conversation · 409 no active turn · 202 accepted (cancellation
// is cooperative/async — the open SSE stream winds down with message.cancel).
// Idempotent while winding down (AbortController.abort() is a no-op when
// already aborted → 202 again); after finally clears activeTurn → 409.
app.post("/conversations/:id/cancel", (c) => {
  const entry = conversations.get(c.req.param("id"));
  if (!entry) return c.json({ error: "Conversation not found" }, 404);
  const turn = entry.activeTurn;
  if (!turn) return c.json({ error: "no active turn" }, 409);
  turn.controller.abort();
  return c.json({ ok: true, ...(turn.runId ? { run_id: turn.runId } : {}) }, 202);
});
```

No auth — parity with every other route on this server. Route auto-appears in `/openapi.json`
(docs routes introspect `app.routes`, `app.ts:70-77`); add the house-style doc comment.

## Wire contract (what R1's Go client codes against)

Cancelled turn, on the still-open POST …/messages stream:

```
…message.delta* → message.cancel {reason}
  → conversation.end {reason:"cancelled"}   (runner's)
  → conversation.end {reason:"cancelled"}   (Conversation's)
  → done {run_id}
```

Cancel POST itself: `202 {"ok":true,"run_id":"…"}` (`run_id` omitted if no `message.start` seen
yet). Dashboard: no change required — its parser passes unknown frames through
(`chat-client.ts:304`); rendering `message.cancel` is R3 polish.

## Tests (acceptance-mapped)

Runtime (`MockLanguageModelV2` from `ai/test` is the house idiom, `agent-runner.test.ts:8`):
1. Pre-aborted signal → `conversation.start`, `message.start`, then cancel pair; **no
   `llm.start`**; generator returns, never throws.
2. Abort between iterations (tool executor fires `controller.abort()` during iteration 0's
   `execute`) → no second `llm.start`, cancel pair emitted.
3. Abort mid-provider-stream (`doStream` with a never-closing ReadableStream; abort after first
   chunk) → cancel pair via `'abort'` part / AbortError path — pins the ai@5 behavior we rely on.
4. `Conversation.stream` with `signal`: trailing end reason `"cancelled"`; exchange recorded
   with partial text.

Server (new `conversations-cancel.test.ts`, cribbing `mkApp`/`makeStreamingRunner` from
`conversations.test.ts:29-76`; parked-runner double that resolves when its `abortSignal` fires):
5. Cancel grammar: 404 unknown / 409 idle / 202 `{ok:true}` mid-turn.
6. Cancelled turn's SSE body ends `message.cancel … done` (cancel issued from a second
   `app.request` while draining the first).
7. Deny-sweep-on-cancel: runner publishes `agent.input.request` then parks on the registry →
   POST cancel → registry resolved deny + stream terminates with `done`
   (delivery scaffolding: `conversations-input.test.ts:158-186`).
8. Disconnect hardening: `res.body.getReader().cancel()` drives hono's `onAbort` → runner double
   observed abort AND pending input denied.
9. Concurrent second POST …/messages during an active turn → 409.

Manual (Gate A): React Stop stops the runner (token burn ends — watch the collector/server log);
curl cancel returns 202 and the open stream winds down. `bun run check` green.

## Open questions for the human gate

1. **`run()`/`runStructured()` silently ignore `abortSignal`.** `RunOptions` is shared across all
   three entry points. Recommendation: ship stream-only with the explicit doc note above (keeps
   the diff M-sized; every live consumer of cancellation streams). Alternative: also add
   top-of-iteration guards to `run()` (:337) — cheap but grows test surface. Default if
   unchallenged: stream-only.
2. **Iteration bookkeeping on cancel.** The cancel-and-return block skips `iteration.end` /
   `message.complete` for the aborted iteration. Collector transitions on `message.cancel`
   (:335) so traces close correctly. Recommendation: accept the skipped `iteration.end`
   (mirrors the existing error path's posture); flag here in case the trace UI cares.
3. **Spec branch base.** `cockpit/cancel` (this spec's branch) is currently based on `main`
   because `cockpit/n5` doesn't exist on origin yet (#340 spec in flight concurrently).
   Implementer restacks onto `cockpit/n5` before coding — confirm that's the intended stack
   mechanics for the PR chain (PR base = `cockpit/n5`, retarget to `main` after #340 merges).
