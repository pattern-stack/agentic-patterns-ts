# go: cmd/cockpit consumer + Justfile recipe + _examples/agentic-patterns disposition

> **Cross-repo note:** tracker issue lives in `pattern-stack/agentic-patterns-ts`; the code
> change lands in `github.com/pattern-stack/chat-patterns` on branch **`cockpit/cmd`**, base
> `main @ 4720311` (#342 hygiene + #343 deps merged; CI `check` = `just quality` is a required
> status; branch protection live). Dossier anchors were scout-verified at `187411b`; this spec
> re-verified `tui.go`, `Justfile`, and `_examples/agentic-patterns/` unchanged at `4720311`
> (#342/#343 touched only `.github/`, `LICENSE`, `README.md`, `go.mod`/`go.sum`).

## Goal

Give the arc its first-light binary: a new `cmd/cockpit` (binary `cockpit`) that points the
existing TUI at `ap playground`'s default port **3456** with an `AP_SERVER_URL` override, a
`just cockpit` recipe to launch it, and retirement of the dead Python-orchestrator example
squatting on the `agentic-patterns` name. This is the PR whose demo closes **Gate B** ("first
light": agent list renders with description text + role-object decode, one full turn streams)
— but the demo itself happens only after siblings #344 (wire) and #345 (parse) are merged;
this issue supplies the consumer, not the wire fixes.

## Approach

**Base, branch, and merge protocol.** Branch `cockpit/cmd` off chat-patterns `main @ 4720311`.
This slice is **file-disjoint from both siblings** — #344 touches
`internal/httpclient/`, `internal/types/`, `contracttest/`; #345 touches `internal/sse/`;
this PR touches `cmd/cockpit/` (new), `Justfile`, `README.md`, `_examples/agentic-patterns/`
(delete). Zero shared files means development fully parallelizes and rebases are trivial.
**Merges stay serial in dependency order** (plan §1, proven throttle): this PR merges **after
#344**. Do not stack on `cockpit/wire` (no file contact makes stacking pointless); open the PR
against `main`, note "merge after #344" in the description, rebase onto `main` once #344
merges, let CI re-run, then merge. #345 is a sibling, not a prerequisite — no ordering
constraint against it beyond the Gate B demo needing both.

**Why the dependency exists at all.** Nothing here compiles against #344's changes — the
dependency is behavioral. Without wire, this binary speaks the dead contract (default `/send`
path + `{"message"}` body, `agent_name` create key, role-decode failure N1) and first light
fails against a live server. After wire, the client defaults are correct and `cmd/cockpit`
needs **no `Endpoints:` override** (dossier §4.2). The agent picker's "description as tertiary
text" also arrives via #344 (wire fix #3 maps `description` → `AgentSummary.Role`, which the
existing picker already renders at `internal/app/model.go:367-371`) — this PR does **zero
rendering work**.

**`cmd/cockpit/main.go` — per dossier §4.2, adopted verbatim.** A ~40-line `package main`
mirroring the shape of `_examples/agentic-patterns/main.go` (right shape, wrong target) with
the plan-locked config: `AppName "agentic-patterns"`, `AssistantLabel "agent:"`,
`BackendURL "http://localhost:3456"`, `EnvOverride "AP_SERVER_URL"`. Semantics re-verified at
`4720311`: `resolveBackend` checks `EnvOverride` first and it wins when the env var is set
(`tui.go:62-67` per dossier); env unset falls through to `BackendURL` (`tui.go:94-95`); setting
both fields is valid (the one-backend counter counts only `BackendURL`). The doc comment is
the binary's contract statement: run `ap playground` first (default 3456, routes mounted at
root — `agent-cli/src/constants.ts:18`, `agent-server/src/app.ts:35-58`), then
`go run ./cmd/cockpit`, `AP_SERVER_URL=...` to override. Deliberately absent: `Endpoints:`
(defaults correct post-#344), `Commands:` (R2/R3 grows a `commands/` dir on the agenti-kit
aggregator pattern, `cmd/agenti-kit/commands/commands.go:16-26`), and `Config.OnReady`
(declared, never invoked — `config.go:43-44`; dead API, do not build on it).

**Justfile recipe.** Add `cockpit:` on the pattern of `kit:` (`Justfile:31-33`), inserted
directly after it so the two `cmd/` consumers sit together ahead of the build/test recipes:
recipe body `cd cmd/cockpit && go run .`, comment line "Chat against a running `ap playground`
(agentic-patterns TS server)".

**CI coverage is automatic and asymmetric.** `cmd/` is inside the module, so `go build ./...`
+ `go vet ./...` in `just quality` (`Justfile:43-45`, the required `check` status) gate the new
binary on every PR from this one forward. Conversely `_examples/` is underscore-prefixed and
**excluded** from `./...` patterns — deleting the example is invisible to CI (and that same
invisibility is partly why the dead example rotted unnoticed).

**Disposition of `_examples/agentic-patterns/`: DELETE** (scout OD §7.6, first-listed
recommendation). The directory is a single 975-byte `main.go` whose header and defaults
describe the dead Python orchestrator (`http://localhost:8080/api`, `AP_BACKEND_URL`,
`python -m uvicorn agentic_patterns.app.orchestrator.app`). Evidence for delete over the
"3-line pointer" variant:

- **Unreferenced.** The README examples table (`README.md:117-122`) does not list it; grep of
  `README.md` / `CLAUDE.md` / `PROTOCOL.md` at `4720311` finds no reference to the directory,
  no `8080`, no orchestrator mention. Nothing dangles.
- **Redundant.** `_examples/minimal/` already documents the generic `BackendURL` HTTP/SSE
  pattern (README table row), and the real agentic-patterns consumer is now first-class
  `cmd/cockpit` in the same repo, discoverable via `just cockpit`.
- **Tombstones rot.** A pointer file is still a dir named "agentic-patterns" with no runnable
  code — the same N6-style drift factory shape, one layer removed. Git history preserves the
  original for archaeology.

**README.** One-line addition to the `just` recipes block (`README.md:101-106`):
`just cockpit   # Chat against a running ap playground (agentic-patterns TS server)`. This is
a step beyond the issue's strict files list, flagged as an open question; recommended because
the block is the repo's quickstart and a recipe absent from it is undiscoverable.

## Interfaces

No new exported API — `cmd/cockpit` is a pure consumer of the existing public `tui.Config`
surface. The load-bearing literal:

```go
tui.New(tui.Config{
	AppName:        "agentic-patterns",
	AssistantLabel: "agent:",
	BackendURL:     "http://localhost:3456", // ap playground default
	EnvOverride:    "AP_SERVER_URL",         // wins when set (tui.go:62-67)
})
```

And the recipe:

```just
# Chat against a running `ap playground` (agentic-patterns TS server)
cockpit:
    cd cmd/cockpit && go run .
```
