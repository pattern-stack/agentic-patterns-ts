# go: scope-on-create + preset picker + /scope command + Config.DefaultScope

> **Cross-repo note:** tracker issue lives in `pattern-stack/agentic-patterns-ts`; the code
> change lands in `github.com/pattern-stack/chat-patterns` on branch **`cockpit/scope`**, base
> **`main @ 8c89d4d`** (#342 hygiene, #343 deps, #346 cmd, #344 wire, #345 parse ALL merged; CI
> `check` = `just quality` is a required status). Dossier anchors were scout-verified at
> `187411b`; this spec re-verified every anchor at `8c89d4d` — **one material delta**: #344 did
> NOT add JSON tags to `types.AgentSummary` (it decodes via an intermediate `wireAgent` struct,
> `internal/httpclient/client.go:71-91`), so the `instantiation` decode rides `wireAgent`, not

## Goal

Make the cockpit scope-aware end-to-end: decode `instantiation {available, defaults, schema,
presets}` from `GET /agents`; insert a `PhaseScopeSetup` picker (Defaults / preset:* / Custom
JSON) between agent-select and create; send `scope` on `POST /conversations` through a changed
`types.Client.CreateConversation` seam (#344 deliberately left the interface untouched — **this
issue owns it**); decode non-201 error bodies into a typed `ScopeValidationError` and render the
server's 400 issues list in-phase (Risk 11 — the issues list IS the MVP form); store the 201
scope echo and surface it via a system line + a display-only `/scope` command; and give library
consumers a `Config.DefaultScope` bypass for scripted entry.

## Approach

**Base, branch, and merge protocol.** Branch `cockpit/scope` off chat-patterns `main @ 8c89d4d`.
No cockpit branches are unmerged at spec time; the only sibling in flight is **#347 (abort,
`cockpit/abort`)**, being specified concurrently. Expected shared file: `internal/app/model.go`
(abort touches the chat-phase esc path / send-context plumbing; this PR adds a new phase arm,
the entry decision in `updateAgentSelect`, and new model fields — different regions, trivial
rebase). `internal/types/types.go` and `internal/chat/model.go` are expected to be
scope-only/abort-only respectively this round (this PR does **not** edit `internal/chat/model.go`
— the `/scope` output rides the existing `command.SystemMsg` render path, `chat/model.go:402-403`).
Per plan §1 the merge protocol is: open against `main`, no stacking, whichever PR is approved
first merges first, the other rebases and lets CI re-run. Merges strictly serial.

**The interface seam (locked — this issue owns it).** `types.Client.CreateConversation`
(`internal/types/client.go:15`) changes signature:

```
CreateConversation(ctx context.Context, agentID string) (CreateConversationResult, error)
→ CreateConversation(ctx context.Context, agentID string, scope map[string]any) (CreateConversationResult, error)
```

Six implementations change: `httpclient.HTTPClient` (`client.go:203` — the real change),
`httpclient.StubClient` (`client.go:~362` — accept + ignore; it never advertises
`instantiation`, so the phase can never trigger against it), `stdioclient` (`client.go:389`),
`cliclient` (`client.go:74`), `execclient` (`client.go:53`), `demo.DemoClient` (`client.go:53`).
Non-HTTP transports error **loudly** on non-empty scope (S-2, locked): `if len(scope) > 0 {
return types.CreateConversationResult{}, fmt.Errorf("scope not supported by this transport") }`
— silently dropping a user-entered scope is worse than an error (contrast with the quiet
nil-history precedent at `cliclient/client.go:135-143`, which is fine for reads).
Two non-test call sites update to pass `nil`: `internal/app/model.go:267` (replaced by the new
entry decision) and `internal/app/demo.go:63` (demo mode — always nil scope).
`contracttest/validate.go:75` speaks raw HTTP and is untouched.

**Wire decode — `GET /agents` instantiation.** Server contract
(`agent-server/src/routes/agents.ts:89-94` @ TS main): `instantiation: {available: bool,
defaults: object|null, schema: object|null, presets: Record<name, Record<field, value>>|null}`.
New `types.Instantiation` struct (JSON-tagged) + `AgentSummary.Instantiation *Instantiation`
(no tag needed — see next). **Adaptation vs the dossier:** `AgentSummary` at `8c89d4d` has no
JSON tags; the canonical decode goes through `wireAgent` (`httpclient/client.go:71-91`). So:
`wireAgent` gains `Instantiation *types.Instantiation \`json:"instantiation"\`` and the mapping
loop (`client.go:144-151`) copies the pointer through. The legacy `[]string` fallback
(`client.go:155-177`) leaves `Instantiation` nil — correct, that backend has no scope concept.
`Schema` is decoded but never rendered (S-3, plan §7 — binding): a later form engine needs no
wire change.

**Create semantics (locked, S-1).** The server does NOT compose declared defaults under a
supplied scope — `effectiveContext = rawScope ?? {...declaredDefaults}`
(`agent-server/src/routes/conversations.ts:128-142` @ `7ae304e`; only zod `.default()`s fill
gaps inside `scope.parse`). Therefore, per row:

- **Defaults** → `CreateConversation(ctx, id, nil)` — `scope` key **omitted** entirely
  (`omitempty`), the server composes its own defaults, and an agent with required-no-default
  fields 400s honestly (D11) — which the phase then renders as the form.
- **Preset `p`** → send `shallowMerge(Instantiation.Defaults, Instantiation.Presets[p])`,
  defaults first, preset keys win. Shallow is correct — scope fields are flat top-level keys
  (`SessionScopeLike`, `agent-server/src/config.ts:43-51`). The preset *name* is never sent
  (matches the React chat's client-side materialization posture).
- **Custom JSON** → send the parsed object **raw, unmerged** (the power path — mirrors
  `ap run --context` replace-not-merge precedence). `jsonBuf` pre-seeded with
  `Instantiation.Defaults` marshaled (editable starting point); `tea.PasteMsg` is the main
  entry vector and reaches the phase via the existing bottom-of-`Update` phase dispatch
  (`app/model.go:231-238`) — no new top-level case needed, `updateScopeSetup` type-switches on
  both `tea.KeyPressMsg` and `tea.PasteMsg`. Backspace via `deleteChar`
  (`chat/input.go:12-19` — exported or duplicated locally, implementer's pick); enter = parse;
  local `json.Unmarshal` error renders inline without leaving jsonEdit mode.

**Risk 11 — decode non-201 bodies (the reason N2 was undiagnosable).**
`HTTPClient.CreateConversation` today throws the body away on non-201
(`client.go:221-223`). New behavior: read the body, decode `{"error": string, "issues"?: […]}`;
if `error == "scope validation failed"` → return `*types.ScopeValidationError` with the decoded
issues; any other decodable body → error containing the server's `error` string (this also
surfaces 404 "Agent not found" and the 400s at `conversations.ts:98/105`); unparseable body →
fall back to today's `HTTP %d` message. The 201 body decodes through a local wire struct
(`{id, scope, context, context_redacted}` — follows the `wireAgent` precedent) into
`CreateConversationResult{ID, Greeting, Scope, Redacted}` with `Scope = scope ?? context`
(scope present only for scope-declaring registrations; values arrive pre-redacted,
`conversations.ts:179,220-237`; hook-less+scope-less agents get a bare `{id, agent_id}` 201 —
all echo fields nil).

**App flow.** `Phase` (`app/model.go:22-28`) gains `PhaseScopeSetup` between `PhaseSelectAgent`
and `PhaseChat`. New file `internal/app/scope.go` holds `scopeState` (agent, cursor,
mode list|jsonEdit, jsonBuf, valErr, submitErr) plus `updateScopeSetup`/`viewScopeSetup`
(render mirrors `viewAgentSelect`'s atoms + cursor idiom, `model.go:317-383`). The
**entry decision** replaces the immediate create at `model.go:258-270`:

1. `agent.Instantiation == nil || !agent.Instantiation.Available` → create immediately,
   `scope=nil` (today's behavior; zero regression for scope-less backends and all non-HTTP
   transports).
2. `cfg.DefaultScope != nil` → create immediately with that map (bypass — the scriptable path).
3. Else → `m.phase = PhaseScopeSetup`, seed `scopeState` (rows: `Defaults`, sorted preset
   names, `Custom JSON…`; the phase always shows when `available`, because the D11 agent has
   nil defaults AND nil presets yet *needs* Custom JSON).

`ConversationCreatedMsg` (`model.go:36-41`) gains `ValErr *types.ScopeValidationError`; the
`tea.Cmd` wrapping the create splits it out via `errors.As`. In the handler
(`model.go:185-198`): `ValErr != nil` while in `PhaseScopeSetup` → **stay in phase**, render
each issue as `path.join(".") + ": " + message` under the picker via `molecules.ErrorBlock`
(same molecule as `model.go:334-339`); with DefaultScope set (phase is `PhaseSelectAgent`) →
render the issues in the agent-select error block and stay there. Other errors keep the
existing `loadErr` path — and the latent never-reset `loadErr` is fixed: **clear `loadErr` (and
`scopeState.valErr`/`submitErr`) on every new selection/submission** (today `model.go:174-188`
sets it and nothing ever clears it). On success, store `result.Scope`/`result.Redacted` on the
app model and append one system line before entering `PhaseChat` — pattern identical to the
Greeting append at `model.go:191-193`, via `chat.TextMessage(chat.RoleSystem, …)`; skip the
line when no scope is bound. Esc: jsonEdit → list; list → back to `PhaseSelectAgent`. The
phase dispatch (`model.go:231-238`) and `View` (`model.go:299-304`) gain `PhaseScopeSetup`
arms; `renderLegend` (`model.go:385-398`) gains the hint line
`"j/k: navigate  enter: select  esc: back"`.

**`/scope` command (display-only — scope is immutable for the conversation lifetime,
`conversations.ts:47-50` Decision 2).** New `command.ShowScopeMsg{}` in `internal/command/commands.go`
(alongside `SystemMsg`, L25-29) + a `Def{Name: "scope", Description: "Show the conversation's
bound scope", Category: "general"}` registered in `DefaultRegistry` (L32-77). The app owns the
stored echo: it catches `ShowScopeMsg` in `Update`'s typed switch and forwards a formatted
`command.SystemMsg{Content: …}` into `m.chat.Update` — the chat model already renders it
(`chat/model.go:402-403`), so **zero chat-model changes**. Keys listed in `Redacted` render as
`<redacted>` annotations; no scope bound → `"(no scope bound)"`.

**`Config.DefaultScope`.** Public `Config` (`config.go:14-45`) gains
`DefaultScope map[string]any`; threaded `tui.go:158-162` → app `Config` (`model.go:43-47`) →
entry decision step 2. Consumer-side `--context '<json>'` / `AP_CONTEXT` flag parsing in
`cmd/cockpit` is **out of scope** (the issue locks it to a later consumer change; the library
seam is what ships here).

## Interfaces

```go
// internal/types/types.go

// Instantiation mirrors GET /agents `instantiation` (agent-server/src/routes/agents.ts:89-94).
type Instantiation struct {
    Available bool                      `json:"available"`
    Defaults  map[string]any            `json:"defaults"`
    Schema    map[string]any            `json:"schema"` // decoded, display-none (S-3 / plan §7)
    Presets   map[string]map[string]any `json:"presets"`
}

type AgentSummary struct {
    ID            string
    Name          string
    Role          string
    Instantiation *Instantiation // nil ⇒ scope-less backend / legacy fallback
}

type CreateConversationRequest struct {
    AgentID string         `json:"agent_id"`
    Model   *string        `json:"model,omitempty"`
    Scope   map[string]any `json:"scope,omitempty"` // omitted entirely when nil (Defaults row / scope-less)
}

type CreateConversationResult struct {
    ID       string
    Greeting string
    Scope    map[string]any // redacted 201 echo (`scope` ?? `context`); nil when absent
    Redacted []string       // `context_redacted` keys, when any
}

// ScopeValidationError is the decoded 400 {"error":"scope validation failed","issues":[…]}.
type ScopeValidationError struct{ Issues []ScopeIssue }
type ScopeIssue struct {
    Path    []any  `json:"path"`
    Message string `json:"message"`
}
func (e *ScopeValidationError) Error() string // "scope validation failed: N issue(s)"

// internal/types/client.go
CreateConversation(ctx context.Context, agentID string, scope map[string]any) (CreateConversationResult, error)

// internal/command/commands.go
type ShowScopeMsg struct{} // emitted by /scope; app formats + forwards command.SystemMsg

// internal/app/model.go
type ConversationCreatedMsg struct {
    ConversationID string
    Greeting       string
    ValErr         *types.ScopeValidationError // non-nil ⇒ stay in scope phase, issues are the form
    Err            error
}

// config.go
// DefaultScope, when non-nil, bypasses the interactive scope phase and is sent as-is.
DefaultScope map[string]any
```

## Tests

Per locked acceptance; conventions per `internal/chat/model_test.go` (plain stdlib) and #344's
`httptest` pattern in `internal/httpclient/client_test.go`.

1. `internal/httpclient/client_test.go` (extend): `ListAgents` decodes `instantiation`
   (presets+defaults present / `schema: null` / absent → `Instantiation == nil`);
   `CreateConversation(id, nil)` body has **no** `scope` key; `(id, map)` carries it;
   400 `scope validation failed` → typed `*ScopeValidationError` with issues; other 400 →
   error contains server `error` string; 404 → "Agent not found" surfaced (N2 regression);
   201 echo `scope` + `context_redacted` land in the result.
2. `internal/app/scope_test.go` (new): record-args fake `types.Client`; `available=false` →
   immediate create with nil scope; presets → phase transition, cursor nav, enter on preset
   sends the **merged** map (defaults⊕preset, preset keys win); custom JSON happy /
   parse-error / `PasteMsg` append; `ValErr` keeps the phase and `View()` contains
   `path: message`; `DefaultScope` bypasses the phase.
3. `contracttest` (optional, cheap): scope-create sub-check per File-level plan.
4. Live (Gate-adjacent, needs `ap playground` + a scope-declaring fixture agent):
   picker → preset → force a 400 → fix via Custom JSON → 201 → `/scope` shows the redacted echo.
5. `just quality` green in CI (`check` required status).

## Out of scope

  (S-3). Schema is decoded now so no wire change later; nothing renders it.
- **`cmd/cockpit` `--context` / `AP_CONTEXT` parsing** — consumer follow-up; only the
  `Config.DefaultScope` library seam ships here.
- **Scope mutation / re-scope mid-chat** — server-immutable (`conversations.ts:47-50`);
  `/scope` is display-only.
- **Conversation picker / replay** (#356 territory) and any `internal/chat/model.go` changes.
- **harness-runners contact** — none; scope rides plain HTTP request/response, not SSE.

## Open questions

1. **Error-body decode blast radius**: this PR decodes non-201 bodies in `CreateConversation`
   only (the Risk-11 mandate). Extending the same treatment to `ListAgents`/`ListConversations`/
   `GetConversation` non-200s is cheap but scope-creep — recommend deferring to an opportunistic
   cleanup. Confirm.
2. **Loud-guard split**: stdio/cli/exec/demo error on non-empty scope; `StubClient` accepts and
   ignores (it can never trigger the phase). Confirm the split, or make all five loud.
3. **Merge order vs #347 (abort)**: both touch `internal/app/model.go` in different regions;
   proposal — no stacking, first-approved merges first, the other rebases (plan §1 serial
   protocol). Confirm.
4. **Scope display format**: one system line with sorted keys and `<redacted>` annotations
   (e.g. `scope: api_key=<redacted> org_id="acme"`), reused verbatim by `/scope`. Confirm, or
   prefer pretty-printed multi-line JSON.
