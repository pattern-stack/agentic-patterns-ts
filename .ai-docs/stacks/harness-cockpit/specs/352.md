## Goal

Give tool authors an optional render hint — `displayType?: string`, by convention
`"code" | "diff" | "bash"`, opaque to core — and thread it end-to-end:

```
ToolDefinition.displayType  (core: authoring surface, defineTool passthrough)
  → ToolSchema.displayType  (core: fromZod at BOTH call sites, toDict, frozen class)
    → ToolCallStartEvent / ToolCallEndEvent .displayType  (runtime: runner stamps, 3 contexts × 2 events)
      → SSE payload key `display_type` on tool.start / tool.end  (runtime: sse-formatter, conditional)
```

The consumer is the Go cockpit: `chat-patterns` `internal/sse/types.go:27,36` **already
declares** `DisplayType string \`json:"display_type"\`` on both `SSEToolStartData` and
`SSEToolEndData` (threaded at `parse.go:95,113`). Absent field → `""` → generic render —
graceful on day zero. Where the R3 Go `footer` slice ships its name/hunk-marker sniff
heuristic, this server-declared field **wins whenever non-empty** (B-4); they compose with
no coordination beyond the vocabulary convention.

**Zero server changes**: `packages/agent-server/src/sse.ts:36-40` (`agentEventToSSE`)
delegates verbatim to runtime's `toSSEMapping` — re-verified at HEAD.

**Versioning (state loudly in the PR):** this is the slice that forces **`bump-both` in
rel1 (#355)** — it adds public API surface to core (`ToolDefinition`, `defineTool`,
`ToolSchema` ctor/`fromZod`/`toDict`), so core takes a minor bump alongside the
runtime/server/cli lockstep. No version bump in THIS PR — bumps happen only in rel1
(plan.md §6), with the `rm bun.lock && bun install`-in-the-bump-commit publish gate.

**Ordering:** file-disjoint from the `conversations.ts` chain (`n5 → cancel → shim`,
#351) — this can land at any point; only `rel1` depends on it.

## Approach

Locked dispositions from the dossier (do not re-litigate): **B-1** bare
`displayType?: string` (not `display?: { type }`) — 1:1 onto the Go field, `terminal`
precedent, minimalism; **B-2** do NOT stamp `agent.tool.intent` (no consumer; plan.md §7
deferred with trigger); **B-3** thread through `playbook.ts` fromZod too; **B-5** producer
contract documented in TSDoc + PR description.

### 1. Core — `packages/agent-core/src/molecules/toolbox.ts`

- `ToolDefinition` (L54): add after `terminal?: boolean` (L77):

  ```
  /**
   * Optional render hint for transports/clients ("code" | "diff" | "bash" today,
   * by convention — the string is opaque to core). Same philosophy as `terminal`:
   * core carries the flag, the host/renderer interprets it.
   *
   * Producer contract for the conventional values (B-5):
   *   "diff" — result must be unified-diff TEXT and `arguments.path` names the file;
   *   "code" — result is the code string; language inferred from `arguments.path`;
   *   "bash" — result rendered as a bash block.
   * Renderers rich-render STRING results only — object-returning tools get the
   * generic render regardless of the hint.
   */
  displayType?: string;
  ```

- `defineTool` (L123): add `displayType?: string;` to the spec object type (beside
  `terminal?` L127), and after the `terminal` passthrough (L158-160) mirror it:
  `if (spec.displayType !== undefined) { definition.displayType = spec.displayType; }`
- `getToolSchemas()` (L176-178): thread `def.displayType` as the new trailing `fromZod`
  argument.

### 2. Core — `packages/agent-core/src/molecules/tool-schema.ts`

- `readonly displayType?: string;` after `terminal?` (L51), TSDoc pointing at
  `ToolDefinition.displayType`.
- Constructor (L56-71): 7th trailing optional param `displayType?: string`; assign before
  `Object.freeze(this)`.
- `fromZod` (L78-94): 6th trailing optional param, threaded to the ctor (L93).
- `toDict` (L108-123): add `displayType?: string` to the return type and a conditional
  spread mirroring the `terminal` one at L121:
  `...(this.displayType !== undefined ? { displayType: this.displayType } : {})` —
  preserving the byte-identical-dict guarantee for undeclared tools.
- `fromOpenAI` (L97-105): unchanged (it already drops `returns`/`terminal`).
- `toVercelAI`: unchanged — SDK-facing; the SDK never sees render hints.

### 3. Core — `packages/agent-core/src/molecules/playbook.ts:55`

Thread `def.displayType` in the second `fromZod` call site (B-3 — one line, keeps both
call sites consistent). **Note:** this site currently also omits `terminal` — pre-existing;
do NOT fix it here (behavioral: playbook-sourced schemas would suddenly declare terminal
tools). Flag as a drive-by candidate in the PR description. Since `fromZod`'s params are
positional, threading `displayType` (6th) requires passing `undefined` for `terminal`
(5th) at this site — pass `undefined` explicitly, preserving today's behavior; do NOT pass
`def.terminal`.

### 4. Runtime — `packages/agent-runtime/src/events/types.ts`

Add `readonly displayType?: string;` to:
- `ToolCallStartEvent` (L130-136), after `arguments`;
- `ToolCallEndEvent` (L138-148), beside `error?`.

`createEvent` is typed against these interfaces, so the runner stamps type-check with no
factory change. The events are frozen — hence conditional spread at stamp sites (below),
never an explicit-`undefined` key.

### 5. Runtime — `packages/agent-runtime/src/runner/agent-runner.ts`

Three contexts, each with a `ToolSchema[]` already in scope; 3 × 2 = 6 event literals.
Precedent for a name-keyed lookup built from `agentTools` exists in the same scopes: the
`terminalTools` Sets at L357 (run) and L1245 (stream). All lines @ `2411fc8`.

| Context | Tools in scope | tool.start literal | tool.end literal |
|---|---|---|---|
| `run()` loop | `agentTools` L351 | L597 | L646 |
| `convertExecutableTools()` (L882; SDK-driven; `runStructured`) | per-tool `t` in the L891 loop | L912 | L954 |
| `stream()` loop | `agentTools` L1241 | L1679 | L1742 |

- `run()` / `stream()`: beside each `terminalTools` Set, build
  `const displayTypes = new Map(agentTools.flatMap((t) => t.displayType !== undefined ? [[t.name, t.displayType] as const] : []));`
  then add to each of the four literals:
  `...(displayTypes.has(tc.toolName) ? { displayType: displayTypes.get(tc.toolName) } : {})`
  (conditional spread — frozen events must not carry an explicit-undefined key; the
  formatter guards on `!== undefined` anyway, but key-absence keeps emitted events
  byte-clean for the runner tests' `not.toHaveProperty` assertions).
- `convertExecutableTools()`: `t` is in hand — stamp
  `...(t.displayType !== undefined ? { displayType: t.displayType } : {})` into the
  literals at L912 and L954. No map needed.
- Do **NOT** stamp `agent.tool.intent` (B-2; plan.md §7 has the re-entry trigger: "a
  consumer appears").
- **Scope boundary — other emitters:** `agent.tool.start/end` are also emitted by
  `cc-event-translator.ts` / `claude-code-runner.ts` (CC-native tools — no `ToolSchema`
  exists to source a hint from), `mock-runner.ts`, `workflows/node.ts`, and
  `workflows/as-agent.ts`. They stay untouched: the field is optional, absent → `""` →
  generic render on the Go side. State this boundary in the PR.

- Idiom is byte-for-byte the backpack `display` conditional at **L378/391/407** (dossier

  readonly displayType?: string;

## Tests

Acceptance (from the issue, with re-verified anchors):

1. **core / tool-schema**: `fromZod` with/without the 6th arg → `displayType` present /
   `undefined`; `toDict()` includes `displayType` only when set — assert the
   **byte-identical dict** for undeclared tools (`not.toHaveProperty("displayType")`),
   the same guarantee the `terminal` spread makes.
2. **core / toolbox**: a toolbox with `displayType: "diff"` on one tool →
   `getToolSchemas()` carries it; undeclared sibling → `undefined`.
3. **core / tool-authoring**: `defineTool({ displayType: "code" })` passthrough and
   `"displayType" in plainDefinition === false` on omission (mirror the terminal test
   L166-186 exactly).
4. **runtime / runner (run + stream)**: existing tool-calling fixtures extended — emitted
   `agent.tool.start` / `agent.tool.end` carry `displayType` when the schema declares it
   and **lack the key** (not `undefined`-valued) when not. Cover the
   `convertExecutableTools` path wherever the existing structured-run tool test lives.
5. **runtime / sse-formatter — BOTH files**: event with `displayType` → payload has
   `display_type`; event without → `not.toHaveProperty("display_type")`. Existing
   assertions stay green untouched (their fixture events carry no `displayType`, and the
   key is only added conditionally — regression-safe by construction).
6. **server (optional)**: one `sse.test.ts` assertion that the relay round-trips
   `display_type` (belt-and-braces on the verbatim-relay claim).
7. `bun run check` green (build + typecheck + lint + test — the required PR status).

Cross-repo note: no Go-side test lands here; the Go decode surface pre-exists
(`sse/types.go:27,36`) and its behavior on absent fields (`""` → generic) is already the
shipped default.
