# go: abort — Esc cancels the in-flight turn (cancel-route + ctx-cancel), spinner-leak fix

> **Cross-repo note:** tracker issue lives in `pattern-stack/agentic-patterns-ts`; the code
> change lands in `github.com/pattern-stack/chat-patterns` on branch **`cockpit/abort`**
> (base: `main @ 8c89d4d` — wire #344/PR5, cmd #346/PR4, **and parse #345/PR6 are ALL
> merged**; the build-graph dependency parse → abort is satisfied, no stacking needed).
> All chat-patterns `file:line` anchors below re-verified at `main @ 8c89d4d`. All TS-server
> anchors re-verified at agentic-patterns-ts `main @ 7ae304e`.

## Goal

Esc during a streaming turn stops it — **acknowledged server-side when the backend offers
it, always immediately client-side**:

1. **Cancel-route-first**: `POST /conversations/:id/cancel` (202 `{ok, run_id?}`) via a new
   *optional* `TurnCanceller` capability interface — implemented by `HTTPClient` only.
2. **Then ctx-cancel**: a per-turn `context.CancelFunc` on the chat model tears down the
   POST-body stream. Post-#341, the body drop is *itself* an authoritative server-side
   cancel (`stream.onAbort` → `controller.abort()` + pending-input deny sweep), so even the
   fallback path stops token burn on current servers.
3. **aborted ≠ error**: terminal render is a `"⊘ stopped"` system line, discriminated by
   the local `aborted` flag (ctx-cancel path) or a typed `ChunkCancelled` (server wind-down
   path). **Never string-match "context canceled"** — it arrives laundered through the
   scan_error `APIError` (locked).
4. **Spinner-leak fix** (pre-existing, ships here per issue title): the `handleResponse`
   error arm never resets `spinnerActive`, so the tick loop rebuilds the viewport forever
   after any stream error.
5. Esc while streaming keeps `PhaseChat` (today it silently drops to the agent picker while
   the stream keeps folding); legend becomes `esc: stop/back`; **Ctrl+C stays quit** (scout
   OD §7.1 — resolved: keep).

## Approach

**State change since the plan was written (BINDING on this spec):** #341 is implemented and
merged on TS main (PR #363, reverted, **re-landed via PR #365**, merge `36e7602`; current
main `7ae304e`). Verified route behavior (`packages/agent-server/src/routes/conversations.ts:583-602`):
`POST /conversations/:id/cancel` → 404 unknown conversation · 409 no active turn · 202
`{ok: true, run_id?}` (`run_id` omitted before the first `agent.message.start`). Wind-down
on the still-open messages stream: `message.cancel {reason}` → `conversation.end
{reason:"cancelled"}` → `done` (wire names per `agent-runtime/src/transport/sse-formatter.ts:187-188`,
`:161-165`). Disconnect hardening: `stream.onAbort` and the route's `controller.abort()`
converge on one `onCancel` that deny-sweeps pending inputs (`conversations.ts:439-448`).
The plan's "soft edge" is therefore hard-satisfiable: **cancel-route-first, ctx-cancel
always, bare ctx-cancel on 404/older servers** — the locked disposition.

**Locked dispositions honored, not re-derived:** Risk 10 (split-brain) — live acceptance
verifies the server run row closes cancelled. Abort/approval race — teardown auto-denies
pending inputs; the cockpit renders that race as *cancelled*, never a server error (our
error arm with `aborted` set swallows the laundered error into `"⊘ stopped"`). Ctrl+C stays
`tea.Quit` (`internal/app/model.go:166`).

### 1. Esc sequencing — ordered POST → ctx-cancel via `tea.Cmd`

Bubbletea discipline: model mutation only in `Update`; I/O in a `Cmd`. On Esc while
streaming, `chat.Model.AbortStream()` (signature changes from the scout draft: now returns
`tea.Cmd`):

- set `aborted = true`;
- if `tc, ok := m.client.(types.TurnCanceller); ok` → return a Cmd that calls
  `tc.CancelTurn` with a fresh **3s-timeout** context (NOT the stream ctx — we need the
  POST to survive the teardown) and yields `cancelResultMsg{result, err}`. Do **not**
  ctx-cancel yet — ordering guarantees the server sees an explicit cancel and we get the
  202 ack + `run_id` before the connection drop can race `activeTurn` teardown.
- else (stdio/cli/exec/demo backends) → ctx-cancel immediately (`cancelLocal()`), return nil.

On `cancelResultMsg` (new chat-internal msg, handled in `chat.Model.Update`):
`cancelLocal()` **unconditionally** — 202, 404, 409, error, timeout all tear down locally.
202 vs 404/409 changes nothing about local teardown; it only decides whether the stop was
*acknowledged* (and supplies `run_id` → stash into `m.lastRunID` so a cancelled turn keeps
its `/run` linkage even when ctx-cancel kills the stream before the `done` frame). Outcome
surfaced under `CHAT_DEBUG_EVENTS` only.

**Second Esc while the ack is in flight = impatient escape hatch**: `aborted` already true
→ call `cancelLocal()` immediately (3 lines; see Open questions Q1).

`cancelLocal()` is the shared release helper: nil-check `cancelStream`, call it, nil it.
Satisfies `go vet`'s `lostcancel` (cancel called on submit-error path, stored otherwise,
released in Done/error arms and `cancelResultMsg`).

Why not wait for the server wind-down instead of ctx-cancelling after the ack? Because a
claudeCode-backed agent never winds down — `ClaudeCodeAPIRunner` ignores `abortSignal`
(known adjacent gap, NOT fixed here) — and a watchdog timer is more state than an
unconditional teardown. The ctx-cancel is the guaranteed UI stop; the POST is the
guaranteed server-side record.

```mermaid
sequenceDiagram
  participant U as user (Esc)
  participant A as app.Model
  participant C as chat.Model
  participant H as HTTPClient
  participant S as TS server
  U->>A: Esc (streaming)
  A->>C: AbortStream() — aborted=true
  C-->>H: Cmd: CancelTurn(3s ctx)
  H->>S: POST /conversations/:id/cancel
  S-->>H: 202 {ok, run_id}
  Note over S: controller.abort() + deny sweep;<br/>wind-down: message.cancel → conversation.end{cancelled} → done
  H-->>C: cancelResultMsg{202, run_id}
  C->>C: cancelLocal() — ctx-cancel tears down POST body
  alt wind-down events arrived first
    C->>C: ChunkCancelled → serverCancelled=true; done → "⊘ stopped"
  else teardown won the race
    C->>C: error chunk + aborted → "⊘ stopped"
  end
```

### 2. Terminal discrimination — two flags, three arms

New `chat.Model` fields (struct at `internal/chat/model.go:149-169` region): `cancelStream
context.CancelFunc`, `aborted bool` (user pressed Esc), `serverCancelled bool` (wire said
`message.cancel`).

- **Reducer**: new `case types.ChunkCancelled: m.serverCancelled = true` — no part render;
  the terminal line lands in the Done/error arm. (Also covers the bonus case where another
  client — e.g. the dashboard Stop button — cancels this conversation: the cockpit renders
  stopped without Esc ever being pressed.)
- **Error arm** (`model.go:607-612`): add `m.spinnerActive = false` (**the leak fix** —
  compare the Done arm `:747-750` which already resets it; the tick loop `:380-392` only
  gates on `spinnerActive`), `cancelLocal()`, then: if `aborted || serverCancelled` → reset
  both flags, append system `"⊘ stopped"`, return — **no "Error:" line**. Else existing
  `"Error: …"` behavior unchanged.
- **Done arm** (`:747-766`): `cancelLocal()`, then: if `serverCancelled` → reset both,
  append `"⊘ stopped"`. Else `aborted = false` **silently** — Done-after-abort without a
  `message.cancel` frame means the turn genuinely completed before the cancel took effect;
  the completed content stands (locked acceptance: "Done-after-abort race clears the flag").
- `skipStreaming` (`:893-976`) needs no abort handling: Esc and Enter during streaming are
  mutually exclusive per keypress, and after an Esc the drain loop terminates on the
  teardown's synthetic terminal chunk.

### 3. Parser — promote `message.cancel` to typed `ChunkCancelled`

Post-#345 the frame already flows as `ChunkUnknown{RawEvent:"message.cancel"}` (no-allowlist
flip, `internal/sse/parse.go:197-202`), but string-matching `RawEvent` in the reducer is the
same smell as string-matching "context canceled". One new case in `ChunkFromSSE`, in #345's
vocabulary style (best-effort decode — cancellation doesn't depend on payload, mirrors the
`iteration.*` precedent at `parse.go:165-173`):

`case "agent.message.cancel", "message.cancel":` → `&StreamChunk{Type: ChunkCancelled,
Content: reason, Meta: d.Meta}`. New constant `ChunkCancelled ChunkType = "cancelled"`
(`internal/types/types.go:19-37` block). `conversation.end` stays `ChunkUnknown` — terminal
handling comes from `done` (locked in #345; not relitigated).

### 4. Optional capability, not a `Client` interface change

`types.Client` (`internal/types/client.go:6-25`) has six implementations (http, cli, exec,
stdio, demo, stub). Only HTTP has a cancel route. So: a standalone `TurnCanceller`
interface + `CancelResult` in `internal/types/client.go`; `HTTPClient` implements it; the
chat model type-asserts. Zero churn in the other five backends.

`HTTPClient.CancelTurn`: `POST BaseURL + cancelTurnPath(id)`, nil body, via the JSON client
`c.HTTPClient` (has a timeout — NOT the timeout-free `streamClient`, `client.go:252`).
202 → best-effort decode `{ok, run_id}` → `CancelResult{StatusCode: 202, RunID}`. 404/409 →
`CancelResult{StatusCode}` with **nil error** (expected outcomes: older server / turn
already over — both mean "proceed to ctx-cancel"). Anything else → error. Endpoint plumbing
follows the existing pattern: `endpointConfig.cancelTurn` default
`"/conversations/{id}/cancel"` + `cancelTurnPath()` helper (`client.go:28-70`) + optional
`types.EndpointConfig.CancelTurn` override field (`types.go:186-194`).

### 5. App-level interception order + legend

`updateChat` (`internal/app/model.go:276-291`): Esc branch gains a **first** check —
`if m.chat.IsStreaming() { return m, m.chat.AbortStream() }` — before the clear-input and
back-to-picker branches. New accessor `IsStreaming()` on `chat.Model` (next to
`IsInputEmpty`, `chat/model.go:266-268`). The chat model's own streaming key branch
(`:434-441`) also gains `case "esc"` → `AbortStream()` for standalone use (app intercepts
first in practice). Legend (`app/model.go:397`): `esc: back` → `esc: stop/back`.

Benign edge: if the user Esc-aborts, the stream ends, and they Esc again to the picker
while a `cancelResultMsg` is still in flight, the msg is dropped by `app.Update`'s default
routing (phase switch no longer reaches `updateChat`) — `cancelStream` was already released
in the error/Done arm, so nothing leaks.

## Interfaces

```go
// internal/types/client.go

// CancelResult is the outcome of TurnCanceller.CancelTurn.
type CancelResult struct {
	StatusCode int    // 202 accepted · 404 no route/conversation · 409 no active turn
	RunID      string // from a 202 {run_id}, when the server knows it
}

// TurnCanceller is an optional backend capability: an explicit server-side
// cancel for the in-flight turn. Backends without it (stdio, cli, exec, demo)
// rely on context cancellation alone.
type TurnCanceller interface {
	CancelTurn(ctx context.Context, conversationID string) (CancelResult, error)
}
```

```go
// internal/chat/model.go

// IsStreaming reports whether a turn is currently in flight.
func (m *Model) IsStreaming() bool

// AbortStream begins cancelling the in-flight turn: cancel-route-first when
// the client implements types.TurnCanceller (returned Cmd POSTs and yields
// cancelResultMsg), bare ctx-cancel otherwise. Second call = immediate local
// teardown. aborted ≠ error: the terminal render is "⊘ stopped".
func (m *Model) AbortStream() tea.Cmd

// cancelResultMsg carries the CancelTurn outcome back into Update.
type cancelResultMsg struct {
	result types.CancelResult
	err    error
}
```

## Open questions

1. **Second-Esc escape hatch** (Approach §1): recommended IN — second Esc during the ack
   window forces immediate ctx-cancel. Alternative: single-shot Esc (strictly simpler,
   worst case ~3s of extra spinner on a dead server). Gate call.
2. **Typed `ChunkCancelled` vs `RawEvent` string-match in the reducer**: recommended typed
   (parser vocabulary is #345's established seam; reducer stays string-free). The
   alternative avoids touching `parse.go` in this PR. Gate call.
3. **Stash the 202 `run_id` into `m.lastRunID`**: recommended yes — a cancelled turn keeps
   its `/run` linkage even though ctx-cancel usually kills the stream before the `done`
   frame delivers it. Alternative: drop it (smaller diff).
4. **claudeCode `abortSignal` gap**: file a TS-repo follow-up issue now (recommended;
   epic #339 or standalone) so the cockpit's cancel isn't silently lossy against
   claudeCode-backed agents, or leave it to the epic's close-out review?
