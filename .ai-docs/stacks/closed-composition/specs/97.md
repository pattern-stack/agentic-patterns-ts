# Spec — `asAgent()`: promote any `Node<TIn,TOut>` to an `AgentLike` (keystone)

## Goal

Add the missing **Node → Agent** direction. `AgentStep` already turns an `Agent`
into a `Node` (`workflows/agent-step.ts`). This issue adds the reverse:
`asAgent(node, { role, coerceIn, renderOut })` promotes *any* `Node<TIn,TOut>`
into something the runner, server, playground, and `ap` CLI treat exactly like an
Agent — so `Sequential(fetch, curate, analyze, respond).build()` becomes
**discoverable, chattable, and runnable**. This is the keystone of the
closed-composition stack: once a pipeline *is* an agent, "chain them, then talk
to / eval the chain" falls out, and the consumer's 496-line `playground.ts`
hand-wrapper collapses to one call.

Scope is the promotion adapter **only**. DI (#98), tool-exec bus threading
(#99/#102), eval (#103), retry (#100), and Loop-accumulator (#101) are parallel
/ downstream issues — do not pull them in.

## Key finding — two agent surfaces; unify on one (read before coding)

The design doc (§3) claims *"Discovery already recognizes `AgentLike` — so a
promoted Node is discovered with no new machinery."* **This is only half true**,
and the gap drives the whole design. There are **two different structural
surfaces**:

| Surface | Defined at | Structural requirement | Used by |
|---|---|---|---|
| `AgentLike` | `runner/types.ts:25` | `role:{name}`, `getModel()`, `getTools()`, `getSystemPrompt()`, `renderInitialPrompt()` | AgentRunner, server introspection (`routes/agents.ts`, `routes/composition.ts`), `Conversation` |
| `isAgentShape` | `agent-cli/src/helpers/discover.ts:75` | `role` (object) **+ `mission` (object) + `awareness` present + `background` present** | `ap` CLI discovery |

`AgentLike` has **no** `mission`/`awareness`/`background`. So a bare `AgentLike`
is chattable/runnable but **NOT discoverable** — `ap` would skip it.

**Resolution (Gate-1 decision): teach discovery the `AgentLike` surface — do NOT
fake the stubs.** An earlier draft had `asAgent()` synthesize frozen
`mission`/`awareness`/`background` stubs so `isAgentShape` passes. That is
rejected as dishonest — it fabricates fields a pipeline does not have. Instead
this is treated as a **cleanup that unifies the framework on one agent surface**:
`PromotedAgent` is an *honest* `AgentLike` (no fake atoms), and `discover.ts`
gains an `isAgentLikeShape()` check so discovery recognizes anything that
satisfies the runner/server surface — full core Agents (`isAgentShape`) **and**
promoted pipelines (`isAgentLikeShape`) alike. This also future-proofs discovery
for any other `AgentLike` producer.

Second, deeper finding — **execution is not literally "runnable by AgentRunner".**
`Conversation.run/stream` (`conversation/conversation.ts:159,224`) executes a turn
as `this.runner.run(this.agent, message)`, and the injected runner is an
`AgentRunner` that drives an **LLM tool-loop over the agent's system prompt +
tools**. A promoted pipeline must instead execute `node.run(coerceIn(message),
ctx)` and render `renderOut(output)` — it must NOT be LLM-looped. Crucially, the
pipeline may contain nested `AgentStep`s whose `run()` calls `ctx.runner.run(...)`
(`agent-step.ts:116,126`) — those *do* need the real LLM runner. So the injected
`AgentRunner` is still needed, but as the **inner `ctx.runner`**, not as the thing
that runs the promoted agent.

The clean resolution (below) keeps the server/discovery/runner **unchanged** and
confines all new behavior to a new file + a ~2-line CLI attach change.

## Approach

Introduce a promoter and a Node-backed runner in a single new file
`packages/agent-runtime/src/workflows/as-agent.ts`:

1. **`asAgent(node, opts)` returns a `PromotedAgent`** — a frozen, **honest**
   `AgentLike` (no fabricated atoms):
   - **satisfies `AgentLike`** (`role:{name}`, `getModel`, `getTools`→`[]`,
     `getSystemPrompt`, `renderInitialPrompt`), mirroring how `applyStepModel`
     (`workflows/base.ts:169`) already hand-builds an `AgentLike` literal.
   - carries the node payload — `__promotedNode`, `coerceIn`, `renderOut`, and the
     declared `model`/`role` — so the runner can execute it.
   - **carries NO `mission`/`awareness`/`background`.** Discoverability comes from
     teaching `discover.ts` the `AgentLike` surface (step 3a), not from stubs.

2. **`NodeBackedRunner` implements `RunnerProtocol`** (`run` + `stream`) over the
   promoted node. `run(agent, message, opts)`:
   - resolves the `PromotedAgent` from `agent`,
   - builds a `NodeRunContext` whose **`runner` is the injected LLM `AgentRunner`**
     (so nested `AgentStep`s call the real model), plus a fresh `scratchpad` and
     the `traceId` from `opts`,
   - calls `node.run(coerceIn(message), ctx)`,
   - maps `NodeResult<TOut>` → `RunResult`: `response = renderOut(output)`,
     `inputTokens/outputTokens` from the node totals, `finishReason =
     succeeded ? "stop" : "error"`, `toolCallsCount: 0`, `iterations: 1`.
   - `stream()` yields a minimal event sequence (`message.start` → one
     `message.chunk` with the full rendered response → `message.complete`) so the
     server SSE chat path (`routes/conversations.ts:71,80` — which requires
     `runner.stream`) works even though the pipeline does not token-stream.

3a. **Teach discovery the `AgentLike` surface.** In `discover.ts`, add
   `isAgentLikeShape(x)` — a bundle-proof duck-type (same rationale as
   `isAgentShape`: `instanceof` is unreliable across the built-`dist/` module
   boundary): `x.role` is an object with `name: string`, **and** `getModel`,
   `getSystemPrompt`, `renderInitialPrompt` are all functions. That fingerprint is
   distinctive enough not to collide with a full core Agent or a random object.
   Document it in the same comment style as `isAgentShape`. Then:
   - The direct-export test becomes `isAgentShape(value) || isAgentLikeShape(value)`.
   - `asWrapper(x)` accepts a wrapper whose `.agent` satisfies **either** shape
     (`isAgentShape(w.agent) || isAgentLikeShape(w.agent)`).
   - `isAgentShape` is **unchanged** — full core Agents keep discovering exactly as
     today; this is purely additive.

3b. **The only other wiring change — CLI runner attach.** Today the CLI attaches one
   shared LLM runner to every registration (`commands/playground.ts:106`,
   `commands/run.ts:50`). Change the attach to: if the registration's agent is a
   promoted node, attach a `NodeBackedRunner` bound to the shared runner as its
   inner runner; otherwise attach the shared runner unchanged. One helper
   (`isPromotedAgent(x)` guard + `nodeBackedRunner(agent, inner)`), applied at
   the ~2 attach call-sites. **The server changes nothing** — `routes/conversations.ts`
   just uses `reg.runner`, which is now node-backed for promoted regs. This is
   what makes "server picks it up with no new machinery" literally true.

### Coercion seams (acceptance: explicit options, sane string defaults)

- **`coerceIn: (message: string) => TIn`** — message → node input. Default is
  identity (`m => m as TIn`), correct when `TIn = string`. Type the options so
  `coerceIn` is **optional when `TIn extends string`, required otherwise**
  (conditional-typed options object) — the compiler forces a coercer for a
  non-string pipeline, matching the "typed coercion seam" acceptance.
- **`renderOut: (out: TOut) => string`** — node output → chat message. Default:
  `out => typeof out === "string" ? out : JSON.stringify(out, null, 2)`.

### Role identity

`opts.role` accepts either a full core `Role` or a minimal `{ name: string;
description?: string }`. `getSystemPrompt()`/`renderInitialPrompt()` render the
Role's prompt when a full Role is given, else return a one-line descriptor
(`"Promoted pipeline: <node.name ?? 'pipeline'>"`). Optional `opts.model`
sets `getModel()`; default a sensible tier string (e.g. `"sonnet"`), overridable.
Note server introspection reads `role.capabilities`, `role.defaultModel`,
`mission?.data` via optional-chaining (`routes/composition.ts:518,527,249`), so
minimal stubs are safe — absent fields render as empty, never throw.

## Interfaces

```typescript
/** Minimal role input — a full core Role, or just a name. */
export type RoleInput = Role | { readonly name: string; readonly description?: string };

/** Conditional options: coerceIn optional for string pipelines, required otherwise. */
export type PromoteOptions<TIn, TOut> = {
  readonly role: RoleInput;
  readonly model?: string;
  readonly renderOut?: (out: TOut) => string;
} & (TIn extends string
  ? { readonly coerceIn?: (message: string) => TIn }
  : { readonly coerceIn: (message: string) => TIn });

/** Honest AgentLike + node payload. NO mission/awareness/background stubs. */
export interface PromotedAgent<TIn, TOut> extends AgentLike {
  readonly __promotedNode: Node<TIn, TOut>;   // brand + payload for isPromotedAgent()
  readonly coerceIn: (message: string) => TIn;
  readonly renderOut: (out: TOut) => string;
}

export function asAgent<TIn, TOut>(
  node: Node<TIn, TOut>,
  opts: PromoteOptions<TIn, TOut>,
): PromotedAgent<TIn, TOut>;

export function isPromotedAgent(x: unknown): x is PromotedAgent<unknown, unknown>;

// --- added to agent-cli/src/helpers/discover.ts ---
/** Bundle-proof duck-type for the AgentLike runner/server surface (see isAgentShape rationale). */
export function isAgentLikeShape(x: unknown): boolean;
// role:{name:string} object + getModel/getSystemPrompt/renderInitialPrompt all functions.
// Discovery accepts isAgentShape(x) || isAgentLikeShape(x), directly and inside asWrapper.

/** RunnerProtocol that executes a PromotedAgent's node; inner = LLM runner for nested AgentSteps. */
export class NodeBackedRunner implements RunnerProtocol {
  constructor(inner: RunnerProtocol);
  run(agent: AgentLike, message: string, options?: RunOptions): Promise<RunResult>;
  stream?(agent: AgentLike, message: string, options?: RunOptions): AsyncGenerator<AgentEvent>;
}
```

## Tests

`workflows/__tests__/as-agent.test.ts` (vitest, mirroring `sequential.test.ts`
conventions — a fake `RunnerProtocol` returning canned `RunResult`s, no live LLM):

1. **Sequential promotion + run.** `asAgent(Sequential.start(a).then(b).build(),
   { role: { name: "Pipe" } })`, run via `NodeBackedRunner` over a fake inner
   runner; assert both nodes execute in order, `RunResult.response ===
   renderOut(finalOutput)`, tokens are summed from the node totals.
2. **Discoverability (in `agent-cli` test suite).** (a) A promoted object passes
   `isAgentLikeShape` and is picked up by `loadAgentsFromFile` (both as a direct
   export and inside a `{ agent }` registration wrapper). (b) **No regression** —
   a full core Agent still discovers via `isAgentShape`. (c) **Negative case** — a
   random object with only `{ role: { name } }` (no `getModel`/render methods, no
   `mission`/`awareness`/`background`) discovers under **neither** shape and is
   skipped.
3. **AgentStep round-trip (Agent→Node→Agent).** Wrap a fake core Agent in
   `AgentStep`, promote it back with `asAgent`, run it; assert the inner agent is
   driven through the inner runner and the response round-trips.
4. **Coercion defaults & seams.** String pipeline works with no `coerceIn`
   (identity); a non-string `TIn` pipeline uses a supplied `coerceIn`; `renderOut`
   default JSON-stringifies a non-string `TOut`.
5. **Failure mapping.** A node returning `{ succeeded: false }` maps to
   `finishReason: "error"` and surfaces the rendered/failed output without throwing.
6. **Stream shape.** `NodeBackedRunner.stream` emits `message.start` → chunk →
   `message.complete` for the SSE path.

Gate: `bun run check` (build + typecheck strict + biome + vitest) green;
`bun run --filter=@agentic-patterns/runtime test` covers the new suite.

## Conventions honored

- **Additive, layer-legal** — new file in runtime layer 9 (workflows); imports
  only core + lower runtime layers; core never imported *from* for execution
  logic beyond types. No `Node` rewrite (§5 non-goal). Role algebra untouched.
- **Immutability** — `PromotedAgent` and its stubs `Object.freeze()`d, matching
  `SequentialNode`'s frozen result and the `applyStepModel` literal pattern.
- **Barrel exports** — surfaced through `workflows/index.ts` → runtime `index.ts`.
- **Fluent-builder friendly** — `asAgent(builder.build(), { role })` is the
  intended single call; no new builder needed.

## Decisions (resolved at Gate 1)

1. **Discovery unified, no stubs.** `PromotedAgent` is an honest `AgentLike`;
   `discover.ts` gains `isAgentLikeShape` and accepts either shape. No
   `mission`/`awareness`/`background` fabrication.
2. **Runner-attach seam is CLI-only** (`playground.ts` + `run.ts`), leaving the
   server byte-unchanged. A runtime `resolveRunner()` helper is deferred until a
   second embedder (e.g. #103 eval) needs the same resolution server-side.
3. **`getTools() → []`** — a promoted pipeline exposes no top-level tools; nested
   `AgentStep`s carry their own.
4. **`stream()` emits a single chunk** (the fully rendered response). True
   per-node streaming is an explicit follow-on, out of keystone scope.
