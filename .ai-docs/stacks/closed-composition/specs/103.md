# Spec — First-class eval: typed cases-in / scores-out over `Agent` and `Node`

## Goal

Promote the consumer's hand-rolled `__bench__/eval-*.ts` pattern into a framework
primitive: **feed a bank of typed cases through a runnable, collect typed scores.**
Because the keystone (#97, `asAgent`) closed composition, a bare `Node`, a bare
`Agent`, and an `asAgent`-promoted pipeline are all reducible to one thing —
`Node<TIn,TOut>` — so **one eval surface covers all three with the same API**. This
is the design doc's "tune each against individual evals" ask (§4 item 4), made native.

v1 is the **in-memory typed harness**: `runEval({ target, cases, scorers }, { runner })`
→ `EvalReport`. Case / Score / Result / Report envelopes are Zod-schema'd per project
convention; the report is a plain typed object, consumable programmatically (persist,
assert in a test, print — the harness itself does none of these). The runner is
injected, so evals run against a `MockRunner` in unit tests with zero live LLM calls.

## Scope decision — does it fit one PR? Yes, at this cut line (read first)

This is the largest-surface issue of the five, so the scope boundary IS the spec's
most important decision. **v1 fits one PR** iff we hold this line:

**In v1 (this PR):**
- The typed envelopes (`EvalCase`, `Score`, `EvalResult`, `EvalReport`) + their Zod schemas.
- `runEval(spec, ctx)` — the harness: normalize target → `Node`, run each case, apply
  scorers, aggregate.
- The **target adapter** (`resolveEvalTarget`) that reduces `Node | AgentLike |
  PromotedAgent` to a `Node<TIn,TOut>` — this is where "one API, three targets" lives,
  and it is only possible *because* #97 closed composition.
- Two built-in pure-function scorers (`exactMatch`, `predicateScorer`) as reference +
  the `Scorer` contract.
- Unit tests over `MockRunner` for all three target kinds.

**Explicitly deferred (each a clean fast-follow, called out so Gate 1 can confirm the cut):**
- **LLM-judge scorer** (`grade.ts` in the consumer) — v1's `Scorer` is `async`, so a
  judge is *just a scorer that calls a runner*; the door is built, the door is not walked
  through. Follow-on issue.
- **Persistence / score store** (the consumer's `EvalStore` sqlite + cockpit) — the
  design doc (§5) classifies persistence as a *consumer* concern; v1 returns the report
  and exposes an optional `onResult` hook. A `SQLiteExporter`-aligned eval store is a
  separate issue.
- **`ap eval` CLI + split discipline** (train/test/validate) — a CLI surface over the
  harness; out of scope for the primitive.
- **Case-bank loaders** (jsonl/gold files) — the harness takes `cases: EvalCase[]`
  in-memory; file loaders are userland/CLI concerns.

If Gate-1 review wants any deferred item pulled forward, that is the signal to split
#103 into #103a (harness) + #103b (judge/store) rather than inflate this PR.

## Key finding — all three targets are already `Node<TIn,TOut>` (the whole design)

The acceptance criterion "runs against a bare Node, a bare Agent, and an asAgent-promoted
pipeline with the same API" sounds like three code paths. **It is one**, because #97
made composition closed. Reduction table:

| Target kind | Detect with | Reduce to `Node<TIn,TOut>` by |
|---|---|---|
| bare `Node<TIn,TOut>` | has a `.run(input, ctx)` function, not promoted | itself |
| `asAgent`-promoted pipeline | `isPromotedAgent(x)` (`workflows/as-agent.ts`) | `x.__promotedNode` (already a `Node<TIn,TOut>`) |
| bare `Agent` / `AgentLike` | `isAgentLikeShape`-style duck-type (`role.name` + `getModel`/render fns) | wrap in `AgentStep<string,string>` with `prompt: (i) => String(i)` — the existing Agent→Node bridge |

`AgentStep` (`workflows/agent-step.ts`) is the pre-existing Agent→Node adapter; a bare
Agent evaluated by the harness becomes a `Node<string,string>` (message in, response
out). The promoted pipeline is unwrapped to the node it already carries — eval feeds
**typed `TIn` directly**, bypassing chat coercion (cleaner than routing through
`coerceIn`; see Decisions #3). Every target then executes identically:
`node.run(case.input, ctx)` where `ctx: NodeRunContext` carries the **injected runner**.

That injected runner is the "keep the runner injectable so evals run against fakes"
requirement: in tests it is a `MockRunner`; in production it is a real `AgentRunner`.
Nested `AgentStep`s inside a promoted pipeline see it as `ctx.runner` and call the real
model — identical to how `NodeBackedRunner` threads its inner runner (#97).

## Approach

New runtime module `packages/agent-runtime/src/eval/`, a **consumer** of the workflows
layer (imports `Node`/`NodeRunContext`, `AgentStep`, `isPromotedAgent`) + the runner
layer. Nothing in workflows/runner imports *from* eval, so it sits cleanly above layer 9
with no cycle.

1. **Typed envelopes + Zod schemas** (`eval/types.ts`). The envelope is schema'd; the
   payloads `TIn`/`TOut`/`TExpected` stay generic (the caller owns their shapes), exactly
   as `AgentConfig` is Zod'd while carrying generic `capabilities: string[]`. See Interfaces.

2. **`Scorer` contract** (`eval/scorer.ts`). A scorer is a pure(-ish) async function
   `(ctx) => Score | Score[]` over `{ input, output, expected, case }`. Two built-ins:
   - `exactMatch(opts?)` — deep-equals `output` vs `expected`; `value` 1/0, `passed` set.
   - `predicateScorer(name, fn)` — wrap any `(output, expected, input) => boolean|number`
     into a `Score`. This is what the consumer's mechanical evals (recall@k, gold
     retention, phantom-deal gate in `eval-retrieval.ts`/`eval-curate.ts`) become —
     each is a pure function over the node output; the harness owns the loop/aggregate
     they hand-roll.

3. **Target adapter** (`eval/target.ts`) — `resolveEvalTarget(target)` per the Key-finding
   table, returning `{ node, kind }`. The one place the three targets converge. Reuses
   `isPromotedAgent` from `workflows/as-agent.ts`; defines a local `isNodeShape` /
   `isAgentLikeShape` guard (bundle-proof duck-type, same rationale as `discover.ts`'s
   `isAgentShape` — `instanceof` is unreliable across the built-`dist/` boundary).

4. **The harness** (`eval/run-eval.ts`) — `runEval(spec, ctx)`:
   - resolve target → `node`;
   - construct the base `NodeRunContext` from `ctx` (`runner` required; `hooks`,
     `toolExecutor`, `traceId`, a fresh `scratchpad` per case via `createScratchpad()`);
   - for each `case`: `node.run(case.input, nodeCtx)` → `NodeResult<TOut>`; run all
     scorers over the output (a failed node → `succeeded:false`, `scores: []`, error
     captured, and it must not throw — errors count, per the consumer's "an errored
     question scores 0" discipline); build `EvalResult`;
   - optional `spec.onResult(result)` callback (the persistence seam — no built-in store);
   - aggregate `EvalReport.summary` (n, passed/failed counts, per-scorer mean, total
     tokens, elapsed — elapsed measured by the *caller*-injected clock or omitted in v1
     to stay deterministic; see Decisions #5).
   - Concurrency: sequential in v1 (deterministic, simplest); a `concurrency` option is
     a noted extension (the consumer runs sequentially too).

5. **Barrel** — new `eval/index.ts` re-exporting the public surface; runtime top-level
   `index.ts` gains `export * from "./eval/index.js"`.

## Interfaces

```typescript
import { z } from "zod";
import type { Node, NodeRunContext } from "../workflows/node.js";
import type { AgentLike } from "../runner/agent-runner.js";
import type { PromotedAgent } from "../workflows/as-agent.js";
import type { RunnerProtocol, ToolExecutor } from "../runner/types.js";
import type { PatternHooks } from "../workflows/base.js";

// --- Envelopes: schema'd shells, generic typed payloads -------------------

/** One eval case: typed input + optional expected + metadata. */
export interface EvalCase<TIn, TExpected = unknown> {
  readonly id: string;
  readonly input: TIn;
  readonly expected?: TExpected;
  readonly tags?: readonly string[];
}
export const EvalCaseSchema = z.object({
  id: z.string(),
  input: z.unknown(),            // TIn — caller narrows via z.infer at their seam
  expected: z.unknown().optional(),
  tags: z.array(z.string()).readonly().optional(),
});

/** One scorer's verdict on one case. Numeric `value`; optional gate `passed`. */
export interface Score {
  readonly name: string;                       // scorer id, e.g. "exact-match", "recall@60"
  readonly value: number;                      // normalized numeric (0..1 by convention)
  readonly passed?: boolean;                   // optional hard gate
  readonly detail?: Record<string, unknown>;   // forensics (dropped-gold, sizes, ...)
}
export const ScoreSchema = z.object({
  name: z.string(),
  value: z.number(),
  passed: z.boolean().optional(),
  detail: z.record(z.unknown()).optional(),
});

/** Per-case outcome: the run result + every scorer's Score. */
export interface EvalResult<TIn, TOut, TExpected = unknown> {
  readonly case: EvalCase<TIn, TExpected>;
  readonly output?: TOut;                       // absent when the node failed
  readonly scores: readonly Score[];
  readonly succeeded: boolean;                  // node execution succeeded
  readonly error?: string;                      // error message when it did not
  readonly inputTokens: number;
  readonly outputTokens: number;
}

/** The whole run: per-case results + aggregate summary. Consumable programmatically. */
export interface EvalReport<TIn, TOut, TExpected = unknown> {
  readonly target: EvalTargetKind;              // "node" | "agent" | "promoted"
  readonly results: readonly EvalResult<TIn, TOut, TExpected>[];
  readonly summary: {
    readonly cases: number;
    readonly succeeded: number;                 // node-level successes
    readonly errored: number;
    readonly scoreMeans: Readonly<Record<string, number>>;  // per scorer name → mean value
    readonly passRate: Readonly<Record<string, number>>;    // per scorer name → fraction passed (when `passed` set)
    readonly totalInputTokens: number;
    readonly totalOutputTokens: number;
  };
}

// --- Scorer ---------------------------------------------------------------

/** Pure(-ish) scoring function. Async so an LLM-judge is a natural extension. */
export type Scorer<TIn, TOut, TExpected = unknown> = (args: {
  readonly input: TIn;
  readonly output: TOut;
  readonly expected?: TExpected;
  readonly case: EvalCase<TIn, TExpected>;
}) => Score | Score[] | Promise<Score | Score[]>;

export function exactMatch<TOut>(opts?: { name?: string }): Scorer<unknown, TOut, TOut>;
export function predicateScorer<TIn, TOut, TExpected>(
  name: string,
  fn: (output: TOut, expected: TExpected | undefined, input: TIn) => boolean | number,
): Scorer<TIn, TOut, TExpected>;

// --- Target adapter -------------------------------------------------------

export type EvalTargetKind = "node" | "agent" | "promoted";
export type EvalTarget<TIn, TOut> =
  | Node<TIn, TOut>
  | AgentLike
  | PromotedAgent<TIn, TOut>;

/** Reduce any target to a Node<TIn,TOut>. The one place the three paths converge. */
export function resolveEvalTarget<TIn, TOut>(
  target: EvalTarget<TIn, TOut>,
): { readonly node: Node<TIn, TOut>; readonly kind: EvalTargetKind };

// --- The harness ----------------------------------------------------------

export interface EvalRunContext {
  readonly runner: RunnerProtocol;              // INJECTED — MockRunner in tests
  readonly hooks?: PatternHooks;
  readonly toolExecutor?: ToolExecutor;
  readonly traceId?: string;
}

export interface EvalSpec<TIn, TOut, TExpected = unknown> {
  readonly target: EvalTarget<TIn, TOut>;
  readonly cases: readonly EvalCase<TIn, TExpected>[];
  readonly scorers: readonly Scorer<TIn, TOut, TExpected>[];
  /** Optional per-result seam — persistence/streaming hook (no built-in store in v1). */
  readonly onResult?: (r: EvalResult<TIn, TOut, TExpected>) => void | Promise<void>;
}

export function runEval<TIn, TOut, TExpected = unknown>(
  spec: EvalSpec<TIn, TOut, TExpected>,
  ctx: EvalRunContext,
): Promise<EvalReport<TIn, TOut, TExpected>>;
```

## Tests

`eval/__tests__/run-eval.test.ts` (vitest; mirrors `as-agent.test.ts` conventions —
`MockRunner`, `FunctionStep`/`AgentStep`/`Sequential` fixtures, no live LLM):

1. **Bare Node target.** A `FunctionStep<string,string>` (or `Sequential`) evaluated
   over 3 cases; assert each output, `exactMatch` scores, and `summary.scoreMeans`.
2. **Bare Agent target.** A fake `AgentLike` + `MockRunner.addResponse("*", …)`; assert
   the harness wraps it in an `AgentStep<string,string>`, runs via the injected mock,
   and `output === response`. Proves "runner injectable → fakes in tests".
3. **Promoted pipeline target.** `asAgent(Sequential.start(a).then(b).build(), { role })`
   fed to `runEval`; assert it is unwrapped to `__promotedNode` and cases feed typed
   `TIn` directly (bypassing `coerceIn`), scores aggregate. **The same `runEval` call
   shape as #1 and #2** — the acceptance criterion, asserted as one API.
4. **`predicateScorer` + multiple scorers per case.** Two scorers on one case →
   `scores.length === 2`, both in `scoreMeans`/`passRate`.
5. **Node failure is scored, not thrown.** A node returning `{ succeeded:false, error }`
   → `EvalResult.succeeded === false`, `error` captured, `scores: []`, `summary.errored`
   incremented; `runEval` resolves (never rejects) — the consumer's "errors must hurt
   the metrics, not vanish" discipline.
6. **`onResult` seam.** Assert it fires once per case with the built `EvalResult`
   (the persistence hook works without a store).
7. **Zod schema round-trip.** `ScoreSchema`/`EvalResultSchema` parse a built result
   (schema is honored, not decorative).

## Conventions honored

- **Additive, layer-legal** — new module in runtime, above workflows (layer 9); imports
  only lower runtime layers + core types. Nothing in workflows/runner imports eval → no
  cycle. `Node` is not rewritten (§5 non-goal); eval adds no field to `NodeRunContext`.
- **Zod schemas** — envelopes schema'd (`EvalCaseSchema`, `ScoreSchema`, …), `z.infer`
  for types, generic payloads mirroring `AgentConfig`'s `capabilities: string[]` pattern.
- **Immutability** — `readonly` throughout the envelopes; `EvalReport` frozen on return.
- **Async throughout** — `Scorer` and `runEval` are `Promise`-returning (the LLM-judge seam).
- **Barrel exports** — `eval/index.ts` → runtime `index.ts`.
- **Injectable runner** — `EvalRunContext.runner` is the sole execution dependency;
  `MockRunner` in tests, `AgentRunner` in production. No global/singleton runner.

## Decisions (proposed — confirm at Gate 1)

1. **One harness, one adapter — not three code paths.** "Same API over Node/Agent/pipeline"
   is delivered by `resolveEvalTarget`, which exists *only because* #97 closed composition.
   This is the load-bearing design choice; everything else is mechanical.
2. **`Scorer` is a pure async function in v1 — not a judge-agent class.** Keeps v1 minimal
   while leaving the LLM-judge as a drop-in async scorer (deferred issue). Rejected: a
   `Scorer` interface/class hierarchy — premature.
3. **Eval feeds typed `TIn` to the promoted node directly, bypassing `asAgent`'s
   `coerceIn`.** `coerceIn` is a *chat* (string→TIn) concern; eval cases are already
   typed. Cleaner and type-safe. (An opt-in "eval through the chat coercion" mode is a
   noted extension, not v1.)
4. **Persistence is a `onResult` seam, not a built-in store.** Design doc §5 makes
   persistence a consumer concern; the consumer's `EvalStore` (sqlite) becomes a separate
   `SQLiteExporter`-aligned issue. v1 returns a plain typed `EvalReport`.
5. **No wall-clock in v1 summary.** `Date.now()`-based `elapsedMs` would make the report
   non-deterministic (and this project's tooling forbids ambient clocks in some contexts);
   timing is a caller concern or a later optional `clock` injection. Summary is
   counts/means/tokens only.
6. **Sequential execution in v1.** Deterministic and matches the consumer's per-question
   loop; a `concurrency` option is a noted extension.

## Open questions (for Gate 1)

- **Scorer failure semantics.** If a *scorer* (not the node) throws — e.g. a malformed
  gold row — should the case error out, or should that scorer's `Score` be dropped with
  the rest recorded? Proposed: catch per-scorer, record a `value:0, detail:{error}` Score,
  keep the others (mirrors "errors hurt, don't vanish"). Confirm.
- **`expected` typing.** v1 types `TExpected` as a third generic defaulting to `unknown`.
  Acceptable, or should a case with no `expected` be a distinct type (two-generic
  `EvalCase<TIn>`) to avoid `expected?: undefined` noise? Proposed: keep the three-generic
  form with `unknown` default — simplest, and scorers that need `expected` narrow it.
- **Should the bare-Agent adapter's `prompt` be overridable?** v1 hard-codes
  `prompt: (i) => String(i)`. A non-string `TIn` agent eval would need a custom prompt
  builder. Proposed: v1 supports string-in agents only (the common case); a
  `promptFor?: (input) => string` option on `EvalSpec` is the extension if needed. Confirm
  the string-only cut is acceptable for v1.
