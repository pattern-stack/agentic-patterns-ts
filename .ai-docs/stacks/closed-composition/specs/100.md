# Spec — Node-native bounded retry

## Goal

Add a **retry combinator** that wraps any `Node<TIn,TOut>` and re-runs it, up to a
bounded number of attempts, when an attempt fails — returning the first success
immediately or the last failure after the budget is spent. It preserves the wrapped
node's exact types (`Node<TIn,TOut>` in, `Node<TIn,TOut>` out), accumulates token
totals honestly across every attempt, and gates retries behind a caller-supplied
predicate with optional backoff between attempts.

This is item 5 of the closed-composition follow-ons (`docs/closed-composition.md`
§4). It **deletes** the consumer's hand-rolled
`~/retrieval-agent-2.0/canvas-workstation/src/query-surface/workflow/structured-retry.ts`
(49 lines, whose own header reads *"UPSTREAM: a runtime-native bounded retry …
deletes this file"*). That file exists because `runStructured`'s no-tools path makes
a schema-parse flake (`"No object generated"`) one-shot fatal, and *execution
robustness belongs to code, decisions to the LLM* — exactly what a retry combinator
encodes.

Scope is the retry combinator **only**. Loop-with-accumulator (#101) and Node DI
(#98) are parallel issues — do not pull them in. This does **not** rewrite `Node`,
touch the Role algebra, or change any existing combinator (§5 non-goals).

## Key finding — "failed NodeResult" vs "thrown error" (read before coding)

The brief flags that the predicate must handle *both* a failed `NodeResult`
(`succeeded:false` + `error`) **and** a thrown error. Grounding this against the
code sharpens the design:

- **Every in-framework leaf catches and returns a failed `NodeResult` — it never
  throws.** `AgentStep.run` wraps its whole body in `try/catch` and returns
  `{ succeeded:false, error, totalInputTokens:0, totalOutputTokens:0 }`
  (`workflows/agent-step.ts:132`); `FunctionStep` does the same and its header states
  *"ALWAYS catches and returns `{ succeeded:false, error }`"* (`function-step.ts:9`).
  So the consumer's `structured-retry.ts` only ever inspects `last.succeeded` — it
  never needs a `try/catch`.
- **But `Retry` wraps *any* `Node<TIn,TOut>`** — including user-authored nodes and
  composites that don't honor the leaf convention (a bug, a raw `async` node, a
  `FanOut` branch that rejects). If such a node's `run()` **rejects**, an
  uncaught throw would escape the retry entirely and defeat the combinator.
- **The composites confirm this asymmetry.** `Loop.run` and `SequentialNode.run`
  branch **only** on `res.succeeded` and never `try/catch` the child `run()`
  (`loop.ts:81`, `sequential.ts:110`) — they *trust* the leaf convention. `Retry`,
  being a robustness primitive whose entire job is to absorb flakes, must **not**
  make that assumption.

**Resolution:** `Retry` treats a rejected `run()` and a returned failed `NodeResult`
as the *same logical failure*. It `try/catch`es each attempt: a throw is normalized
to `{ error, result: undefined }`, a failed result to `{ error: result.error,
result }`. Both feed one predicate. Token accounting for a throw contributes `0/0`
(there is no result to read totals from), exactly as `AgentStep`'s own catch does.
This is the one substantive behavioral decision in the issue; everything else is
mechanical.

## Approach

Introduce one new file `packages/agent-runtime/src/workflows/retry.ts`, mirroring the
**`Loop`/`Accumulate` shape** (a `Node`-implementing class built from a frozen spec
object — *not* a `.then()` fluent builder, which is for multi-node pipelines):

1. **`class Retry<TIn,TOut> implements Node<TIn,TOut>`**, constructed from a
   `RetrySpec<TIn,TOut>`. It validates `maxAttempts` is a positive integer in the
   constructor and throws otherwise — the exact guard `Loop` uses for `maxIterations`
   (`loop.ts:46`). `name` comes from `spec.name`.

2. **`run(input, ctx)` loop** (attempts `1..maxAttempts`):
   - Derive `childCtx = { ...ctx, scratchpad: ctx.scratchpad ?? createScratchpad() }`
     — identical to every other composite, so a nested `AgentStep` still reaches the
     real `ctx.runner`. The **same `input` and `childCtx` are reused for every
     attempt** (retry is idempotent re-execution, not a fold).
   - Emit `onPatternStart` once, and `onIterationStart`/`onIterationComplete` per
     attempt (reusing `PatternHooks`, exactly like `Loop`), so the dashboard's
     Live/Graph views show each retry.
   - Execute one attempt inside `try/catch`:
     - success (`res.succeeded === true`) → accumulate its tokens, set
       `exitReason: "succeeded"`, return immediately with the **accumulated** totals
       spread over the successful result.
     - failed result → accumulate `res` tokens, build
       `RetryFailure{ error: res.error ?? Error("<name>: attempt failed"), result: res, attempt }`.
     - thrown → accumulate nothing (0/0), build
       `RetryFailure{ error: normalizeError(thrown), result: undefined, attempt }`.
   - After a failure, if `attempt === maxAttempts` → stop (`exitReason:
     "attempts_exhausted"`). Else consult `shouldRetry(failure)`: `false` → stop
     (`exitReason: "predicate_declined"`); `true` → `await sleep(computeDelay(...))`
     if `backoff` is set, then loop.
   - On any stop-with-failure, return a failed `NodeResult` carrying the **last**
     failure's error and the accumulated token totals (never re-throw) — matching
     `structured-retry.ts`'s "after budget exhaustion the LAST failure is returned"
     and `Loop`'s "return the last state, caller branches on `exitReason`" ethos.

3. **Token honesty.** `totalInputTokens`/`totalOutputTokens` sum across **all**
   attempts (each failed attempt still burned tokens), and the returned result — on
   success *or* exhaustion — carries the accumulated totals, not just the last
   attempt's. This is the single invariant `structured-retry.ts` was written to
   preserve; the test plan asserts it explicitly.

4. **Predicate — default retry-on-any-failure.** `shouldRetry` is optional; its
   default is `() => true` (retry every failure until the cap), reproducing the
   consumer's unconditional "retry ONLY on failure" behavior. Callers narrow it,
   e.g. `f => /No object generated/.test(f.error.message)`.

5. **Backoff — kept deliberately small (no jitter).** `backoff?: RetryBackoff` is a
   two-member discriminated union: `{ kind:"fixed"; delayMs }` and
   `{ kind:"exponential"; delayMs; factor?; maxDelayMs? }` (`factor` default `2`).
   A pure `computeDelay(backoff, attempt)` maps the 1-based *failed* attempt to a
   wait; `exponential` = `min(delayMs * factor^(attempt-1), maxDelayMs ?? ∞)`.
   Default (no `backoff`) = **no delay**, so the vast majority of tests run without
   timers. The delay is awaited **between** attempts only — never before the first,
   never after the last. Jitter is explicitly out of scope (a follow-on if ever
   needed) to avoid the bikeshed.

6. **Ergonomic factory.** Alongside the class, export a lowercase
   `retry(node, opts)` factory returning `new Retry({ node, ...opts })`, matching the
   `nodeTool` / `delegateTo` / `slot` factory convention in the barrel. Intended call
   site: `retry(myNode, { maxAttempts: 3, shouldRetry })`.

7. **Barrel export.** Add the `Retry` class, `retry` factory, and the
   `RetrySpec` / `RetryResult` / `RetryFailure` / `RetryPredicate` / `RetryBackoff`
   types to `workflows/index.ts` (already re-exported wholesale by runtime
   `index.ts:10`). No `runtime/index.ts` change needed.

### Interfaces (signatures only — not implementation)

```ts
// packages/agent-runtime/src/workflows/retry.ts

/** A single failed attempt, as seen by the retry predicate. */
export interface RetryFailure<TOut> {
  /** Error for this attempt: a failed NodeResult's `error`, or a normalized throw. */
  readonly error: Error;
  /** Present when the node RETURNED `{succeeded:false}`; absent when it THREW. */
  readonly result?: NodeResult<TOut>;
  /** 1-based number of the attempt that just failed. */
  readonly attempt: number;
}

/** Decide whether to retry after a failure. Default: always retry until maxAttempts. */
export type RetryPredicate<TOut> = (failure: RetryFailure<TOut>) => boolean;

/** Delay policy between attempts. No jitter (out of scope). */
export type RetryBackoff =
  | { readonly kind: "fixed"; readonly delayMs: number }
  | {
      readonly kind: "exponential";
      readonly delayMs: number;
      readonly factor?: number;      // default 2
      readonly maxDelayMs?: number;  // default unbounded
    };

export interface RetrySpec<TIn, TOut> {
  readonly name?: string;
  /** The node to run and, on failure, re-run. Types are preserved end-to-end. */
  readonly node: Node<TIn, TOut>;
  /** REQUIRED positive-integer cap on TOTAL attempts (not extra retries). */
  readonly maxAttempts: number;
  /** Gate retries. Default `() => true`. */
  readonly shouldRetry?: RetryPredicate<TOut>;
  /** Optional delay between attempts. Default: none. */
  readonly backoff?: RetryBackoff;
}

export type RetryExitReason = "succeeded" | "predicate_declined" | "attempts_exhausted";

export interface RetryResult<TOut> extends NodeResult<TOut> {
  /** Attempts actually made (1..maxAttempts). */
  readonly attempts: number;
  readonly exitReason: RetryExitReason;
}

export class Retry<TIn, TOut> implements Node<TIn, TOut> {
  readonly name?: string;
  constructor(spec: RetrySpec<TIn, TOut>);   // throws on non-positive-integer maxAttempts
  run(input: TIn, ctx: NodeRunContext): Promise<RetryResult<TOut>>;
}

/** Ergonomic factory: `retry(node, { maxAttempts: 3 })`. */
export function retry<TIn, TOut>(
  node: Node<TIn, TOut>,
  opts: Omit<RetrySpec<TIn, TOut>, "node">,
): Retry<TIn, TOut>;
```

## Tests

`workflows/__tests__/retry.test.ts` (vitest, mirroring `loop.test.ts` /
`accumulate.test.ts` conventions — hand-written fake `Node`s with a call counter and
canned `NodeResult`s; a stub `NodeRunContext` `{ runner }` with a fake runner; **no
live LLM**):

1. **Success on first attempt.** Node succeeds immediately → runs exactly once,
   `attempts === 1`, `exitReason === "succeeded"`, output + tokens pass through.
2. **Retry then succeed (the `structured-retry.ts` use case).** A node returning
   `{ succeeded:false, error: Error("No object generated"), totalInputTokens: 5,
   totalOutputTokens: 7 }` on attempt 1 and a success `{…, 3, 4 }` on attempt 2, with
   `maxAttempts: 3`. Assert: 2 calls, `exitReason: "succeeded"`, returned
   `totalInputTokens === 8` and `totalOutputTokens === 11` (**accumulated across the
   failed attempt** — the core invariant), output is attempt 2's.
3. **Budget exhausted → last failure returned, not thrown.** Node always fails with
   distinct per-attempt errors; `maxAttempts: 3`. Assert 3 calls, `succeeded: false`,
   `exitReason: "attempts_exhausted"`, `error` is the **last** attempt's, and
   `totalInputTokens/OutputTokens` are the sum over all 3 attempts. The `run()`
   promise **resolves** (does not reject).
4. **Thrown error is caught and retried.** A node whose `run()` **rejects** on
   attempt 1 (`throw new Error("boom")`) and returns success on attempt 2. Assert the
   throw did not escape (`run()` resolves), 2 calls, `exitReason: "succeeded"`, and
   the attempt-1 failure surfaced to the predicate with `result === undefined`
   (capture via a spy predicate).
5. **Predicate declines.** `shouldRetry: f => f.error.message === "retryable"`; node
   fails once with a `"fatal"` error. Assert 1 call, `succeeded: false`,
   `exitReason: "predicate_declined"`, no second attempt.
6. **Predicate sees the failure shape.** Spy predicate records each `RetryFailure`;
   assert `attempt` increments `1,2,…` and `result` is present for a failed-NodeResult
   attempt but `undefined` for a thrown attempt.
7. **`maxAttempts` validation.** `new Retry({ node, maxAttempts: 0 })` and
   `{ …, maxAttempts: 2.5 }` throw in the constructor (mirrors `loop.test.ts` guard
   test).
8. **Backoff.** Unit-test the delay policy with vitest **fake timers**: `exponential`
   `{ delayMs: 10, factor: 2 }` over a 3-attempt failure produces waits of `10` then
   `20`; `maxDelayMs: 15` caps the second wait at `15`. Assert no delay is awaited
   after the final attempt. (Isolate the pure `computeDelay` where practical so the
   timing assertions don't depend on wall clock.)
9. **Nested `AgentStep` reaches the real runner.** `retry(new AgentStep({ agent,
   prompt }), { maxAttempts: 2 })` run with a fake `ctx.runner` whose first `run()`
   throws / returns a failed result and second succeeds — proves `childCtx.runner`
   is threaded so the inner leaf still calls the injected runner across attempts.
10. **Hooks fire per attempt.** A `PatternHooks` spy records `onPatternStart` once
    and `onIterationStart`/`onIterationComplete` once per attempt.

## Conventions honored

- **Additive, layer-legal** — one new file in runtime layer 9 (`workflows/`); imports
  only `node.js`, `base.js` (`PatternHooks`), and `slot.js` (`createScratchpad`) —
  all same-layer/lower. `Node` untouched (§5 non-goal). No core import.
- **Immutability** — the returned `RetryResult` is `Object.freeze()`d, matching
  `LoopResult` (`loop.ts`).
- **Spec-object combinator shape** — class + frozen `RetrySpec`, exactly like `Loop`
  and `Accumulate`; the `.then()` builder is reserved for multi-node pipelines and is
  not appropriate for a single-node wrapper.
- **Barrel exports** — surfaced through `workflows/index.ts` → runtime `index.ts`.
- **zod** — none needed; `RetrySpec` is a structural options object like `LoopSpec`
  (no runtime data-model validation beyond the `maxAttempts` guard), consistent with
  the sibling combinators, none of which zod-validate their spec.

## Decisions (resolved at Gate 1)

1. **Throw and failed-NodeResult unified.** `Retry` `try/catch`es each attempt and
   feeds both to one predicate; a throw yields `result: undefined` and `0/0` tokens.
   It **never re-throws** — exhaustion resolves to a failed `NodeResult`, matching the
   consumer and the `Loop` "return last, branch on exitReason" contract.
2. **`maxAttempts` counts total attempts, not extra retries.** `maxAttempts: 1` = no
   retry. This matches `structured-retry.ts`'s `attempts` parameter (`for attempt =
   1..attempts`), so the consumer's call sites port with the same number.
3. **Backoff is a 2-member union, no jitter.** `fixed` / `exponential` only; jitter
   and custom delay functions are explicit follow-ons, deferred to avoid bikeshed
   (per brief).
4. **Class + `retry()` factory, not a `.then()` builder.** Single-node wrapper →
   `Loop`/`Accumulate` shape, with a lowercase factory for ergonomics.

## Open questions (for Gate 1 reviewer)

- **A — normalizeError on non-Error throws.** A node could `throw "string"` or reject
  with a non-Error. Plan: wrap non-`Error` throws as `new Error(String(thrown))` so
  `RetryFailure.error` is always a real `Error` (consistent with `error as Error`
  casts elsewhere, but stricter). Acceptable, or preserve the raw value on a separate
  field? Recommendation: normalize; don't widen the type.
- **B — should `retry` also expose `attempts`/`exitReason` when nested?** As a
  `Node<TIn,TOut>` it returns the richer `RetryResult`, but a parent composite reading
  it as `NodeResult` sees only the base fields (same as `LoopResult` today). No action
  proposed — flagging for symmetry confirmation.
- **C — backoff in tests via fake timers.** Test 8 uses vitest fake timers; if the
  team prefers zero timer coupling, `computeDelay` can be exported and unit-tested
  purely, with the sleep seam left untested. Recommendation: export `computeDelay`,
  keep one fake-timer integration test.
