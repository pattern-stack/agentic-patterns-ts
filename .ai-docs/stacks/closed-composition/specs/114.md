# Spec — `pipeline2`: an `asAgent`-promoted pipeline you can chat with via `ap`

## Goal

Ship the **dogfood example** that proves the closed-composition stack from a
consumer's seat: a `Sequential` pipeline of `FunctionStep`s + one `AgentStep`,
with a dependency injected via `depKey`/`provideDeps` and a flaky step wrapped in
`retry()`, **promoted to an agent via `asAgent()`** — so `ap playground examples`
discovers it, lists it, and lets you chat with it exactly like a hand-written LLM
agent. Nested step/agent events show up in the playground (the #102 propagation).

This is **teaching material, not library code**. Optimize the file for a reader
who has never seen the primitives: linear top-to-bottom, one concept per section,
comments that say *which* primitive each block demonstrates and *why*. Kitchen-sink
is an explicit anti-goal — we deliberately exercise six primitives and cut the
rest (see [§ Deliberately out of scope](#deliberately-out-of-scope)).

## Scope

- **Examples + docs only.** New files under `examples/agents/pipeline2/`. A short
  `README.md`.
- **No package source edits.** Every primitive this example needs already ships
  on `origin/main` (verified below). If the example seems to *need* a source
  change, that is a finding to surface — not a change to make here.
- **`bun run check` stays green** (see [§ How this interacts with `check`](#how-this-interacts-with-bun-run-check)).

## Ground truth — what actually ships on `origin/main` (verified)

Every symbol below was read on `origin/main`; the example imports **only**
published entry points (`@agentic-patterns/core`, `@agentic-patterns/runtime`).

| Primitive | Exact export (from `@agentic-patterns/runtime`) | Signature the example uses |
|---|---|---|
| Pipeline | `Sequential` (`SequentialBuilder`) | `Sequential.start(a).then(b).then(c).build("pipeline2") → Node<TIn,TCur>` — `.then()` type-checks `step[i].TOut === step[i+1].TIn` |
| Deterministic leaf | `FunctionStep` | `new FunctionStep<TIn,TOut>({ name, fn: (input, scratchpad, ctx) => TOut \| Promise<TOut> })` — always catches, returns `{succeeded:false,error}`; tokens 0 |
| LLM leaf | `AgentStep` | `new AgentStep<TIn,TOut>({ name, agent, prompt: (input, scratchpadReader) => string, output?, model?, maxIterations? })` — omit `output` (or pass `z.string()`) for the text path |
| DI channel | `depKey`, `provideDeps` | `const k = depKey<T>("name")`; `provideDeps().set(k, v).build() → DepRegistry`; read at a leaf via `ctx.deps?.get(k)` |
| Retry | `retry` | `retry(node, { maxAttempts, backoff?, shouldRetry? }) → Node<TIn,TOut>` — never re-throws; returns first success or last failure |
| Run-scoped state | `slot`, `ScratchpadAccess` | `const s = slot<T>({ key, scope:"run", init:()=>… })`; `scratchpad.get(s)` / `.update(s, fn)` |
| Promotion | `asAgent`, `PromotedAgent` | `asAgent(node, { role, deps?, coerceIn?, renderOut?, model? }) → PromotedAgent` — `coerceIn` is **optional when `TIn extends string`** |

Discovery + launch path (verified in `packages/agent-cli`):

- `ap playground examples` → `cli.ts` treats the positional as the agents root
  (`discoveryRoot = <repo>/examples`) and globs
  `["**/agent.{ts,js,mjs}", "**/*.agent.{ts,js,mjs}"]`. So
  `examples/agents/pipeline2/agent.ts` is matched.
- `discover.ts` accepts a `PromotedAgent` because `isAgentLikeShape()` recognizes
  the `AgentLike` surface (`role.name` + `getModel` + `getSystemPrompt` +
  `renderInitialPrompt`) — a `PromotedAgent` has exactly these. Identity: rel path
  `agents/pipeline2/agent.ts` → `agents` is top-level → **no domain** → id
  `pipeline2`, name `Pipeline2` (from the folder).
- `playground.ts` attaches the runner per-registration:
  `runner: isPromotedAgent(reg.agent) ? new NodeBackedRunner(llmRunner) : llmRunner`.
  So the promoted pipeline is **executed as a node graph**, and the ambient LLM
  runner (`llmRunner`) becomes the `ctx.runner` any nested `AgentStep` calls.
  **This wiring already exists — the example only has to be shaped like a
  `PromotedAgent`; it changes nothing in the CLI.**

## Key finding — "runs without live API keys" vs how `ap playground` picks a runner (read before coding)

This is the subtle reconciliation the issue's acceptance criteria demands.

`playground.ts` builds its runner via `createRunner({ tier })` **without**
`fallbackToMock`. `createRunner`'s keyless priority is: provider env vars → the
`claude` CLI on `PATH` (`ClaudeCodeAPIRunner`, **no API key needed**) → otherwise
**throw**. So:

- On a normal dev box (this is a Claude Code repo — the `claude` CLI is present),
  `ap playground` boots keyless and attaches `ClaudeCodeAPIRunner`. No API key.
- On a bare box with neither a provider key nor the CLI, `ap playground` throws at
  startup — **a property of the CLI, not of this example.** No example can make
  `ap playground` boot when it can't construct any runner.

The example therefore cannot inject its own fake runner through `ap playground`
(the CLI owns runner selection). The design that honors *"runs without live API
keys by default"* is a **clearly-gated live mode** (the second option the
acceptance criteria explicitly allows):

- **Default mode** (`AP_EXAMPLE_LIVE` unset): the curate step is a **deterministic
  `FunctionStep`**. A chat message flows `fetch → curate → respond` and renders a
  real answer **invoking no model at all** — the attached `NodeBackedRunner` never
  calls its inner LLM runner. No key, no model call, fully reproducible.
- **Live mode** (`AP_EXAMPLE_LIVE=1`): the curate step is a real **`AgentStep`**
  that calls the ambient runner (the LLM). This is the one place a model is hit.

Net: default `ap playground examples` chat with `pipeline2` produces a
deterministic response with no API key (given the CLI can boot at all); live mode
exercises the `AgentStep`. See [§ Open questions](#open-questions) Q1 — the
tension is that the `AgentStep` is only in the graph in live mode.

## Approach — the pipeline, top to bottom

A tiny self-contained **"tip curator"**: the chat message is a *topic*; the
pipeline looks up matching tips from an in-memory catalog, curates them into a
short digest, and formats a reply. No network, no external services, no clock,
no randomness (all of which are unavailable/forbidden and would make a teaching
example flaky-for-real).

```
message:string
  │  coerceIn = identity (TIn = string, so no coercer needed)
  ▼
┌─ fetchTips ─────────────────────────────────────────────┐
│ retry( FunctionStep<string, Tip[]>, { maxAttempts: 2 } ) │  ← retry() + depKey + slot
│   reads catalogKey dep; simulates a cold-cache miss on   │
│   attempt 1 via a run-scoped slot counter, succeeds on 2 │
└──────────────────────────────────────────────────────────┘
  ▼ Tip[]
┌─ curate ────────────────────────────────────────────────┐
│ LIVE ? AgentStep<Tip[], string>   ← the one LLM leaf     │
│      : FunctionStep<Tip[], string> (deterministic top-3) │
└──────────────────────────────────────────────────────────┘
  ▼ string (digest)
┌─ respond ── FunctionStep<string, string> ───────────────┐
│ wraps the digest in a friendly, human-readable reply     │
└──────────────────────────────────────────────────────────┘
  ▼ string
Sequential.build("pipeline2")  →  asAgent(pipeline, { role, deps })  →  default export
```

### Why each primitive appears (and why it's the smallest honest demo)

- **`Sequential` + `.then()`** — the composition spine; the typed seams
  (`Tip[] → string → string`) are the teachable moment vs legacy `outputKey`
  string-threading.
- **`FunctionStep`** (×2: fetch, respond) — deterministic glue, the "no LLM"
  leaf. `respond` shows the trivial case; `fetch` shows a leaf that reads
  `ctx.deps` and `scratchpad`.
- **`AgentStep`** (×1: curate, live-gated) — the LLM leaf, text path (no `output`
  schema → no `runStructured` dependency, keeps live mode simple).
- **`depKey`/`provideDeps`** — `catalogKey` injects the in-memory catalog at
  promotion time (`asAgent({ deps })` → `NodeBackedRunner` sets `ctx.deps`), read
  at the fetch leaf via `ctx.deps?.get(catalogKey)` — **no closures**, the
  canonical DI lesson.
- **`retry()`** — wraps the flaky fetch; `maxAttempts: 2` with the slot counter
  makes exactly one visible retry per turn.
- **`slot`/scratchpad** — a `run`-scoped counter gives the fetch step
  *deterministic* flakiness that **resets each chat turn** (a fresh scratchpad is
  built per `NodeBackedRunner.run`), so retry is demonstrated reproducibly without
  cross-turn state bleed. (This is the judicious 6th primitive; see Q2.)

## File-level plan

### Create: `examples/agents/pipeline2/agent.ts`

The whole example in one linear file. Structure (in reading order):

1. **Imports** — from `@agentic-patterns/core` (only what the curate `AgentStep`'s
   agent needs, live mode) and `@agentic-patterns/runtime` (`Sequential`,
   `FunctionStep`, `AgentStep`, `depKey`, `provideDeps`, `retry`, `slot`,
   `asAgent`). Package names, not workspace paths — matches `examples/live-demo.ts`.
2. **Domain types + catalog** — `interface Tip { id; topic; text }`,
   `interface Catalog { query(topic: string): Tip[] }`, and a `const CATALOG:
   Catalog` over a small frozen array (~6 tips across 2–3 topics). Pure data.
3. **DI key** — `const catalogKey = depKey<Catalog>("catalog")`.
4. **Scratchpad slot** — `const attemptSlot = slot<number>({ key:
   "pipeline2.fetchAttempt", scope: "run", init: () => 0 })`.
5. **`fetchTips`** — `new FunctionStep<string, Tip[]>({ name: "fetch", fn: (topic,
   scratchpad, ctx) => { scratchpad.update(attemptSlot, n => n + 1); if
   (scratchpad.get(attemptSlot) === 1) throw new Error("catalog cold — transient");
   const catalog = ctx.deps?.get(catalogKey); if (!catalog) throw new Error("catalog
   dep not provided"); return catalog.query(topic); } })`. Wrap:
   `const fetchWithRetry = retry(fetchTips, { maxAttempts: 2 })`.
   *(Note the leaf reads deps AND scratchpad AND demonstrates the flake all at once.)*
6. **`curate`** — `const LIVE = process.env.AP_EXAMPLE_LIVE === "1";` then a
   branch producing a `Node<Tip[], string>`:
   - live: `new AgentStep<Tip[], string>({ name: "curate", agent: curatorAgent,
     prompt: (tips) => \`Pick the 3 best tips and write a one-line digest:\n${tips
     .map(t => "- " + t.text).join("\n")}\` })` (text path, no `output` schema).
   - default: `new FunctionStep<Tip[], string>({ name: "curate", fn: (tips) =>
     tips.slice(0, 3).map(t => "• " + t.text).join("\n") })`.
   `curatorAgent` (live only): a **compact** role-only agent built with
   `AgentBuilder`/`RoleBuilder` (mirrors `examples/live-demo.ts` idiom) — build it
   inside the live branch so default mode constructs nothing. See Q3 for the
   agent-vs-minimal-`AgentLike` decision.
7. **`respond`** — `new FunctionStep<string, string>({ name: "respond", fn:
   (digest) => \`Here are some tips:\n${digest}\` })`.
8. **Assemble** — `const pipeline = Sequential.start(fetchWithRetry).then(curate)
   .then(respond).build("pipeline2");`
9. **Promote + export** — `const deps = provideDeps().set(catalogKey, CATALOG)
   .build();` then `export default asAgent(pipeline, { role: { name: "Pipeline2",
   description: "A promoted Sequential pipeline: fetch → curate → respond." },
   deps });`. `TIn = string` ⇒ **no `coerceIn`**; default `renderOut` (string
   passthrough) is correct.

## Interfaces (signatures only — not code)

```ts
interface Tip { readonly id: string; readonly topic: string; readonly text: string }
interface Catalog { query(topic: string): Tip[] }

const catalogKey: DepKey<Catalog>;                 // depKey<Catalog>("catalog")
const attemptSlot: Slot<number>;                   // slot({ key, scope:"run", init:()=>0 })

const fetchTips: Node<string, Tip[]>;              // FunctionStep, reads deps+scratchpad, flaky
const fetchWithRetry: Node<string, Tip[]>;         // retry(fetchTips, { maxAttempts: 2 })
const curate: Node<Tip[], string>;                 // AgentStep (live) | FunctionStep (default)
const respond: Node<string, string>;               // FunctionStep

const pipeline: Node<string, string>;              // Sequential.start(...).then(...).build("pipeline2")

export default: PromotedAgent<string, string>;     // asAgent(pipeline, { role, deps })
```

  `package.json`/`tsconfig` ⇒ **not typechecked**. (Write it type-correct anyway —
  it's teaching material — but a type slip won't fail the gate.)
- **`test`** = `--filter='*' test` (per-package vitest). `examples/` untouched.
- **`lint`** = **`biome check .`** — covers the whole tree; `examples/` is **not**
  in `biome.json`'s ignore list. **This is the one gate the new files must pass.**
  ⇒ double quotes, semicolons, 2-space indent, no unused imports, and
  `noExplicitAny` is `warn` (won't fail, but avoid `any`). Prefer `import type`
  for type-only imports.

## Open questions (for Gate 1)

- **Q1 — AgentStep only present in live mode.** The acceptance line "mixing
  FunctionSteps and at least one AgentStep" is satisfied by the *code* (live mode
  wires a real `AgentStep`), but **default keyless mode has no AgentStep in the
  graph** (deterministic curate). *Recommended:* keep the live gate — it's the
  honest way to satisfy "runs without keys by default" and makes the default
  reproducible. *Alternative:* always include the `AgentStep`; then default chat
  hits the model, requires the `claude` CLI to be present, and is nondeterministic
  (worse teaching material). **Recommend the live-gated design.**
- **Q2 — flaky-step state: scratchpad vs dep.** *Recommended:* a `run`-scoped
  `slot` counter (resets per turn → one clean retry every turn; adds the `slot`
  primitive as a judicious 6th). *Alternative:* a mutable counter held in a dep
  (keeps to the issue's 5-primitive set, but state **bleeds across chat turns** —
  only the first message ever retries). **Recommend the slot.**
- **Q3 — curate agent construction (live mode).** *Recommended:* a compact
  `AgentBuilder`/`RoleBuilder` agent (idiomatic, matches `live-demo.ts`, ~15
  lines). *Alternative:* a minimal inline `AgentLike` literal (leaner, but less
  representative of how consumers build agents). Either satisfies `AgentStep`.
  **Recommend the compact real agent.**
- **Q4 — example theme.** "Tip curator over an in-memory catalog" is a
  placeholder chosen for zero dependencies and self-evidence. If there's a
  canonical demo domain for this repo (the math agent in `live-demo.ts`?), say so
  and I'll align.

## Risks

- **Boot-without-runner:** on a machine with neither a provider key nor the
  `claude` CLI, `ap playground` throws before listing agents — orthogonal to this
  example, but call it out in the README so the "keyless" claim isn't mis-read.
- **Discovery import executes top-level code:** `agent.ts` must have **no
  side effects at import** beyond building the frozen pipeline (no network, no
  `console`, no `process.exit`). The design keeps top level pure.
- **`biome` is the real gate:** the single way this PR can redden `check`. Run
  `biome check .` locally before pushing.
