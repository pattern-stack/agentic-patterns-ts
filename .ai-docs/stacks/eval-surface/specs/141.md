# Spec — LLM-judge scorer: set-membership + 5-axis rubric (#141, E6)

## Goal

Promote v1 `grade.ts` (`~/Projects/retrieval-agent/packages/benchmarks/agent-eval/grade.ts`,
read at spec time — accessible) as two built-in async `Scorer`s under
`agent-runtime/src/eval/scorers/`:

1. **`set-membership.ts`** — deterministic, no model. Cited-id precision/recall/F1
   vs expected ids; pass = recall ≥ 0.6 ∧ precision ≥ 0.4 (config-overridable).
   **Fixes the v1 prefix-vs-UUID citation-match bug on port** (see § The prefix
   bug, below) with a regression test.
2. **`judge.ts`** — 5-axis rubric (accuracy / completeness / grounding /
   hazard-avoidance / calibration, 0–5 each + boolean pass) via an **injected
   runner** — "just a scorer that calls a runner" (doc §11), no vendor
   hardcoding. Config-driven thresholds, ADK-style `score ≥ threshold`.

Judge axes land in `scores_json` beside mechanical metrics with **no schema
change** (verified below). CLI: `ap eval --judge` gates on judge thresholds;
without `--judge`, behavior is byte-identical.

## Approach

### Verified against the branch tip (2026-07-04, `dug/141-eval-judge` @ `b0b046c`, forked from `origin/dug/140-capture-session`)

- **Scorer contract** (`eval/scorer.ts:22-27`): `Scorer<TIn,TOut,TExpected>` is
  `(args: {input, output, expected?, case}) => Score | Score[] | Promise<…>` —
  already async, already allows `Score[]`. **The args carry no runner** —
  `runEval` invokes scorers with exactly `{input, output, expected, case}`
  (`run-eval.ts:263-269`). This forces the injection-seam decision below.
- **Score shape** (`eval/types.ts:58-64`): `{name, value: number|null, passed?,
  detail?, error?}` — `value: null` + `error` is the ERRORED convention (Gate-1
  binding refinement, types.ts module doc): excluded from `scoreMeans`, counted
  in `summary.scoreErrors`. `detail` is a free `Record<string, unknown>` — room
  for P/R forensics and raw axes with no schema change.
- **Throwing scorers** are caught by `runScorers` (`run-eval.ts:117-130`) and
  recorded ERRORED under `scorer.name || "scorer-<i>"` — factory-returned
  closures are anonymous, so a throwing judge would lose its name. This informs
  the never-throw failure contract below.
- **Agent-target output is a string**: `resolveEvalTarget` wraps a bare agent in
  `AgentStep<string,string>` (`eval/target.ts:83-95`) — `output` for the CLI's
  agent targets is the final response text. Node targets may have arbitrary
  `TOut`. This informs the cited-id extraction default.
- **`RunnerProtocol`** (`runner/types.ts:156-186`): only `run(agent, message,
  options?) → Promise<RunResult>` is required; `runStructured` and `stream` are
  optional. `RunResult.response` is the final text (`runner/types.ts:41-54`).
  `run` needs an `AgentLike` (`role.name`, `getModel`, `getTools`,
  `getSystemPrompt`, `renderInitialPrompt` — `runner/types.ts:26-32`), so the
  judge ships a minimal inline judge-agent.
- **CLI runner construction** (`commands/eval.ts:219-229`): one
  `RunnerProtocol` per invocation — `opts.runner` (test seam) or
  `createRunner({eventBus: bus, tier})`. `model` provenance =
  `AGENT_MODEL ?? tier` (eval.ts:233). Resolver-backed/gateway runners honor
  `agent.getModel()` per call (`agent-runner.ts:293-297`); fixed-model runners
  don't.
- **Default scorer precedent** (`commands/eval.ts:265-267`): expected-gated —
  a case without `expected` returns `[]` (unscored, un-gated via
  `derivePass → null`) rather than auto-failing. Both new scorers follow it.
- **Gate semantics** (`commands/eval.ts:494`): gate FAIL when `errored > 0 ∨
  failed > 0 ∨ scoreErrors > 0`, where `failed` comes from
  `derivePass(r.scores)` (`storage/eval-store.ts:536-546` — all gating scorers
  passed → true; any failed → false; none gated → null). Adding judge scores
  with `passed` set therefore gates **automatically** — no gate-code change.
- **scores_json flow — NO schema change needed (verified)**:
  `createEvalResultRecorder` (`storage/eval-recorder.ts`) passes `r.scores`
  through structurally (`EvalScoreLike`), and `recordEvalResult` serializes
  wholesale — `JSON.stringify(r.scores)` (`storage/eval-store.ts:415`) into
  `eval_result.scores_json`. Heterogeneous entries (mechanical + judge axes +
  detail payloads) coexist by construction (doc §4).
- **Dashboard renders extra scores with zero changes (verified)**:
  `pages/eval/CaseDetail.tsx:104-112` maps `result.scores` generically through
  `ScoreRow`. No dashboard edit in this issue.
- **Runtime barrel**: `src/index.ts:19` does `export * from "./eval/index.js"` —
  new exports added to `eval/index.ts` surface automatically.
- **Reference `grade.ts`**: accessible and read. Rubric schema (grade.ts:74-84),
  judge system prompt (grade.ts:99-105), set-membership math (grade.ts:123-135),
  UUID extraction (grade.ts:60-72). The bug is concrete — see next section.

### The prefix bug (MUST-FIX on port) — exact semantics

**What v1 did wrong.** v1's extractor collects **full UUIDs** from the answer
text (`UUID_RE`, grade.ts:60: `[0-9a-f]{8}-[0-9a-f]{4}-…{12}`), but the
question bank's `expected_obs_ids` are **8-char prefixes** (verified in
`questions.jsonl`, e.g. `["b260d4f7", "d25cf47e"]`). `gradeSetMembership` then
tests `expectedSet.has(fullUuid)` (grade.ts:126-127) — a full UUID is never a
member of a set of 8-char prefixes, so **hits = 0 always** for those questions:
recall falsely 0, systematic false negatives. Flagged as a P3 port-blocker in
canvas-workstation's `eval-harness-plan.md` ("fix the 8-char-prefix-vs-full-UUID
match bug + a guard test").

**Pinned fix semantics — full-id equality, normalized:**

- An id matches iff the **whole strings are equal after normalization** —
  normalization = `trim()` + `toLowerCase()`. Nothing else.
- **No prefix matching in either direction.** Truncating both sides to 8 chars
  would trade false negatives for false positives (distinct UUIDs sharing a
  prefix); accepting prefix-of matches makes membership ambiguous. Banks must
  store full ids — that is the contract.
- **Make the mismatch visible instead of silent**: when an expected id fails to
  match but is a proper prefix of some cited id, it is reported in
  `detail.prefixSuspects` (the exact set of ids the v1 bug shape produces).
  A bank authored with prefixes now *fails loudly with a diagnosis* instead of
  silently scoring 0.

**Regression test pins both halves**: (a) full-UUID expected vs same UUID cited
in different case → hit; (b) 8-char prefix expected vs full UUID cited → NOT a
hit, `passed: false`, and the prefix appears in `detail.prefixSuspects`.

### Decisions (the three the conductor asked for + two more)

1. **(a) Cited-id extraction contract.** The scorer only sees
   `{input, output, expected, case}`, so both sides are resolver functions with
   honest defaults:
   - `extractCited` (cited side, default): render `output` to text (`string` →
     as-is; otherwise `JSON.stringify`), regex-extract **full UUIDs**
     (v1's `UUID_RE`), lowercase, dedupe via `Set`. Works for the CLI's
     agent targets (output *is* the answer text, target.ts:83-95) and for
     JSON-ish node outputs; structured outputs (e.g. an `AnswerContract` with a
     `citations` array) override the function.
   - `expectedIds` (expected side, default): `expected` itself when it is a
     `string[]`; else `expected.citedIds` when that is a `string[]`; else
     `undefined` → the scorer returns `[]` (unscored — the expected-gated
     precedent, eval.ts:265-267). One documented key (`citedIds`), no guessing
     pile; anything else overrides the function.
2. **(b) Judge-runner injection seam: construction-time closure.** Scorer args
   have no runner and `EvalRunContext.runner` is not threaded to scorers
   (run-eval.ts:263-269) — deliberately, since #103. Widening the `Scorer`
   contract to receive ctx would touch every existing scorer and the engine
   (§13: "not a rewrite of #103"). So `judgeScorer(opts)` **closes over an
   injected `RunnerProtocol`** passed at construction. CLI-side it receives the
   already-selected runner (including the `opts.runner` test seam) — zero new
   runner construction.
3. **(c) `grade.ts` accessibility**: accessible; read in full. The rubric axis
   descriptions and the grounding-vs-accuracy separation language
   (grade.ts:79, 99-105) are battle-tested and ported near-verbatim.
4. **Judge transport: `runner.run()` + robust text parse — NOT `runStructured`.**
   `runStructured` is optional on the protocol and capability-gated on
   `AgentRunner` (DESIGN §9.4); a judge that behaves differently per runner
   would make scores non-comparable across environments, and the garbage-output
   contract has to exist anyway. Single path: prompt demands JSON-only output,
   parse strips code fences / extracts the first balanced `{…}` block /
   `JSON.parse` / `JudgeVerdictSchema.safeParse`. (Upgrading capable runners to
   `runStructured` is a noted non-goal, not v1.)
5. **Judge failure contract: never throws; self-reports ERRORED.** Unparseable
   verdict, schema-invalid verdict, or a throwing runner call each produce one
   `Score {name: "judge", value: null, error: "<reason>"}` — the existing
   ERRORED convention (types.ts:53-64), NOT `passed: false`. Rationale:
   `passed: false` would conflate "judge broke" with "answer is bad" — the
   exact conflation the Gate-1 refinement exists to prevent; and self-reporting
   (rather than throwing into `runScorers`'s catch) keeps the scorer's
   configured name instead of the anonymous-closure `scorer-<i>` fallback
   (run-eval.ts:124). Gate effect: `scoreErrors > 0` → CLI gate FAIL
   (eval.ts:494) — a broken judge fails CI loudly rather than green-lighting.

### `set-membership.ts`

```ts
import type { Scorer } from "../scorer.js";
import type { EvalCase, Score } from "../types.js";

/** Args mirror of the Scorer callback param — what both resolvers receive. */
export interface SetMembershipArgs<TIn = unknown, TOut = unknown, TExpected = unknown> {
  readonly input: TIn;
  readonly output: TOut;
  readonly expected?: TExpected;
  readonly case: EvalCase<TIn, TExpected>;
}

export interface SetMembershipOptions<TIn = unknown, TOut = unknown, TExpected = unknown> {
  /** Score name. Default "set-membership". */
  name?: string;
  /** Pass requires recall ≥ this. Default 0.6 (doc §11). */
  recall?: number;
  /** Pass requires precision ≥ this. Default 0.4 (doc §11). */
  precision?: number;
  /**
   * Resolve the expected id set. Default: `expected` itself when `string[]`;
   * else `expected.citedIds` when `string[]`; else undefined.
   * Returning undefined ⇒ the case is UNSCORED (scorer returns []) — the
   * expected-gated convention (eval.ts:265-267), never an auto-fail.
   */
  expectedIds?: (args: SetMembershipArgs<TIn, TOut, TExpected>) => readonly string[] | undefined;
  /**
   * Extract cited ids from the run output. Default: stringify output
   * (string as-is, else JSON.stringify) and match full UUIDs
   * (/[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}/gi),
   * lowercased, deduped.
   */
  extractCited?: (args: SetMembershipArgs<TIn, TOut, TExpected>) => readonly string[];
}

export function setMembership<TIn = unknown, TOut = unknown, TExpected = unknown>(
  opts?: SetMembershipOptions<TIn, TOut, TExpected>,
): Scorer<TIn, TOut, TExpected>;
```

**Pinned math** (normalization = trim + lowercase on every id, both sides;
membership = whole-string equality — the fix):

```
E = normalized expected ids (deduped)   C = normalized cited ids (deduped)
hits      = |E ∩ C|
recall    = |E| > 0 ? hits/|E| : 1
precision = |C| > 0 ? hits/|C| : (|E| === 0 ? 1 : 0)
f1        = (precision+recall) > 0 ? 2PR/(P+R) : 0
passed    = recall ≥ opts.recall(0.6) ∧ precision ≥ opts.precision(0.4)
```

The `|C| = 0 ∧ |E| = 0 ⇒ precision 1` branch is a deliberate improvement over
v1 (grade.ts:128 yields precision 0 there, failing a case that correctly cited
nothing); pinned by test T-SM6.

**Emitted Score** (single — one gating verdict, mean-able `value`):

```ts
{
  name: "set-membership",
  value: f1,                       // 0..1, per Score convention (types.ts:60)
  passed,                          // recall/precision thresholds
  detail: {
    precision, recall, f1,
    expectedCount, citedCount, hits,
    missing: string[],             // E \ C
    unexpected: string[],          // C \ E
    prefixSuspects?: string[],     // missing ids that are a PROPER PREFIX of a
                                   // cited id — the v1 bug shape, surfaced.
                                   // Present only when non-empty.
  },
}
```

### `judge.ts`

```ts
import { z } from "zod";
import type { AgentLike, RunnerProtocol } from "../../runner/types.js";
import type { Scorer } from "../scorer.js";

export const JUDGE_AXES = [
  "accuracy", "completeness", "grounding", "hazardAvoidance", "calibration",
] as const;
export type JudgeAxis = (typeof JUDGE_AXES)[number];

/** Ported from grade.ts:74-84 — axis .describe() strings carried verbatim
 *  (the grounding-vs-accuracy separation language is load-bearing). */
export const JudgeVerdictSchema = z.object({
  pass: z.boolean(),
  axes: z.object({
    accuracy: z.number().min(0).max(5),
    completeness: z.number().min(0).max(5),
    grounding: z.number().min(0).max(5),
    hazardAvoidance: z.number().min(0).max(5),
    calibration: z.number().min(0).max(5),
  }),
  notes: z.string(),
});
export type JudgeVerdict = z.infer<typeof JudgeVerdictSchema>;

/** ADK-style `score ≥ threshold`, 0–5 scale (raw axis units, NOT normalized). */
export type JudgeThresholds = Partial<Record<JudgeAxis, number>> & {
  /** Threshold on the axis mean (0–5). Applied to the overall "judge" score. */
  mean?: number;
};

export interface JudgeScorerOptions {
  /** REQUIRED — the injected runner. "Just a scorer that calls a runner." */
  runner: RunnerProtocol;
  /** Judge model id, returned by the default judge agent's getModel().
   *  Honored by resolver-backed/gateway runners (agent-runner.ts:293-297);
   *  fixed-model runners judge on their own model. Default "sonnet". */
  model?: string;
  /** Full agent override (custom system prompt / model / name). Wins over
   *  `model` + `system`. Default: built-in minimal judge AgentLike. */
  agent?: AgentLike;
  /** System-prompt override for the default judge agent. */
  system?: string;
  /** Per-case user-prompt builder override. Default template below. */
  prompt?: (args: {
    input: unknown; output: unknown; expected?: unknown;
    case: { id: string; tags?: readonly string[] };
  }) => string;
  /** Score-name prefix. Default "judge" (⇒ "judge", "judge:accuracy", …). */
  name?: string;
  thresholds?: JudgeThresholds;
  /** Default true: no `expected` ⇒ return [] (unscored), the expected-gated
   *  convention. Set false to grade rubric-only (grounding/calibration still
   *  meaningful without an answer key). */
  requireExpected?: boolean;
  /** RunOptions.maxIterations for the judge call. Default 1 (tool-free single shot). */
  maxIterations?: number;
}

export function judgeScorer(opts: JudgeScorerOptions): Scorer<unknown, unknown, unknown>;
```

**Default judge agent** (frozen inline object — no core import; `AgentLike` is
a runtime-local interface, runner/types.ts:26-32):

```ts
{
  role: { name: "eval-judge" },
  getModel: () => opts.model ?? "sonnet",
  getTools: () => [],
  getSystemPrompt: () => opts.system ?? DEFAULT_JUDGE_SYSTEM,
  renderInitialPrompt: () => "",
}
```

**Emitted scores** (success path — `Score[]`, six entries):

| name | value | passed | detail |
|---|---|---|---|
| `judge` | mean(axes)/5 (0..1) | `verdict.pass` ∧ (`thresholds.mean` unset ∨ mean ≥ it) | `{axes: <raw 0-5>, notes, judgeInputTokens, judgeOutputTokens}` |
| `judge:accuracy` | raw/5 | only when `thresholds.accuracy` set: raw ≥ it | `{raw}` |
| `judge:completeness` | raw/5 | ditto | `{raw}` |
| `judge:grounding` | raw/5 | ditto | `{raw}` |
| `judge:hazard-avoidance` | raw/5 | ditto | `{raw}` |
| `judge:calibration` | raw/5 | ditto | `{raw}` |

Axis scores carry `passed` **only** when that axis has a configured threshold —
unconfigured axes stay informational (`passed` absent ⇒ they don't gate,
derivePass semantics eval-store.ts:536-546). Gating composes automatically:
any thresholded axis failing ⇒ `derivePass` false ⇒ case failed ⇒ CLI gate
FAIL. Score names use kebab (`judge:hazard-avoidance`) matching the
`exact-match` convention; the zod field stays `hazardAvoidance`.

**Failure path** (single Score, never throws): runner call threw, response had
no parseable JSON object, or JSON failed `JudgeVerdictSchema.safeParse` ⇒

```ts
[{ name: "judge", value: null, error: "judge verdict unparseable: <reason>" }]
```

**Parse pipeline** (pinned): (1) take `RunResult.response`; (2) strip a leading/
trailing markdown code fence if present (```json … ```); (3) locate the first
balanced `{…}` block (brace-depth scan — the response may pre/postfix prose);
(4) `JSON.parse`; (5) `JudgeVerdictSchema.safeParse`. Any step failing ⇒ the
ERRORED Score with a step-specific reason.

**Judge tokens**: the judge's `RunResult.inputTokens/outputTokens` are recorded
on the overall `judge` Score's `detail` — they are NOT added to
`EvalResult.inputTokens/outputTokens` (those are the target's, run-eval.ts:279-280).
Documented limitation; see Open questions.

### Judge prompt (default template, ported from grade.ts:99-118)

System (`DEFAULT_JUDGE_SYSTEM`, ~verbatim from grade.ts:100-105 with the
sales-agent framing generalized):

> You are a strict grader for an AI agent. Score the agent answer against the
> EXPECTED answer key (and the named HAZARD when present). Reward correct,
> cited, well-calibrated answers; penalize fabrication, overclaiming, and
> falling into the hazard. Be exacting — a fluent answer that misses the real
> ask or hits the hazard does NOT pass. CITATION CHECK: when the answer
> attaches a quote to a claim, verify the quote actually contains/supports
> that claim. A confident claim backed by a quote that does not substantiate
> it is a GROUNDING failure (score grounding low) — even if the claim turns
> out to be true. Keep this separate from accuracy.
> Respond with ONLY a JSON object matching:
> `{"pass": boolean, "axes": {"accuracy": 0-5, "completeness": 0-5, "grounding": 0-5, "hazardAvoidance": 0-5, "calibration": 0-5}, "notes": "1-3 sentences"}`
> — no prose before or after the JSON.

User prompt (default `prompt` builder):

```
QUESTION:
<input — string as-is, else JSON.stringify>

EXPECTED (answer key):
<expected — string as-is; object: its `expected`|`answer` string field if
 present, else JSON.stringify of the whole object>

HAZARD to watch for:                     ← line emitted only when
<expected.hazard — string>                 expected is an object with a
                                           string `hazard` field
AGENT ANSWER:
<output — string as-is, else JSON.stringify;
 empty/whitespace ⇒ "(empty — the agent produced no answer)">

Score each axis 0-5 and decide pass/fail. JSON only.
```

Empty-answer short-circuit (grade.ts:148-150 precedent): when the rendered
answer is empty, skip the runner call entirely and return the six scores with
all axes 0, `pass: false`, `notes: "no answer produced (empty output)"` —
deterministic, saves a judge call.

### CLI wiring (`--judge`)

`cli.ts` — options map additions + USAGE:

```
--judge                         (eval) add answer-quality graders: the
                                deterministic set-membership scorer + the
                                LLM judge (5-axis rubric) on the same runner
--judge-model <id>              (eval) judge model id (default: AGENT_MODEL
                                or the AGENT_TIER tier); honored when the
                                runner resolves per-agent models
--judge-thresholds <list>       (eval) comma list axis=n (0-5), axes:
                                accuracy|completeness|grounding|
                                hazard-avoidance|calibration|mean
                                e.g. accuracy=3,grounding=3,mean=3.5
```

`commands/eval.ts`:

- `EvalCommandOptions` += `judge?: boolean; judgeModel?: string;
  judgeThresholds?: string;`
- **Step 1 (flag validation)**: parse `judgeThresholds` early — split on `,`,
  each entry `axis=n` with axis ∈ {five kebab axis names, `mean`} and
  n ∈ [0,5] numeric; anything else ⇒ `errExit2` (exit 2, before any
  file/store/runner work — the established validation order, eval.ts:81-84).
  `--judge-model`/`--judge-thresholds` without `--judge` ⇒ usage error
  (exit 2) — silent no-ops hide typos.
- **After runner construction (Step 7)**, only when `opts.judge`:

  ```ts
  scorers = [defaultScorer, setMembership(), judgeScorer({
    runner,                                  // the SAME selected runner (incl. test seam)
    model: opts.judgeModel ?? model,         // model = AGENT_MODEL ?? tier (eval.ts:233)
    thresholds,                              // parsed above
  })];
  ```

  `setMembership()` rides along with `--judge` (v1's `grade.ts` shipped both
  graders as one grading pass); it is expected-gated, so cases without
  resolvable ids get no set-membership score.
- **Banner**: add a `judge` line when active
  (`judge    on — model <m>  thresholds <parsed|defaults>`), following the
  existing banner shape (eval.ts:395-413).
- **Without `--judge`**: the `scorers` array construction is untouched
  (`[defaultScorer]`), no judge parsing side effects, no extra output lines —
  byte-identical by construction (acceptance #3), locked by test T-CLI2.

Judge observability note: the CLI judge reuses the runner created with the
shared `eventBus` (eval.ts:226), so judge calls emit onto the same bus under
their own generated traceIds — they appear as separate traces in events.db.
Accepted (arguably useful); suppressing them is a non-goal.
