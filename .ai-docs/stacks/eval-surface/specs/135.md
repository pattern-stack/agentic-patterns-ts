# Spec — `ap eval`: run a suite from the CLI, persisted to `EvalStore`, gate exit code (#135, E4)

## Goal

New `ap eval` command (doc §3 E4, §10): discover agents (reuse `helpers/discover.ts` —
`cli.ts` already does discovery for every command), resolve ONE target, load a case bank
(file via #134's loaders, or a stored set id via #132's `listEvalCases`), apply the
`--split` filter with the held-out guard (`--allow-test` ⇒ `{ allowTest: true }`), run
`runEval` with an **`EvalStore`-backed `onResult`** (suite row + per-case run row +
`eval_result` annotation — #132's spec'd seam verbatim), capture per-case traces through
the shared bus (#133: `ctx.eventBus` + `ctx.traceId = evalRunId` ⇒ per-case ids
`${evalRunId}:${caseId}` — the doc §5's exact formula), print a live per-case line plus
an aggregate with **per-split pass rates**, and **exit non-zero on gate failure**
(CI-friendly). No `--judge` — that flag arrives with E6 (#141).

All three upstream surfaces ship on this branch and are consumed, not rebuilt:
`EvalStore`/`derivePass`/`loadEvalStore` (#132), `loadCasesJsonl`/`loadGold`/
`filterBySplit`/`assertSplitSelectable`/`HeldOutSplitError` (#134), and
`EvalRunContext.eventBus` + `EvalResult.traceId` (#133) — every one re-verified at the
tip (below).

Additive to `agent-cli` only. No runtime/server/dashboard edits, no version bump.

### Upstream-surface mismatch (load-bearing): RunStoreExporter cannot satisfy this issue's acceptance — use #132's manual seam

The issue sketches attaching `RunStoreExporter` (§5.3 fusion) for the run rows. **At the
tip that path cannot meet the acceptance criterion "`--variant` lands on eval_run AND the
runs' metadata slot":**

- `RunStoreExporter._onMessageStart` (`exporters/run-store.ts:109-132`) calls
  `startRun({ runId, traceId, tsStart, agentName, model, systemPrompt, agentConfig })` —
  **no `metadata`**, and the exporter has no constructor knob to stamp any. Bus-created
  rows structurally cannot carry `variant`/`evalRunId`/`caseId`.
- The bus's `runId`s are unobservable from `onResult` (minted inside `AgentRunner` per
  call; `RunStore.listRuns` has no traceId filter) — `eval_result.run_id` linkage would
  require extra bus-subscription machinery.
- The fusion is runner-mediated (#133 § "honest boundaries"): `MockRunner` and
  promoted-`FunctionStep` targets emit **nothing** ⇒ zero rows — untestable in CLI tests
  and empty for non-LLM targets.

**Resolution — the manual seam, exactly as #132's spec § "The persistence seam"
prescribes** (shipped precedent: `storage/__tests__/run-store.test.ts:344-382`; #132
says the exporter path "*can* instead" be used — not must): `onResult` writes
`startRun` (with `metadata: { evalRunId, caseId, variant?, split? }` — the acceptance
criterion) + `finishRun` + `recordEvalResult`. **Trace capture is preserved
independently**: `SQLiteExporter` (not `RunStoreExporter`) attaches to the shared bus,
so per-case trace **events** land in the same file keyed by `${evalRunId}:${caseId}`,
and the manual run row carries `traceId: r.traceId` — the run↔trace join holds.

Accepted cost (documented in code): manual rows carry `toolCalls: 0`, `iterations: 0`,
`elapsedMs: 0` (unknown at the `onResult` seam). Tokens, finalAnswer, status, error,
and traceId are real. Follow-up (recorded, not done here): an additive `metadata` knob
on `RunStoreExporter` would let #136+ switch to fusion rows without schema changes.

### Step 1 — CLI surface (`cli.ts` + USAGE)

```
ap eval [<agents-dir>] --set <path|id> [--target <id>] [--variant <label>]
        [--split train|dev|test] [--allow-test] [--gold <path>] [--db <path>]
```

New `parseArgs` entries (`cli.ts:64-77`): `set`, `target`, `variant`, `split`, `gold`,
`db` (string) + `"allow-test"` (boolean) — no collisions with existing names. USAGE
gains the command + flags block. Dispatch case delegates everything else:

```ts
case "eval": {
  await runEvalCommand({
    agents, set: values.set ? String(values.set) : undefined, …,
    allowTest: Boolean(values["allow-test"]),
  });
  return;
}
```

**Exit-code taxonomy** (documented in USAGE): `0` gate pass · `1` **gate failure**
(suite ran; results bad) · `2` usage/config error (everything in the table above). CI
can distinguish "my agent regressed" from "my invocation is broken". Gate failure sets
`process.exitCode = 1` and returns (natural flush/exit); usage errors keep the repo's
`process.exit` precedent, with code 2.

### Step 2 — `commands/eval.ts`: flow (order is load-bearing)

1. **Validate flags** — required `--set`; parse `--split`; on a `test` split call
   `assertSplitSelectable(split, { allowTest })` **immediately** (#134's free-refusal
   property: before any file/store/runner work). Catch `HeldOutSplitError` → exit 2.
2. **Resolve target** per the table; `targetId = reg.id`; the eval target is `reg.agent`
   — `resolveEvalTarget` (engine) handles both full Agents (`AgentStep` bridge,
   string-in) and promoted agents (unwraps `__promotedNode`, `target.ts:70-71`). **No
   `NodeBackedRunner`** — that wrapper is for chat-style `Conversation`s; the engine
   runs the promoted node directly with `ctx.runner` as the inner runner.
3. **Load cases.** File mode: `setId = basename minus final extension` ("bank.jsonl" →
   "bank" — the stable id A/B compare groups by; collision across dirs accepted v1);
   `cases = gold ? loadGold(setPath, goldPath) : loadCasesJsonl(setPath)`; render
   `CaseBankLoadError` (structured `path/line/caseId` fields) → exit 2. Stored-set
   mode: requires the store (persistence disabled ⇒ exit 2 `--set <id> requires
   persistence`); map `EvalCaseRow` → `EvalCase` **normalizing `null` → `undefined`**
   for `expected`/`tags`/`split` (`parseJsonUnknown(null)` returns `null`,
   `eval-store.ts:635-642` — an un-normalized `expected: null` would make the default
   scorer gate an expected-less case).
4. **Split filter** — `cases = filterBySplit(cases, split, { allowTest })` when
   `--split` given. **Empty selection ⇒ exit 2** (`error: no cases in split "<s>" of
   set "<id>"`) — an empty suite exiting 0 is a false-green CI pass.
5. **Persistence** — mirror `maybeAttachPersistence` (`playground.ts:361-382`) with
   `loadEvalStore`: `AP_PERSISTENCE=0` → skip with banner; unavailable → **warn loudly
   and continue unpersisted** (run/print/gate still work; better-sqlite3 is a direct dep
   so this is the exceptional path). `ensureParentDir(dbPath)` first.
6. **Mirror the bank** (file mode + store only; §16.4's optional mirror, enabling
   #136/#137 browse): `upsertEvalSet({ id: setId, name: setId })` +
   `upsertEvalCase(setId, { caseId: c.id, input: c.input, expected: c.expected,
   tags: c.tags, split: c.split })` per **loaded** case (post-gold-overlay,
   pre-split-filter — the mirror is the whole bank; the split is run-level). Idempotent
   by construction (#132 upserts).
7. **Bus + runner** — `const bus = new AgentEventBus()`; when store present:
   `new SQLiteExporter({ store }).attach(bus)` (EvalStore IS an EventStore — trace
   events land in the same file). Runner: `opts.runner ?? (await createRunner({
   eventBus: bus, tier, verbose: false })).runner` — the playground's exact selection
   (`tier = AGENT_TIER ?? "sonnet"`); passing the SAME bus to `createRunner` and
   `ctx.eventBus` is #133's prescribed anti-rebind pattern (`run-eval.ts:50-52` note).
8. **Suite row** — `evalRunId = store.startEvalRun({ setId, targetId, variant, split,
   model, gitSha })`. Provenance is best-effort: `model = AGENT_MODEL env ?? tier`
   (`RunnerSelection` exposes `{runner, reason, source}` only — no resolved model id;
   noted limitation), `gitSha = execSync("git rev-parse HEAD")` trimmed,
   `undefined` on throw.
9. **Run** — `runEval({ target: reg.agent, cases, scorers: [defaultScorer], onResult },
   { runner, eventBus: bus, traceId: evalRunId })`. With the store absent, omit
   `traceId` (engine mints a base). Per-case ids become `${evalRunId}:${caseId}` —
   doc §5's formula, exactly what #133 built `ctx.traceId` for. `onResult` (§ Interfaces
   for the verbatim wiring): print the live per-case line, then (store only)
   `startRun`(metadata stamp) → `finishRun` → `recordEvalResult`(pass =
   `derivePass(r.scores)`).
10. **Finish** — `store.finishEvalRun(evalRunId, { status: "ok" })` on report;
    if `runEval` throws (up-front envelope validation is its only throw path),
    `finishEvalRun(..., { status: "error" })` then rethrow (main()'s catch prints,
    exits 1). `store.close()` in a `finally`.
11. **Print + gate** (Step 4).

### Step 3 — default scorer: expected-gated exact-match

The engine requires `spec.scorers`; the doc/issue name none for E4 (custom scorers are
the programmatic `runEval` seam; the judge is #141). Default — a module-private wrapper
over the shipped `exactMatch()` (`scorer.ts:120`):

```ts
const exact = exactMatch();
const defaultScorer: Scorer<unknown, unknown, unknown> = (args) =>
  args.expected === undefined ? [] : exact(args);
```

A case **with** `expected` is gated by deep-equality (score name `"exact-match"`,
`passed` set); a case **without** stays un-scored (`[]` ⇒ `derivePass` → `null` ⇒
un-gated) rather than auto-failing (`exactMatch`'s own doc warns `deepEqual(output,
undefined)` is false — an ungated smoke case must not read as a regression). Node
errors still gate regardless (below). No custom-scorer flag in v1 (non-goal).

### Step 4 — gate semantics + printout

`EvalReport` carries no gate surface (verified `types.ts:110-125` — per-scorer
`passRate`/`scoreMeans` + `succeeded/errored/scoreErrors`); the CLI defines the gate,
built on the SAME `derivePass` that stamps `eval_result.pass` — printout and stored
rows cannot disagree:

> **FAIL** iff `summary.errored > 0` (a case's node execution failed) **or** any
> result has `derivePass(r.scores) === false` (a gating scorer failed) **or**
> `summary.scoreErrors > 0` (a scorer threw — "couldn't score" must not pass CI
> silently; revisit when #141's judge makes transient scorer errors likelier).

Pass ⇒ exit 0. Fail ⇒ print the reason breakdown, `process.exitCode = 1`.

Per-split rows are computed **from `report.results`** (group by `r.case.split ??
"(untagged)"`; per group: cases, gated pass `x/y` via `derivePass`, errors, rate) —
NOT from `store.splitAggregates()`, which aggregates across historical runs matching a
filter, not this one invocation (and must work store-less). Printout sketch (live
per-case lines stream from `onResult` as the suite runs; ANSI helpers per `run.ts`):

```
  eval     bank → dealbrain/curator   variant=baseline  split=dev
  storage  ~/.local/state/ap/events.db (eval run Z8kQ…)
  runner   env-anthropic — using anthropic (env ANTHROPIC_API_KEY)

  ✓ case-01  exact-match 1.0                       812↓ 96↑
  ✗ case-02  exact-match 0.0                       790↓ 88↑
  ⚠ case-03  node error: boom

  cases 3 · passed 1 · failed 1 · errored 1 · score-errors 0
  exact-match   mean 0.50   pass 1/2

  split        cases  pass   errors  rate
  dev          2      1/2    0       50%
  (untagged)   1      0/0    1       —

  gate FAIL (1 scorer-failed, 1 errored) → exit 1
```

The `onResult` wiring — #132's seam, verbatim shape (`specs/132.md` § "The persistence
seam"; precedent `run-store.test.ts:344-382`):

```ts
onResult: (r) => {
  printCaseLine(r);                       // live progress — before persistence
  if (!store) return;
  const runId = store.startRun({
    agentName: targetId,
    model,                                // best-effort (AGENT_MODEL ?? tier)
    ...(r.traceId ? { traceId: r.traceId } : {}),   // run ↔ trace-events join
    metadata: {                           // the acceptance criterion: variant on the run row
      evalRunId,
      caseId: r.case.id,
      ...(variant !== undefined ? { variant } : {}),
      ...((r.case.split ?? split) !== undefined ? { split: r.case.split ?? split } : {}),
    },
  });
  store.finishRun(runId, {
    finalAnswer: r.output === undefined ? "" : JSON.stringify(r.output),
    toolCalls: 0,                         // unknown at this seam (see mismatch section)
    iterations: 0,
    inputTokens: r.inputTokens,
    outputTokens: r.outputTokens,
    finishReason: r.succeeded ? "stop" : "error",
    elapsedMs: 0,
    status: r.succeeded ? "ok" : "error",
    ...(r.error !== undefined ? { error: r.error } : {}),
  });
  store.recordEvalResult({
    evalRunId,
    caseId: r.case.id,
    runId,
    scores: r.scores,
    pass: derivePass(r.scores),           // the same helper the gate uses
  });
},
```

## Tests

`packages/agent-cli/src/commands/__tests__/eval.test.ts` — the `tools.test.ts` harness
(captureStdio + exit spy + `runSafely`; assert `process.exitCode` for gate outcomes,
reset it per test). Fixtures: in-memory `DiscoveredAgent`s wrapping
`asAgent(new FunctionStep(...))` (deterministic, runner-untouched — `resolveEvalTarget`
runs the promoted node directly; one step throws on input `"boom"` for the error path);
`opts.runner = new MockRunner()` everywhere (no env dependence); temp jsonl banks via
the `mkdtempSync` idiom; `--db <tmpfile>` and post-hoc reopen with
`new EvalStore({ path, Database })` for row assertions (proves the real file path e2e).
Small throwaway fixture agents are authorized.

1. **Happy path (the acceptance path).** 2-case bank, all matching → exit code unset
   (0); stdout has per-case ✓ lines + aggregate; reopened store: one `eval_run`
   (status `ok`, `setId`/`targetId`/`variant`/`split`/`model` round-tripped), one
   `eval_result` per case (`pass = 1`, scores JSON intact), one run row per case with
   `metadata.evalRunId/caseId/variant` and `trace_id === "<evalRunId>:<caseId>"`;
   `evalRunResults(evalRunId)` returns joined rows with tokens/finalAnswer from the
   runs side.
2. **Gate failure — scorer.** One case's `expected` mismatches → `process.exitCode = 1`;
   stdout shows `gate FAIL`; that case's `eval_result.pass = 0`.
3. **Gate failure — node error.** `"boom"` case → errored counted; run row
   `status: "error"` with the message; `eval_result.pass` NULL (no scores);
   `process.exitCode = 1`.
4. **--split filters.** Mixed-split bank + `--split dev` → only dev cases in results
   and rows; `eval_run.split = "dev"`.
5. **Held-out guard.** `--split test` without `--allow-test` → exit 2, stderr contains
   the verbatim `case-bank.ts:244` message + the `--allow-test` hint; with
   `--allow-test` → runs.
6. **Invalid --split.** `--split validate` → exit 2, message lists `train | dev | test`.
7. **Target resolution.** Unknown `--target` → exit 2 + `available:` list; two agents,
   no `--target` → exit 2 + list; single agent, no `--target` → runs against it.
8. **Stored-set mode.** Pre-seed the temp db (`upsertEvalSet`/`upsertEvalCase`,
   including a case with NO expected) → `--set <id>` runs from the store; the
   expected-less case is un-gated (null-normalization proven); unknown id → exit 2
   listing available set ids.
9. **Mirroring + idempotency.** File mode → `listEvalCases(setId)` equals the bank
   (split/tags/expected intact); second invocation: case count stable, second
   `eval_run` row added.
10. **--gold overlay.** Gold expected wins over inline; gate reflects gold.
11. **Empty selection.** `--split train` on a dev-only bank → exit 2 `no cases`.
12. **Missing --set / --gold misuse.** No `--set` → exit 2; `--gold` with a stored-set
    id → exit 2.
13. **Per-split printout.** Mixed bank → stdout contains per-split rows with the
    `x/y` pass column and a rate; untagged bucket rendered.
14. **Unpersisted run.** `AP_PERSISTENCE=0` (env stubbed) → warning line, suite still
    runs, gate still sets exit code, no db file created.
15. **Trace-event capture (integration).** `opts.runner` = a ~25-line lifecycle-stub
    runner (the #133 `trace-capture.test.ts` idiom: emits `message.start`/`complete`
    to `options.eventBus`) + a full-Agent fixture → reopened store: `events` rows exist
    with `trace_id = "<evalRunId>:<caseId>"`, proving the command's SQLiteExporter +
    shared-bus wiring end-to-end.

Run: `bun run --filter=@agentic-patterns/cli test` (+ `typecheck`, `lint`). The 38
existing CLI tests must stay green — the only shared edits are `cli.ts` (additive
flags/case) and `playground.ts`'s mechanical import swap.
