# Spec — eval read routes + `evalStore` config seam + SPA `/eval` prefix fix (#136, E5 substrate)

## Goal

The read-only server substrate for the Eval tab (doc §8, E5): a new
`packages/agent-server/src/routes/eval.ts` exposing **four GETs** —
`/eval/sets` (case banks + per-split counts), `/eval/sets/:id/cases` (browse),
`/eval/runs` (history, filterable by set/target/variant/split), `/eval/runs/:id`
(per-case results **JOINed with their `runs` rows** — tokens, trace_id, status,
final_answer — plus a computed summary) — served straight off #132's `EvalStore`
query surface, no parallel DTOs. Thread an optional **`evalStore?: EvalStore`**
through `ServerConfig` exactly like the shipped `eventStore` seam (`config.ts:95`),
with the same absent-store behavior the eventStore routes established: **routes
always mounted, 503 + hint when unconfigured** (`routes/events.ts:50-57`). Fix the
must-fix gotcha (doc §8): add `/eval` to the playground SPA fallback's
`API_PREFIXES` (`playground.ts:211`) with a regression test, and wire `ap
playground` to actually pass an `EvalStore` (swap `loadEventStore` →
`loadEvalStore` — an `EvalStore` IS an `EventStore`, so it serves both config
fields) so the routes are live end-to-end against the same db `ap eval` writes.

Write routes (`POST /eval/runs`, capture-from-session) and the SSE stream are
epic 2 — not here. No dashboard changes (#137).

### Scope note (one deliberate addition beyond the issue's key-files list)

The issue lists only `app.ts` / `config.ts` / `playground.ts:211` / new
`routes/eval.ts`. This spec **adds the 3-line playground persistence swap**
(finding 7): without it, `ap playground` never constructs an `EvalStore`, every
`/eval` route answers 503 forever, and acceptance №1 ("all four GETs serve
EvalStore data") is only true in tests — while #137 is scoped dashboard-only and
should not be reaching into the CLI. The swap is strictly widening (an
`EvalStore` is a `RunStore` is an `EventStore`; same file, same `resolveDbPath()`
discipline — so the playground reads the very db `ap eval` writes, the doc's
one-file design).

### Route design — `routes/eval.ts` (NEW)

`export function evalRoutes(evalStore: EvalStore | undefined): Hono` — the
`eventRoutes` signature shape (`events.ts:13`), minus the bus (no ingest/SSE
here). Mounted at `app.ts:39`: `app.route("/", evalRoutes(config.evalStore));`.

Every handler opens with the 503 guard (finding 2). Response bodies are the
store's row types serialized as-is — **no parallel DTOs** (the events routes
precedent: `{ events: rows }`, `events.ts:63`). Query params use the doc §8
short names. `limit` uses the `parseInt10` clamp idiom duplicated file-locally
(`events.ts:99-104` — small helpers are deliberately file-local in this repo,
per the `run-store.ts` `generateId` precedent).

| Method + path | Query params | 200 body | Errors |
|---|---|---|---|
| `GET /eval/sets` | — | `{ sets: EvalSetSummary[] }` — `listEvalSets()`; each row carries `caseCount` + `splitCounts` | 503 no store |
| `GET /eval/sets/:id/cases` | `split` (train\|dev\|test) | `{ setId, cases: EvalCaseRow[] }` — `listEvalCases(id, { split })` | 503 no store · 400 invalid `split` · 404 unknown set |
| `GET /eval/runs` | `set`, `target`, `variant`, `split`, `limit` (default 50, clamp 1–500) | `{ runs: EvalRunRow[] }` — `listEvalRuns({ setId: set, targetId: target, variant, split, limit })`, newest first | 503 no store · 400 invalid `split` |
| `GET /eval/runs/:id` | — | `{ run: EvalRunRow, results: JoinedEvalResultRow[], summary }` — `getEvalRun(id)` + `evalRunResults(id)` + handler-computed summary | 503 no store · 404 unknown run id |

Error semantics, precisely:

- **Absent store (all four):** `503 { error: "persistence not configured", hint:
  "start \`ap playground\` with AP_PERSISTENCE != 0 to enable eval queries" }` —
  the `events.ts:50-57` shape.
- **Invalid `split`:** validated with `EvalSplitSchema.safeParse` (finding 4) →
  `400 { error: 'invalid split "<s>" — expected train | dev | test' }` (the #135
  CLI message shape). Absent param ⇒ no filter.
- **Unknown set id:** `listEvalCases` returns `[]` for both empty and missing
  sets, so distinguish: `404 { error: 'eval set "<id>" not found' }` **only
  when** the id is absent from `listEvalSets()` *and* no cases matched; an
  existing-but-empty set (or an empty split slice of a real set) is
  `200 { setId, cases: [] }`.
- **Unknown run id:** `getEvalRun(id) === null` → `404 { error: 'eval run "<id>"
  not found' }`. (`compareEvalRuns`'s throw-on-unknown is not reachable — no
  compare route in this issue.)

`GET /eval/runs/:id` summary — computed in the handler from the joined rows,
using the same pass semantics as `derivePass`/`splitAggregates` (`pass` is
tri-state; `passRate` counts only gated results, `eval-store.ts:518-526`):

```json
{
  "run":     { "id": "…", "tsStart": "…", "tsEnd": "…", "setId": "bank", "targetId": "dealbrain/curator",
               "variant": "baseline", "split": "dev", "model": "sonnet", "gitSha": "…", "status": "ok" },
  "results": [ { "evalRunId": "…", "caseId": "case-01", "runId": "…",
                 "scores": [{ "name": "exact-match", "value": 1, "passed": true }], "pass": true,
                 "traceId": "<evalRunId>:case-01", "runStatus": "ok", "finalAnswer": "\"42\"",
                 "inputTokens": 812, "outputTokens": 96, "finishReason": "stop",
                 "elapsedMs": 0, "runError": null } ],
  "summary": { "cases": 3, "passed": 1, "failed": 1, "ungated": 1, "errored": 1,
               "passRate": 0.5, "inputTokens": 1602, "outputTokens": 184 }
}
```

`passed`/`failed`/`ungated` bucket `pass === true / false / null`; `errored`
counts `runStatus === "error"`; `passRate = passed / (passed + failed)`, `null`
when nothing gated; token fields are null-safe sums. The other three bodies are
direct row-type serializations:

```json
// GET /eval/sets
{ "sets": [ { "id": "bank", "name": "bank", "description": null, "createdTs": "2026-07-03 …",
              "caseCount": 12, "splitCounts": { "train": 8, "dev": 3, "": 1 } } ] }

// GET /eval/sets/bank/cases?split=dev
{ "setId": "bank", "cases": [ { "setId": "bank", "caseId": "case-01", "input": "2+2?",
                                "expected": "4", "tags": ["smoke"], "split": "dev" } ] }

// GET /eval/runs?set=bank&variant=baseline&limit=20
{ "runs": [ /* EvalRunRow[] — newest first */ ] }
```

```ts
import type { EvalStore } from "@agentic-patterns/runtime";
import { EvalSplitSchema } from "@agentic-patterns/runtime";
import { Hono } from "hono";

/**
 * Read-only eval endpoints backed by ServerConfig.evalStore.
 * 503 + hint when the store isn't configured (routes/events.ts precedent).
 * Write routes (POST runs, capture-from-session) and SSE are epic 2.
 */
export function evalRoutes(evalStore: EvalStore | undefined): Hono;

/** Handler-computed rollup for GET /eval/runs/:id — derivePass-consistent. */
interface EvalRunSummary {           // module-private; serialized in the 200 body
  cases: number;
  passed: number;                    // pass === true
  failed: number;                    // pass === false
  ungated: number;                   // pass === null
  errored: number;                   // runStatus === "error"
  passRate: number | null;           // passed / (passed + failed); null when ungated-only
  inputTokens: number;               // null-safe sums over the joined rows
  outputTokens: number;
}
```

## Tests

`packages/agent-server/src/__tests__/eval.test.ts` — the `events.test.ts`
harness: `mkApp(store: EvalStore | undefined)` mounting only `evalRoutes`;
`beforeEach` builds `new EvalStore({ path: ":memory:", Database })` and seeds
**via the store's own API**: `upsertEvalSet`/`upsertEvalCase` (mixed
train/dev/untagged splits), two `startEvalRun`/`finishEvalRun` suites (variants
"a"/"b"), and per case a real `startRun`/`finishRun` (with tokens, finalAnswer,
traceId `<evalRunId>:<caseId>`, one `status: "error"` row) +
`recordEvalResult` linking — i.e. exactly what `ap eval` writes (#135 seam).

1. **GET /eval/sets** → 200; the seeded set present with correct `caseCount` and
   per-split `splitCounts` (the acceptance's "+ per-split counts").
2. **GET /eval/sets/:id/cases** → all cases round-tripped (input/expected/tags/
   split intact); `?split=dev` narrows; `?split=bogus` → 400 with the
   `train | dev | test` message; unknown set id → 404; **existing set, empty
   split slice → 200 `cases: []`** (the empty-vs-missing distinction).
3. **GET /eval/runs** → newest first; each of `?set=`, `?target=`, `?variant=`,
   `?split=` narrows to the matching suite; combined filters intersect;
   `?limit=1` truncates; `?limit=99999` clamps without erroring (the
   `events.test.ts:112-118` clamp idiom).
4. **GET /eval/runs/:id** → 200 with `run` (all `EvalRunRow` fields
   round-tripped), `results` whose joined fields (`inputTokens`,
   `outputTokens`, `finalAnswer`, `traceId`, `runStatus`) equal what
   `finishRun`/`startRun` wrote — **proving the values come from the `runs` side
   of the JOIN** — and `summary` counts (`passed/failed/ungated/errored/
   passRate/token sums`) matching the seed arithmetic; unknown id → 404.
5. **503 sweep** — `mkApp(undefined)`: all four paths return 503 with the hint
   (the `events.test.ts:100-110` loop).
6. **Config threading** — `createServer(makeConfig({ evalStore: store }))` →
   `GET /eval/sets` 200; `createServer(makeConfig())` (no evalStore) → 503.
   Local minimal-config helper copied from `app.test.ts:143-151`.

`packages/agent-cli/src/commands/__tests__/playground.test.ts` — the regression
test for the gotcha (pure-function table over the exported `isApiPath`; the SPA
fallback consults it at `playground.ts:236-238` before the `index.html` rewrite,
so classification is the load-bearing bit):

7. **`/eval` is API**: `isApiPath` true for `/eval`, `/eval/sets`,
   `/eval/sets/bank/cases`, `/eval/runs/abc-123` — *would have failed before
   this change* (the regression assertion).
8. **Boundaries hold**: false for `/evaluate` (prefix must not match by
   substring), `/`, `/chat`, `/tokens` (SPA routes stay SPA); true for each
   pre-existing prefix root + a subpath (locks the whole allowlist against

Run: `bun run --filter=@agentic-patterns/server test` +
`--filter=@agentic-patterns/cli test` (+ `typecheck`, `lint` on both). The 63

## Non-goals (scope fences)

- **No write routes** — `POST /eval/runs` (run-from-UI) and
  `POST /eval/cases/from-session` (capture) are epic 2 (doc §8 table; issue
  body). The read-only `evalRoutes` signature deliberately takes no bus/runner.
- **No SSE** — `GET /eval/runs/:id/stream` arrives with run-from-UI (needs a
  live run to stream).
- **No compare / split-aggregate routes** — `compareEvalRuns` (`eval-store.ts:460`)
  and `splitAggregates` (`:509`) have no consumer until #137/#138 pick their
  shapes; each is one added handler on this same route group when needed.
- **No dashboard changes** — the Eval tab is #137; the deep-link caveat
  (finding 6) is #137's client-route decision, pre-existing for four other tabs.
- **No pagination beyond `limit`** — matches the events routes (offset/cursor
  paging doesn't exist anywhere in this server; don't introduce it here).
- **No auth on /eval** — the events routes' `AP_INGEST_TOKEN` guards ingest
  (POST) only; reads are unauthenticated everywhere in this server.
- **No `EvalStore` construction inside the server package** — the store is
  handed in via config (the eventStore precedent); only the CLI constructs one.
- **No package version bump** — release mechanics are cut at stack level.
