# Spec — Bifrost gateway awareness: typed guardrail violations + redaction events

## Goal

Part 2 of 2: make the runtime *aware* of Bifrost governance responses instead
of treating them as generic failures.

1. **Typed errors** — parse Bifrost's error envelope (`type`,
   `is_bifrost_error`, `status_code`, `error.message`, `extra_fields`) into a
   typed hierarchy: `virtual_key_required` (401, live-captured),
   `provider_blocked` (403, live-captured), guardrail violation (HTTP 446 —
   **provisional**, docs-derived). Never a silent generic failure for a
   Bifrost-typed error.
2. **Events** — `agent.guardrail.violation` (blocked) and
   `agent.guardrail.redaction` (masked) through the FULL #388/#389 plumbing:
   types → profiles → SSE formatter → **manifest regen** → relay allowlist →
   collector → dashboard (NAMED_EVENTS + tones + chat badge).
3. **Redaction detection** — in-band `[ENTITY_TYPE-#]` placeholder scan +
   `bifrost_metadata`/`extra_fields` capture via a `metadataExtractor`
   (the one-key seam #406 deliberately left in `buildFromGateway`). Entity
   *counts by type* only — never the raw values.
4. **Fallback attribution** — surface `extra_fields.provider` /
   `resolved_model_used` (which provider actually served a gateway response)
   on `agent.llm.end` and `RunResult`.

Hard invariants: non-gateway providers are byte-for-byte unaffected; the
GATE-CHAIN INVARIANT and all #389 approval plumbing are untouched;
de-anonymization stays out of scope (Bifrost admin logs API + RBAC).

## Verified SDK + wire facts (byte-checked, not docs-checked)

The design stands on these; each was verified against the pinned dists on the
#406 branch:

1. **Provider HTTP errors surface as `APICallError`** with `statusCode?`,
   `responseHeaders?`, **`responseBody?` (raw string)**, `data?` (parsed), and
   `isRetryable` (`@ai-sdk/provider@4.0.3` `dist/index.d.ts:672-693`).
2. **`data` LOSES the Bifrost envelope.** openai-compatible's default error
   schema is `z.object({ error: z.object({ message, type?, param?, code? }) })`
   with `$strip` semantics (`@ai-sdk/openai-compatible@3.0.14`
   `dist/index.d.ts:6-14`) — Bifrost's **top-level** `type`,
   `is_bifrost_error`, `status_code`, and `extra_fields` are stripped from
   `APICallError.data`. Classification MUST parse `responseBody` (raw JSON,
   preserved verbatim), not `data`.
3. **A custom `errorStructure` is NOT injectable.** `errorStructure` exists
   only on the internal `OpenAICompatibleChatConfig` (`d.ts:82`), NOT on
   `OpenAICompatibleProviderSettings` accepted by `createOpenAICompatible`
   (`d.ts:329-380` — no such key). Runner-side `responseBody` parsing is the
   only route; do not attempt provider-level error-schema injection.
4. **`metadataExtractor` IS injectable** at the provider level
   (`OpenAICompatibleProviderSettings.metadataExtractor`, `d.ts:370`) — the
   seam #406 anticipated. Non-streaming: `extractMetadata({ parsedBody })`'s
   result is spread into the response `providerMetadata` (`dist/index.js:665`);
   streaming: `createStreamExtractor()` → `processChunk` per chunk (`:803`) →
   `buildMetadata()` merged into the finish part (`:899`). The returned object
   must be keyed by provider id (we use `"gateway"`).
5. **Non-retryable errors are thrown RAW on the first attempt.**
   `retryWithExponentialBackoff` throws the original error when
   `tryNumber === 1` and shouldRetry is false (`@ai-sdk/provider-utils@5.0.12`
   `dist/index.js:3357-3364`); a `RetryError` (with `.lastError`) is thrown
   only after multiple attempts (`:3328-3333`, `:3360-3364`). 401/403/446 are
   non-retryable → the classifier sees a bare `APICallError` in the common
   case but must defensively unwrap `RetryError.lastError`.
6. **`generateText` result exposes `providerMetadata`** (ai@7.0.37
   `d.ts:464`); the stream drain's existing `case "finish-step"`
   (`agent-runner.ts:1736-1740`) receives `part.providerMetadata:
   ProviderMetadata | undefined` (ai@7.0.37 `d.ts:2898-2904`).
7. **Name collision:** ai@7 itself exports a `GatewayError` (Vercel AI
   Gateway; used in its retry predicate, `dist/index.js:2703`). Our classes
   are therefore named `Bifrost*`, not `Gateway*` — consistent with #406's
   vendor-naming quarantine in `providers/bifrost.ts`.
8. **Live-captured wire shapes (authoritative, issue #406 body, 2026-07-27):**
   401 `{"type":"virtual_key_required",…,"error":{"message":"virtual key is
   required. Provide a virtual key via the x-bf-vk header."}}`; 403
   `{"type":"provider_blocked",…,"error":{"message":"Provider 'gemini' is not
   allowed for this virtual key"},"extra_fields":{…}}`. **Docs-derived
   (PROVISIONAL):** the 446 guardrail-violation body
   (`error.type: "guardrail_violation"`, `guardrail_id`/category/severity/
   action), `bifrost_metadata` on redacted successes, and `extra_fields` on
   success bodies. See § Provisional-shape discipline.

## Approach

Three additions, all response-side, all gated on the gateway path:

**A. Classification (pure, in `providers/bifrost.ts`).** A tolerant Zod
envelope schema + `classifyBifrostError(e: unknown)`: unwrap
`RetryError.lastError` if present (fact 5), require `APICallError.isInstance`,
`JSON.parse` the `responseBody` (fact 2), accept only bodies with
`is_bifrost_error === true` or a recognized `type`; map to
`BifrostVirtualKeyRequiredError` (401 / `virtual_key_required`),
`BifrostProviderBlockedError` (403 / `provider_blocked`),
`BifrostGuardrailViolationError` (446 or `error.type ===
"guardrail_violation"` — provisional), else base `BifrostError`. Each carries
`statusCode`, `bifrostType`, attribution from `extra_fields` (`provider`,
`originalModelRequested`, `resolvedModelUsed`), and `cause` = the original
`APICallError`. Anything unparseable → `undefined` (caller falls back to
today's generic path — classification must never throw).

**B. Runner hooks (small, at existing choke points).** Two private helpers on
`AgentRunner`:

- `_gatewayAwareError(e, scope)` — classify; when a
  `BifrostGuardrailViolationError`, emit `agent.guardrail.violation` first;
  always enrich the `agent.error` emission (typed `errorType`, Bifrost message,
  `context: { statusCode, bifrostType, provider, guardrailId?, … }`); return
  the typed error (or the original when classification misses) for rethrow.
  Wired at: the run-loop catch (`agent-runner.ts:577-606` — replace the
  bare-`err` emission + `throw e`), the stream drain's `case "error"`
  (`:1811-1842` — classify `part.error`, emit+yield violation before the
  existing `agent.error`), and NEW thin try/catch wrappers around the three
  `runStructured` provider calls (`:1263-1269` no-tools, `:1314-1320` capable,
  `:1416-1422` tier-2). The structured wrappers are a **deliberate behavior
  addition** (today a thrown `APICallError` propagates with NO `agent.error`
  event on those calls — verified: no try around them; call out in the PR).
- `_maybeEmitRedaction(text, providerMetadata, scope)` — no-ops unless
  `model.provider.startsWith("gateway")` (same gate as
  `bifrostCorrelationHeaders`, `bifrost.ts:80`; the provider string is
  `"gateway.chat"`). Runs `scanRedactionPlaceholders(text)` and reads
  `providerMetadata?.gateway` (extractor output); emits ONE
  `agent.guardrail.redaction` per LLM call when either source fires, with
  entity counts and `source: "placeholders" | "metadata" | "both"`. Wired at:
  run-loop success after `agent.llm.end` (`:655-668`, scanning `result.text`
  each iteration), stream end (scanning the accumulated `fullText`, `:1540` /
  `:1902`, with `providerMetadata` captured from the `finish-step` part at
  `:1736-1740`), and `runStructured` post-validation (scanning
  `JSON.stringify(parsed.data)` once, `:1432` region).

Import note: `agent-runner.ts` gains a VALUE import from
`providers/bifrost.js`; `bifrost.ts`'s existing import from `agent-runner.js`
is type-only (`RunHeadersContext`, erased at build) — no runtime cycle.

**C. Metadata + attribution.** `bifrostMetadataExtractor` (structurally
compatible with openai-compatible's `MetadataExtractor` — defined WITHOUT
importing the type, so the barrel-exported `bifrost.ts` takes no compile-time
dependency on the optional peer): picks `extra_fields` + `bifrost_metadata`
from `parsedBody` and returns `{ gateway: { … } } | undefined`. Wired as ONE
key in `buildFromGateway`'s provider-settings literal
(`model-resolver.ts:456-464`) — exactly the seam #406 reserved. It is pure
read-only extraction of Bifrost-named fields: absent fields → `undefined` →
non-Bifrost gateways see no providerMetadata delta. Attribution then surfaces
as an optional `gateway` field on `agent.llm.end` (additive; no new wire name
→ no manifest impact from this part) and an optional `RunResult.gateway`
(additive, precedent: `costUsd`/`usageDetails`, `runner/types.ts:57-67`).

**Event plumbing** follows the #389 checklist verbatim (every anchor
re-verified on the #406 branch) — see the File-level plan. Profile decision:
both events register in **UX + DEBUG only** (matching the issue's acceptance
wording and #389's precedent at `event-profiles.ts:52-53`/`:116-117`).
Violations still reach OBSERVABILITY exporters via the enriched `agent.error`
(already in that profile, `event-profiles.ts:93`); a dedicated exporter
mapping for redactions is deferred (Open question 2).

export class BifrostError extends Error {
  readonly statusCode?: number;
  readonly bifrostType?: string;
  readonly provider?: string;
  readonly originalModelRequested?: string;
  readonly resolvedModelUsed?: string;
  readonly envelope: unknown;           // parsed responseBody, verbatim

export class BifrostProviderBlockedError extends BifrostError {}
export class BifrostGuardrailViolationError extends BifrostError {
  readonly guardrailId?: string;        // PROVISIONAL (docs-derived)
  readonly category?: string;
  readonly severity?: string;
  readonly action?: string;
}
export function classifyBifrostError(e: unknown): BifrostError | undefined;

export function scanRedactionPlaceholders(
  text: string,
): Readonly<Record<string, number>> | undefined;

export interface GatewayAttribution {
  readonly provider?: string;
  readonly requestedModel?: string;
  readonly servedModel?: string;
}
export function attributionFromProviderMetadata(
  pm: unknown,
): GatewayAttribution | undefined;

/** Structurally MetadataExtractor-compatible; no static openai-compatible import. */
export const bifrostMetadataExtractor: {
  extractMetadata: (o: { parsedBody: unknown }) => Promise<Record<string, Record<string, unknown>> | undefined>;
  createStreamExtractor: () => {
    processChunk(parsedChunk: unknown): void;
    buildMetadata(): Record<string, Record<string, unknown>> | undefined;
  };
};

// events/types.ts — new events (wire names: guardrail.violation / guardrail.redaction)

  readonly action: "blocked";
  readonly message: string;
  readonly statusCode?: number;
  readonly bifrostType?: string;
  readonly guardrailId?: string;
  readonly category?: string;
  readonly severity?: string;
  readonly provider?: string;
}
interface GuardrailRedactionEvent extends BaseEvent {
