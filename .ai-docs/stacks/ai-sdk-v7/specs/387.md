# Spec — Promote ClaudeCodeLanguageModel V2 → V4 provider spec

## Goal

Rewrite the hand-written Claude Code provider from `LanguageModelV2` to
`LanguageModelV4` so it stops triggering ai@7's runtime deprecation warning for
V2 models (vercel/ai#10689 — the user-visible win) and starts **emitting real
cache read/write token numbers** from the Claude CLI's usage fields (feeds
#388 token-detail). Session economics, defer-hook mechanics, config isolation,
and the flatten fallback are all **behavior-invariant** — this is a
spec-boundary translation, not a provider redesign.

**Stacked on #386**: branch `dugshub/387-cc-v4-provider-spec` is based on
`dugshub/386-ai-sdk-v7-bump` (PR #393, in validation). #386 deliberately left
`claude-code.ts` / `cc-shim.ts` / `cc-session.ts` + 4 test suites V2-pinned
(D5 + its codemod guard list); those pinned files are exactly and exhaustively
this PR's surface. #386 already introduced
`ResolvedLanguageModel = V2 | V3 | V4` (`src/providers/types.ts:22`), so the
promoted model needs **zero seam changes** in runner/resolver — it stays
assignable everywhere it's used today.

All spec-shape claims below are verified against the published
`@ai-sdk/provider@4.0.3` d.ts and `@anthropic-ai/claude-agent-sdk@0.3.220`
`sdk.d.ts` (the installed dev version; runtime pins `^0.3.0` dep /
`^0.3.215` devDep, package.json:58/:67).

**One correction to the issue text**: V4's warnings type is
**`SharedV4Warning`**, not `SharedV3Warning`. `LanguageModelV4GenerateResult.warnings`
and the `stream-start` part are both `Array<SharedV4Warning>` (d.ts; V4 adds a
`deprecated` variant over V3's `unsupported | compatibility | other`).
understanding.md §Provider-spec wrote V3 because V3→V4 was described as
byte-identical — the warning union is the one place it isn't.

## Approach

Four ordered commits on the stacked branch:

1. **Type-rename commit** — mechanical `LanguageModelV2*` → `LanguageModelV4*`
   across the three source files + four test suites; `specificationVersion:
   "v4"`; fix the two `ToolResultOutput` render switches for the V4 union
   (`execution-denied` + `media`→`file`/`custom`). Tree typechecks but tests
   still assert V2 result shapes — red.
2. **Result-shape commit** — nested usage builder (reading cache fields from
   the CLI's `NonNullableUsage`), `{unified, raw}` finishReason, warnings
   threading; migrate test fixtures/assertions; flip the
   `specificationVersion === "v2"` canary (claude-code.test.ts:213) to `"v4"`.
   Green.
3. **Reasoning commit** — map the new V4 `reasoning` CallOption onto the
   harness's `effort` / `thinking` options (verified supported — see below);
   add tests asserting the captured SDK options.
4. **Version-bump commit** — `just bump-lockstep minor` → runtime/server/cli
   **0.32.0 → 0.33.0** (386 landed 0.32.0; core is untouched — providers live
   only in runtime).

Three load-bearing verified facts that shape the design:

- **The CLI carries cache numbers today.** The SDK result message's
  `usage: NonNullableUsage` is a fully-non-nullable `BetaUsage`
  (sdk.d.ts:1284) — `input_tokens`, `output_tokens`,
  `cache_creation_input_tokens`, `cache_read_input_tokens` are all present on
  every real result. The current provider reads only
  `input_tokens`/`output_tokens` (claude-code.ts:568-572 in `runQuery`,
  :986-990 in `doStream` — there is no `deriveUsage` helper; the reads are
  inline). The V4 nested shape has exactly the slots for the discarded fields.
- **The harness supports the `reasoning` knob natively.** SDK `Options` has
  `effort?: 'low' | 'medium' | 'high' | 'xhigh' | 'max'` (sdk.d.ts:1653-1668)
  and `thinking?: ThinkingConfig`
  (`adaptive | enabled{budgetTokens} | disabled`, sdk.d.ts:1640-1651). So the
  V4 `reasoning` CallOption maps to real harness behavior — no
  "accepted-and-ignored" cop-out needed, except for `'minimal'` (no harness
  equivalent → map to `'low'` + a `compatibility` warning).
- **Usage semantics must match the ecosystem.** `@ai-sdk/anthropic@4.0.21`
  maps Anthropic usage as `total = input_tokens + cache_creation + cache_read`,
  `noCache = input_tokens`, `cacheRead`/`cacheWrite` = the cache fields, and
  `raw` = the raw usage object (verified in its dist). We mirror that exactly,
  so downstream flattening (`result.usage.inputTokens` in AgentRunner) stays
  consistent across our providers. Note the intended behavior change: reported
  input totals **grow** when prompt cache is active (V2 reported only uncached
  `input_tokens`) — that is the acceptance criterion, not a regression.

`ClaudeCodeProviderOptions`, `SessionStrategy`, `CCSessionDebugEvent` all keep

```ts

```

Two new module-private helpers:

```ts
/** Map the CLI's NonNullableUsage (BetaUsage-shaped) → V4 nested usage.
 *  Formula mirrors @ai-sdk/anthropic@4 for cross-provider consistency:
 *  total = input_tokens + cache_creation + cache_read; noCache = input_tokens. */
function buildUsage(raw: Record<string, number> | null): LanguageModelV4Usage;
// → { inputTokens: { total, noCache, cacheRead, cacheWrite },
//     outputTokens: { total: output_tokens, text: undefined, reasoning: undefined },
//     raw: raw ?? undefined }

/** Apply the V4 `reasoning` CallOption to SDK options (effort/thinking);
 *  returns warnings ('minimal' → compatibility). Mutates sdkOptions. */
function applyReasoning(
  sdkOptions: SDKOptions,
  reasoning: LanguageModelV4CallOptions["reasoning"],
): SharedV4Warning[];
```

And two signature changes to existing private helpers:

```ts
private _baseSdkOptions(options: LanguageModelV4CallOptions): {
  sdkOptions: SDKOptions;

function buildGenerateResult(
  out: QueryOutcome,
  warnings: SharedV4Warning[],
```

- **`ResolvedLanguageModel` / runner / resolver seams** — already V4-ready

  and their tests.
- **Reasoning-token accounting** (`outputTokens.reasoning`) — emitted as

- **`strict` / `inputExamples` FunctionTool support** — ignored (documented);

## Open questions

None block start; defaults chosen:

1. **Absent-usage field policy**: when the mock (or a degraded CLI path)
   omits cache fields, emit `0` (matching `NonNullableUsage`'s all-present
   contract and anthropic@4's `?? 0` coalescing — chosen default) rather than
   `undefined`. If the implementer finds real CLI paths where usage is wholly
   absent (`usage: null` QueryOutcome), emit all-`undefined` nested fields
   rather than fabricating zeros.
2. **`outputTokens.reasoning`**: `BetaUsage` may grow
   `output_tokens_details.thinking_tokens` (anthropic@4 reads it from the
   raw API). Implementer should opportunistically read
   `usage.output_tokens_details?.thinking_tokens` if present on the installed
   SDK's result — harmless if absent (`undefined`). Not acceptance-gated.
3. **`reasoning: 'none'` vs subscription models**: `thinking: { type:
   "disabled" }` is the semantically-correct mapping; if live smoke shows the
   CLI rejects it for some model, fall back to `effort: "low"` + compatibility
   warning and note it in the PR.
