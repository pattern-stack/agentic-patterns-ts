# Spec — Detailed token accounting (cache + reasoning): events → exporters → dashboard

All line numbers cite branch `dugshub/386-ai-sdk-v7-bump` @ `292274b` (the migrated
v7 runtime). Verified against the installed `ai@7.0.37` / `@ai-sdk/provider@4.0.3` /
`@ai-sdk/anthropic@4.0.21` d.ts + dist on that branch.

## Goal

The runtime reads only flat `inputTokens`/`outputTokens` everywhere (verified:
that is the complete set of usage reads in `agent-runner.ts`; understanding.md
"Token accounting today"). ai@7's app-level `LanguageModelUsage` additionally
carries `inputTokenDetails.{noCacheTokens,cacheReadTokens,cacheWriteTokens}` and
`outputTokenDetails.{textTokens,reasoningTokens}` (byte-verified,
`ai/dist/index.d.ts:319-369`). Surface those five detail counts as **optional**
fields on the usage-carrying `agent.*` events, thread them through the console /
Langfuse / OTel exporters and the SSE wire, and render a minimal breakdown in the
dashboard trace view.

**The load-bearing invariant is absent ≠ zero.** In ai@7 the detail *objects*
are always present but every member is `number | undefined` — a provider that
doesn't report cache/reasoning yields `undefined` members, and our events must
then **omit** the detail payload entirely, never zero-fill. Two verified
consequences drive this:

- `@ai-sdk/anthropic@4` populates all of them (`convertAnthropicUsage`,
  `@ai-sdk/anthropic/dist/index.js:1968-2017`): `cache_read_input_tokens` →
  `cacheRead`, `cache_creation_input_tokens` → `cacheWrite`,
  `output_tokens_details.thinking_tokens` → `reasoning`.
- Our still-V2 `ClaudeCodeLanguageModel` emits only flat
  `usage: {inputTokens, outputTokens}` (`src/providers/claude-code.ts:633-635`),
  and ai@7's V2→V3 shim (`convertV2UsageToV3`, `ai/dist/index.js:762-775`) maps
  only V2's optional `cachedInputTokens`/`reasoningTokens` (which we never set)
  — so the CC provider reports **no** detail until #387 promotes it to V4. #388
  is `parallel_with` #387 and must NOT assume it: CC runs simply carry no
  `usageDetails`, and everything downstream renders exactly as today.

**Stacked on #386**: branch `dugshub/388-token-detail-accounting` from
`dugshub/386-ai-sdk-v7-bump`. Do not merge before #386.

## Approach

One new shared type + one small runner helper module; then purely additive
threading. No new event types, no new SSE wire names (the wire manifest guards
*names* only — `sse-wire-manifest.test.ts:25-30` — so no manifest regeneration).

**Convention note:** the events layer is deliberately **plain TS interfaces**,
not Zod (`events/types.ts` top-of-file; Zod lives in `admin/schemas.ts` etc.).
Follow the local convention: interface fields, `readonly`, optional (`?`), with
`Object.freeze` nowhere in this layer — exactly like `costUsd?` (#323) and
`artifacts?` (ADR-0006), the two prior additive event-payload extensions this
change should imitate (including their conditional-spread emission style,
`agent-runner.ts:756`).

### The five-field detail shape (flat, one object)

Flat mirrors the events convention (top-level `inputTokens`/`outputTokens`) and
keeps SSE/dashboard mapping trivial; the five SDK member names are globally
unambiguous so no input/output nesting is needed.

### Presence rule (the absent ≠ zero mechanics)

- `detailsFromUsage(usage)` returns `undefined` when **all five** members are
  `undefined` → the event field is omitted entirely (conditional spread).
- When at least one member is defined, the object carries **only the defined
  members** (no zero-filling of the others).
- Aggregation across iterations/steps mirrors the SDK's own
  `addTokenCounts` (`ai/dist/index.js:2616-2618`): per field, `undefined +
  undefined = undefined`; otherwise sum treating `undefined` as 0. This is the
  exact semantics ai@7 itself uses in `addLanguageModelUsage` — cite it in the
  helper's doc comment so nobody "fixes" it later.

## Interfaces

The one new exported type (events layer) + the runner helper signatures:

```ts
// src/events/types.ts
/**
 * Optional cache/reasoning token detail (#388). Populated ONLY from what the
 * provider reported — every member is independently optional and the carrying
 * event omits the whole object when the provider reported nothing.
 * ABSENT MEANS UNREPORTED, NEVER ZERO. Input-side members partition
 * `inputTokens` when all three are present (v4-spec providers, e.g.
 * @ai-sdk/anthropic: total = noCache + cacheRead + cacheWrite); output-side
 * members partition `outputTokens` likewise (text + reasoning).
 */
export interface TokenUsageDetails {
  readonly noCacheTokens?: number;
  readonly cacheReadTokens?: number;
  readonly cacheWriteTokens?: number;
  readonly textTokens?: number;
  readonly reasoningTokens?: number;
}

// LLMCallEndEvent + MessageCompleteEvent + RunResult each gain:
readonly usageDetails?: TokenUsageDetails;
```

```ts
// src/runner/usage-details.ts
import type { LanguageModelUsage } from "ai";
import type { TokenUsageDetails } from "../events/types.js";

/** undefined when the provider reported no detail members at all. */
export function detailsFromUsage(usage: LanguageModelUsage | undefined): TokenUsageDetails | undefined;

/** Per-field: undefined+undefined = undefined; else sum treating undefined as 0
 *  (mirrors ai's own addTokenCounts/addLanguageModelUsage). */
export function mergeUsageDetails(
  a: TokenUsageDetails | undefined,
  b: TokenUsageDetails | undefined,
): TokenUsageDetails | undefined;
```

SSE wire (additive key on two existing events, snake_case, defined-only):

```
llm.end / message.complete payloads +=
  usage_details?: { no_cache_tokens?, cache_read_tokens?, cache_write_tokens?,
                    text_tokens?, reasoning_tokens? }
```

- **THE double-billing claim — VERIFIED, and correctly fixed.**
  `asLanguageModelUsage` (`ai/dist/index.js:2545-2564`) sets the app-level flat
  `inputTokens` to `usage.inputTokens.total` and `inputTokenDetails.noCacheTokens`
  to `usage.inputTokens.noCache`. `convertAnthropicUsage`
  (`@ai-sdk/anthropic/dist/index.js:2003-2009`) builds `total = input_tokens +
