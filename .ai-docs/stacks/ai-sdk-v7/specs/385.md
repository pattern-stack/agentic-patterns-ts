# Spec — Drop CJS output; require Node >= 22

## Goal

Ship every publishable package (`core`, `runtime`, `server`, `cli`) as ESM-only with
`engines.node: ">=22"`, so the subsequent `ai@7` bump (#386) — which is ESM-only,
Node >= 22 — is unblocked. This lands as a standalone PR, independently revertable
and publishable, per decisions D2/D3 in `understanding.md`.

No runtime behavior changes. This is a packaging + build-config + docs + smoke-gate
change only.

## Approach

Three concentric edits, all mechanical, all verified against current files:

1. **Build**: tsup `format` → `["esm"]` in the three dual-format packages
   (cli is already ESM-only at `packages/agent-cli/tsup.config.ts:6`).
2. **Manifest**: for core/runtime/server, delete `main` + `module`, flatten the
   `exports["."]` conditional to `{types, default}` (no `require` branch); bump
   `engines.node` to `">=22"` in all four package.json files plus the private
   workspace root.
3. **Contract**: TWO sibling gates currently *assert* the CJS contract and must
   flip from "verify CJS works" to "verify CJS artifacts are absent":
   - **PR-time**: `tools/check-dist-contract.ts` — required on every PR, wired
     both into `bun run check` (root `package.json:20`) and as a dedicated CI
     step "Dist contract (ESM + CJS load)" (`.github/workflows/ci.yml:39-40`).
     Without the flip, `bun run check` and the CI step go red the moment tsup
     stops emitting `index.cjs` (existence check at `:55`).
   - **Publish-time**: `test/post-publish/run-tarball-smoke.ts` — runs in the
     publish job via `scripts/publish.sh:181`.

   Flipping both directly encodes the acceptance criterion at both gates.

CI **node version** needs no change — both jobs already run `node-version: 24`
(`.github/workflows/ci.yml:27` and `:83`). But the workflow file IS touched:
the dist-contract step name and its explanatory comment (`ci.yml:35-39`) say
"BOTH formats" / "ESM + CJS load" and go stale — see File-level plan.

### Version bumps (staged, per repo convention)

Current state (verified 2026-07-26 against both the working tree and the live npm
registry): lockstep trio at **0.30.0**, core at **0.14.0** — and both are
**already published** (`npm view @agentic-patterns/{core,runtime,server,cli}
version`). The ADR-0006 render-artifacts release consumed 0.30.0/0.14.0, so this
PR cannot ride those numbers and must take a fresh minor.

`just bump-both` (justfile:97, defaults `minor minor`) — runs
`scripts/bump.sh --lockstep minor --core minor`. Rationale: engines floor raise +
dropped require entry point is breaking for CJS consumers; under 0.x convention a
minor bump signals that. Result: runtime/server/cli **0.30.0 → 0.31.0**, core
**0.14.0 → 0.15.0**. Publish fires automatically on merge (idempotent, gated on
the updated smoke). Implementer note: re-run the `npm view` check at
implementation time — if another release lands first, the from→to shifts again;
the invariant is "one fresh minor on both tracks from whatever is current".

## Interfaces

No new interfaces. The consumer-visible contract change is subtractive:

```json
// core / runtime / server package.json — after
{
  "types": "./dist/index.d.ts",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" }
  },
  "engines": { "node": ">=22" }
}
```

`require("@agentic-patterns/*")` from CJS consumers on Node < 22 stops resolving —
intended and release-noted via the minor bump. (Node >= 22 CJS consumers can still
`require()` the ESM entry via `require(esm)`, which is why the smoke gate now
checks artifact absence rather than require-failure.)

## Tests

1. `bun run check` — per root `package.json:20` this is build + **dist-contract**
   + typecheck + lint + vitest + model-facing-schemas; green. The dist-contract
   leg only passes once `tools/check-dist-contract.ts` is flipped (it is the first
   thing that breaks after the tsup change — flip it in the same commit).
2. After `bun run build`: `find packages/*/dist -name '*.cjs*' -o -name '*.d.cts'`
   returns nothing — automated by the new negative assertions at BOTH gates:
   PR-time (`check:dist-contract`) and publish-time (tarball smoke).
3. `bun test/post-publish/run-tarball-smoke.ts` (after build) — exercises the
   updated publish gate end-to-end: pack → install into throwaway consumer → ESM
   import ✓, `.d.ts` ✓, no `.cjs`/`.d.cts` in installed dist ✓, cli bin ✓.
4. Optional belt-and-braces: `bash scripts/publish.sh ci --dry-run` (full CI
   publish path incl. smoke, no upload).

No new vitest suites — the two gate scripts are the packaging contract's test
surface.
