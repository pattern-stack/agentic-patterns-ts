# Spec — Bump ai@5 → ai@7 + mechanical migration

## Goal

Move `packages/agent-runtime` from `ai@5` / `@ai-sdk/provider@2` (LanguageModelV2
era) to `ai@7` / `@ai-sdk/provider@4` (LanguageModelV4 era) with **no behavior
change**: same events, same gate-chain semantics, same token accounting, same
public runner API. `ClaudeCodeLanguageModel` and its shim/session modules stay
V2-spec (decision D5 — ai@7 accepts V2 models per understanding.md fact 1; the
runtime deprecation warning is accepted until #387). All SDK usage lives in
agent-runtime (understanding.md §Usage surface — verified: no `ai`/`@ai-sdk`
imports in core/server/dashboard); the only out-of-package touch is the CLI's
`init` scaffold version strings.

**Stacked on #385**: branch from `dugshub/385-drop-cjs-node22` (ESM-only +
Node ≥ 22 is a hard prereq — ai@7 is ESM-only, `engines.node >= 22`). Do not
merge before #385 merges.

## Approach

Five ordered, separately-committed passes — so every codemod hunk is reviewable
in isolation from hand edits:

1. **Deps commit** — bump the six version strings in
   `packages/agent-runtime/package.json` (exact locations below), `bun install`.
   Tree is red after this commit alone; that's expected and contained.
2. **Codemod v6 commit** — `npx @ai-sdk/codemod v6 packages/agent-runtime`,
   review every hunk, revert any touch on the V2-pinned files (guard list below).
3. **Codemod v7 commit** — `npx @ai-sdk/codemod v7 packages/agent-runtime`,
   same review discipline.
4. **Hand-fix commit** — everything the codemods miss: the type-widening at the
   runner/resolver seams (the one real interface change), residual renames in
   `agent-runner.ts`, mock-fixture reshaping the codemod half-did, stale "v5"
   comments, CLI scaffold pins.
5. **Version-bump commit** — `just bump-lockstep minor` (justfile:89); core is
   SDK-free and untouched, so no core bump.

Two verified non-events that shrink the issue's stated scope:

- **`message-utils.ts` needs NO `allowSystemInMessages`**: `convertHistory()`
  emits only `user`/`assistant`/`tool` roles — `system_prompt` parts are
  deliberately skipped (`src/runner/message-utils.ts:86`, "handled separately by
  agent.renderInitialPrompt()"). v7's system-in-messages rejection cannot fire.
  No restructure; comment sweep only.
- **`create-runner` has NO version sniffing**: `specificationVersion` is never
  read anywhere in `src/` (sole non-test occurrence is the *declaration* at
  `src/providers/claude-code.ts:647`). The `"v1"`/`"v2"` strings in
  `create-runner.test.ts:52,82,277` live inside `as any` stubs that are never
  interrogated — no `"v4"` awareness is needed; updating them is cosmetic.

And one real interface change the issue doesn't name: after
`@ai-sdk/anthropic@4` lands, every `ProviderProtocol.load()` returns a
**V4-spec** model, while our seams are typed `LanguageModelV2`
(`agent-runner.ts:28,159`, `create-runner.ts:20,87`, `model-resolver.ts:30`,
`providers/types.ts:15`). Those types must widen to the V2|V3|V4 union or the
build breaks the moment the deps bump. See Interfaces.

## Interfaces

One new exported type alias, in `src/providers/types.ts` (all other changes are
renames on existing surfaces):

```ts
import type { LanguageModelV2, LanguageModelV3, LanguageModelV4 } from "@ai-sdk/provider";

/**
 * A live, instance-form language model — any provider-spec version ai@7
 * accepts. Mirrors ai's `LanguageModel` union minus the string
 * (global-provider-id) arm: our resolvers hand out instances, never ids.
 */
export type ResolvedLanguageModel = LanguageModelV2 | LanguageModelV3 | LanguageModelV4;
```

Threaded through (replacing bare `LanguageModelV2`):

```ts
// providers/types.ts       — ProviderProtocol.load(modelId): Promise<ResolvedLanguageModel>
// providers/model-resolver — ModelResolver.resolve(id?): Promise<ResolvedLanguageModel>
// runner/agent-runner      — constructor(model: ResolvedLanguageModel | ModelResolver, ...)
// runner/create-runner     — CreateRunnerOptions.model?: ResolvedLanguageModel
```

This is widening-only: every existing caller (including `ClaudeCodeLanguageModel`,
still V2) remains assignable. `model.modelId` — the only property the runner
reads off the model itself (:364, :1071, :1297) — exists on all three specs.
