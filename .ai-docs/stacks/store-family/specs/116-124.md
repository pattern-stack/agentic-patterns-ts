# Spec — Per-node runner override + host passthrough (#116 + #124, one PR)

> **Issue lineage:** the design doc labels the propagation track "#99". GitHub #99 (core
> `ToolExecutionContext` param) and #102 (trace threading) are **closed, verified-done
> groundwork**; the remaining propagation scope was re-filed as **#124**. Everywhere the design
> doc says "#99", read #124 for the work below.

## Goal

Make "every subagent configured/contextualized the same **declarative** way" true for the two
context fields that can't be declared today:

- **#116 — the runner.** Per-node *model* override exists (`AgentStepSpec.model` →
  `applyStepModel`, `base.ts:169`), but the runner is ambient-only (`ctx.runner`,
  `node.ts:29`). A node that needs a different executor (canvas-workstation: direct-Google for
  native structured output, because the ambient gateway runner rejects json-schema
  `responseFormat`) can only get one via a hand-written decorator that overwrites `ctx.runner`
  (`with-persistence.ts:124-133` — the closure hack). Fix: `runner?: RunnerProtocol` on
  `AgentStepSpec` (`agent-step.ts:44`) and `CoordinatorStepSpec` (`coordinator-step.ts:69`),
  plus a blessed `withRunner(node, runner)` subtree combinator. The hack becomes
  `withRunner(pipelineNode, directGoogleRunner)` — declared at assembly, visible in review.

- **#124 — scratchpad + deps.** An agent-as-tool subagent runs inside the runner's tool loop,
  not the Node call-tree; the only object crossing that runner → tool boundary is core's
  `ToolExecutionContext` (`toolbox.ts:29`, added by #99). Trace fields already ride that rail
  (#102); `scratchpad`/`deps` come from a construction-time closure instead
  (`node-tool.ts:57-58`) — so a coordinator's delegated subagents never see the caller's live
  run context. Fix — **Design A (locked)**: an opaque `host?: unknown` passthrough on
  `ToolExecutionContext` and `RunOptions`, populated by `AgentStep.run` with
  `{ scratchpad, deps }`, copied per tool call by the runner's `buildToolCtx`
  (`agent-runner.ts:207`), and consumed by `nodeTool` (`node-tool.ts:55-63`) — which **forks**
  the inherited scratchpad (`slot.ts:127`), never aliases it.

Both changes are **additive** — no renames, no behavior change for existing callers, no version
bump (settled at #118's Gate-1: the stack's single 0.7.0 → 0.8.0 bump lives in #118; #116/#124
leave `package.json` untouched). One PR closing both issues, stack branch 2 on
`dug/118-store-naming-standardization`.

The design is **LOCKED** (`docs/node-context.md`, 2026-07-03) — this spec translates it to
file-level edits; it does not re-litigate. Every file:line below was re-verified at the branch
tip `cf0333b` (see "Verified against branch tip").

## Approach

### #116 — declarative per-node runner

Three edits, all in `workflows/`:

1. **`AgentStepSpec.runner?: RunnerProtocol`** (`agent-step.ts:44`, field beside `model` at
   `:62`). v1 is a **raw `RunnerProtocol` instance** — a 1:1 replacement for what the closure
   hack already builds. The capability/policy form (`requires: { structuredOutput: "native" }`)
   is explicitly deferred until a second consumer appears (locked design §"Open design choice").
2. **Resolution in `AgentStep.run`** (`agent-step.ts:102`): `const runner = this.spec.runner ??
   ctx.runner;` immediately after the model view (`:103`), then route all three runner touches
   through it — the `runStructured` capability guard (`:114`), the `runStructured` call
   (`:117`), and the text-path `run` call (`:127`). Note the guard now checks the **resolved**
   runner: a spec-level override that lacks `runStructured` fails loud
   (`StructuredOutputUnsupported`) even if the ambient runner has it — the override is total
   for that node, by design.
3. **`withRunner(node, runner)`** — new file `workflows/with-runner.ts`, exported through
   `workflows/index.ts` (which reaches the package barrel via `src/index.ts:10`). A transparent
   decorator: returns a `Node` whose `run(input, ctx)` is `inner.run(input, { ...ctx, runner })`.
   It preserves `inner.name` (hooks/events keep attributing to the real node) and passes the
   `NodeResult` through untouched.

**Precedence** (falls out of `spec.runner ?? ctx.runner`, stated here so tests pin it):
leaf `spec.runner` > nearest enclosing `withRunner` (ctx override) > root `ctx.runner`.

`CoordinatorStep` gains the same spec field (`coordinator-step.ts:69`) and forwards it into the
internal leaf it already builds (`:125-131`) — `runner: this.spec.runner` in the
`AgentStepSpec` — so resolution stays in exactly one place (`AgentStep.run`).

Orthogonality (locked design): per-node *runner* and per-node *model* remain independent; a
concrete runner override also sidesteps the "model override only bites with a resolver-backed
runner" caveat for that node.

### #124 — Design A: the opaque `host` passthrough

The scratchpad must travel *through* the runner. Put it on the one object that already crosses
the boundary, using the exact philosophy `emit` uses: **core declares an opaque slot; the host
wires the meaning.** Core stays dependency-clean — the field is `unknown`; core never imports
runtime's `Scratchpad`/`DepReader`.

```
AgentStep.run(ctx)                              has ctx.scratchpad ✓
  └─ runner.run/runStructured(agent, msg, { …opts, host:{scratchpad,deps} })  ← RunOptions carries it
       └─ [LLM emits tool call(s) — possibly parallel, Promise.all agent-runner.ts:512]
            └─ buildToolCtx() → ToolExecutionContext{ …trace, host }           ← copied ONCE (:207)
                 └─ NodeToolbox tool.execute(args, ctx)
                      └─ nodeTool → spec.node.run(input, {
                           scratchpad: host.scratchpad.fork() ?? closure/fresh, ← inherit, FORK
                           deps:       host.deps ?? closure,
                         })
```

Five additive edits (numbered as in the locked design):

1. **core `ToolExecutionContext`** (`agent-core/src/molecules/toolbox.ts:29`) — add
   `readonly host?: unknown;`, documented like `emit`: host-declared passthrough, core never
   interprets it.
2. **runtime `RunOptions`** (`runner/types.ts:113`) — add `host?: unknown;`: opaque payload the
   runner copies verbatim onto every `ToolExecutionContext` it builds for this run.
3. **`AgentStep.run`** (`agent-step.ts:105-110`) — add
   `host: { scratchpad: ctx.scratchpad, deps: ctx.deps }` to the `RunOptions` it builds.
   `CoordinatorStep` inherits this via its internal `AgentStep` (`coordinator-step.ts:133`
   spreads `{ ...ctx, toolExecutor }`, so the coordinator's own scratchpad/deps flow in).
4. **runner `buildToolCtx`** (`agent-runner.ts:207`) — add `host?: unknown` to its args object
   and `host: a.host` on the returned context. This is the **single copy site** — the one place
   a `ToolExecutionContext` is constructed. The three converging dispatch sites only *relay*
   the value (one arg each, no logic):
   - `:541` — `run()`'s parallel tool dispatch (`options` in scope): `host: options?.host`.
   - `:697` — inside `convertExecutableTools` (`:644`), whose `ctx` param
     (`{ traceId; runId; parentSpanId }`, `:647`) gains `host?: unknown`; its single caller in
     `runStructured` (`:807`) passes `host: options?.host`.
   - `:1312` — `stream()`'s dispatch (`options` in scope): `host: options?.host`.
5. **`nodeTool`** (`node-tool.ts:53-63`) — narrow and consume:

   ```ts
   const host = ctx?.host as { scratchpad?: Scratchpad; deps?: DepReader } | undefined;
   ```

   then prefer the live context over the construction-time closure:
   `scratchpad: host?.scratchpad ? host.scratchpad.fork() : (scratchpad ?? createScratchpad())`
   and `deps: host?.deps ?? deps`. The closure params stay as documented fallbacks (their `:40-46`
   doc comment gets updated: automatic propagation now exists via #124; closure = explicit
   override / no-host fallback). The closure-scratchpad path stays **byte-identical** (still
   passed by reference — its "shared slot store across calls" contract, `node-tool.ts:90`, is
   existing documented behavior and not this issue's to change).

**The one semantic decision — fork, don't alias** (locked): a coordinator's LLM fires tool
calls **in parallel** (`Promise.all`, `agent-runner.ts:512`; the class doc at `:118` states it).
Aliasing one mutable scratchpad across parallel subagent calls reintroduces the race the
run/branch split exists to prevent. `fork()` (`slot.ts:127`) shares **run-scoped** entries by
reference (the subagent reads *and* writes the same shared state — the ask) while
**branch-scoped** entries start fresh per call (concurrency-safe). **`join()` / merge-back is
OFF for v1** — call-and-return delegation has no clean index order to merge on; a subagent's
branch-scoped scratch is discarded, matching "a branch with no `merge` discards its scratch".

**What #124 does NOT thread: the runner.** `host` carries `{ scratchpad, deps }` only.
`nodeTool` keeps its construction-time runner — so a `withRunner` subtree does not leak its
override into wrapped sub-workflows across the seam. That is the locked design's boundary, not
an oversight (revisit only with a real use case).

## Interfaces

```typescript
// ---------------------------------------------------------------------------
// packages/agent-core/src/molecules/toolbox.ts — ToolExecutionContext (:29)
// ---------------------------------------------------------------------------
export interface ToolExecutionContext {
  readonly emit?: (event: ToolEvent) => void;
  readonly runId?: string;
  readonly traceId?: string;
  readonly parentToolCallId?: string;
  /**
   * Host-declared opaque passthrough — core NEVER interprets it (same
   * philosophy as `emit`: core declares the slot, the host wires the meaning).
   * The host copies its `RunOptions.host` here per tool call; a consumer that
   * knows the host narrows it itself (e.g. runtime's `nodeTool` reads
   * `{ scratchpad, deps }` to propagate run context across the
   * agent-as-tool seam, #124).
   */
  readonly host?: unknown;
}

// ---------------------------------------------------------------------------
// packages/agent-runtime/src/runner/types.ts — RunOptions (:113)
// ---------------------------------------------------------------------------
export interface RunOptions {
  // …existing fields unchanged…
  /**
   * Opaque host payload copied verbatim onto every `ToolExecutionContext`
   * this run's tool dispatches build (`buildToolCtx`). The runner never
   * reads it. The workflow layer uses it to carry `{ scratchpad, deps }`
   * across the agent-as-tool seam (#124).
   */
  host?: unknown;
}

// ---------------------------------------------------------------------------
// packages/agent-runtime/src/workflows/agent-step.ts
// ---------------------------------------------------------------------------
export interface AgentStepSpec<TIn, TOut = string> {
  // …existing fields unchanged…
  /**
   * Per-node runner override (#116). v1: a concrete RunnerProtocol — the
   * declared form of the ctx-rewriting closure hack. Resolution:
   * `spec.runner ?? ctx.runner`. NOTE: the structured-output guard checks
   * the RESOLVED runner; an override without `runStructured` fails loud.
   */
  readonly runner?: RunnerProtocol;
}

// AgentStep.run — resolution + host threading (edits within :102-127)
async run(input: TIn, ctx: NodeRunContext): Promise<NodeResult<TOut>> {
  const agent = applyStepModel(this.spec.agent, this.spec.model);
  const runner = this.spec.runner ?? ctx.runner;                    // #116
  const message = this.spec.prompt(input, slotReader(ctx.scratchpad));
  const opts: RunOptions = {
    toolExecutor: ctx.toolExecutor,
    maxIterations: this.spec.maxIterations,
    traceId: ctx.traceId,
    parentSpanId: ctx.parentSpanId,
    host: { scratchpad: ctx.scratchpad, deps: ctx.deps },           // #124
  };
  // …guard/calls at :114/:117/:127 use `runner` instead of `ctx.runner`…
}

// ---------------------------------------------------------------------------
// packages/agent-runtime/src/workflows/with-runner.ts — NEW (#116)
// ---------------------------------------------------------------------------
import type { RunnerProtocol } from "../runner/types.js";
import type { Node, NodeResult, NodeRunContext } from "./node.js";

/**
 * Run a whole subtree on a specific runner — the declared form of the
 * `{ ...ctx, runner }` closure hack. Transparent: preserves the inner node's
 * name and result. Precedence: a leaf's own `spec.runner` still wins inside
 * the subtree; nesting `withRunner` lets the innermost wrapper win. Does NOT
 * cross the agent-as-tool seam (a NodeToolbox keeps its construction-time
 * runner — #124 threads scratchpad/deps only).
 */
export function withRunner<TIn, TOut>(
  inner: Node<TIn, TOut>,
  runner: RunnerProtocol,
): Node<TIn, TOut> {
  return {
    name: inner.name,
    run: (input: TIn, ctx: NodeRunContext): Promise<NodeResult<TOut>> =>
      inner.run(input, { ...ctx, runner }),
  };
}

// ---------------------------------------------------------------------------
// packages/agent-runtime/src/runner/agent-runner.ts — buildToolCtx (:207)
// ---------------------------------------------------------------------------
private buildToolCtx(a: {
  traceId: string;
  runId: string;
  parentToolCallId: string;
  parentSpanId: string;
  host?: unknown;                       // relayed from RunOptions by the 3 dispatch sites
}): ToolExecutionContext {
  return {
    runId: a.runId,
    traceId: a.traceId,
    parentToolCallId: a.parentToolCallId,
    host: a.host,                       // #124 — the single copy site
    emit: /* …unchanged… */,
  };
}

// ---------------------------------------------------------------------------
// packages/agent-runtime/src/workflows/node-tool.ts — the seam (:53-63)
// ---------------------------------------------------------------------------
execute: async (args: Record<string, unknown>, ctx?: ToolExecutionContext) => {
  const input = spec.parameters.parse(args);
  // #124: prefer the LIVE caller context (delivered via the host passthrough)
  // over the construction-time closure. FORK, don't alias: run-scoped slots
  // share through the fork; branch-scoped slots stay isolated per (possibly
  // parallel) tool call. join()/merge-back is OFF for v1.
  const host = ctx?.host as { scratchpad?: Scratchpad; deps?: DepReader } | undefined;
  const result = await spec.node.run(input, {
    runner,
    scratchpad: host?.scratchpad ? host.scratchpad.fork() : (scratchpad ?? createScratchpad()),
    deps: host?.deps ?? deps,
    traceId: ctx?.traceId,
    parentSpanId: ctx?.parentToolCallId,
  });
  // …unchanged…
}
```

## Tests

All in vitest, following the harnesses already in the tree: `MockRunner` (+ `callHistory`) for
runner-identity assertions (`per-step-model.test.ts` precedent), and the
`MockLanguageModelV2` + real `AgentRunner` + shared-bus wiring for driving the actual tool loop
(`node-tool.test.ts:94-183` precedent).

**`workflows/__tests__/with-runner.test.ts` (#116):**

1. `AgentStep` with `spec.runner` — override `MockRunner` records the call (both text and
   structured paths); the ambient `ctx.runner` records **zero** calls.
2. Resolved-runner guard — `spec.runner` *without* `runStructured` + an `output` schema →
   `succeeded: false` with `StructuredOutputUnsupported`, even though `ctx.runner` supports
   structured output.
3. `withRunner(Sequential(a, b), runnerB)` — both leaves dispatch on `runnerB`; ambient runner
   untouched; result/output pass through unchanged and `name` is preserved.
4. Precedence — inside a `withRunner(…, runnerB)` subtree, a leaf declaring `spec.runner:
   runnerC` dispatches on `runnerC`; its sibling without one dispatches on `runnerB`.
5. `CoordinatorStep` with `spec.runner` — the routing turn dispatches on the override
   (`MockRunner.runStructured` history), not the ambient runner.

**`workflows/__tests__/host-propagation.test.ts` (#124)** — the locked design's three tests
plus seam units:

1. **Coordinator → subagent, run-scoped slot** (the doc's test 1, full rail): a
   `CoordinatorStep` run through the real `AgentRunner` (MockLanguageModelV2 emits one team
   tool call, then the final structured answer) with a root scratchpad carrying a written
   run-scoped slot; the delegated subagent's `AgentStep.prompt` reads the slot into its
   message → assert the child-side runner/model saw the value. Proves `AgentStep → RunOptions.host
   → buildToolCtx → ToolExecutionContext.host → nodeTool → fork()` end-to-end.
2. **Parallel branch isolation** (doc's test 2): two subagent tool executes against the same
   host scratchpad, each writing a **branch-scoped** slot → no clobber; each call saw a fresh
   branch scope; parent's branch scope untouched. (Unit-level: invoke the `nodeTool` execute
   twice with `ctx.host` set; concurrency-shaped via `Promise.all`.)
3. **Root deps reach the subagent** (doc's test 3): `provideDeps` at the root →
   `ctx.host.deps` inside a delegated `FunctionStep` (`fn(input, scratchpad, ctx)` reads
   `ctx.deps?.get(key)`) returns the root-bound client.
4. **Fork semantics at the seam** (unit): child sees parent's run-scoped value; child's
   run-scoped *write* is visible to the parent afterward (run entries shared by reference
   through the fork — `slot.ts:128`); child's branch-scoped write is **not** (no `join` in v1).
5. **Precedence + back-compat** (unit): `host.scratchpad`/`host.deps` win over closure args;
   no `ctx` / no `host` → closure-or-fresh behavior byte-identical (existing
   `node-tool.test.ts` stays green **unmodified** — that is itself the regression gate).

**Runner-side relay coverage** (in `runner/__tests__/agent-runner.test.ts` /
`agent-runner-stream.test.ts`): a capture tool (`execute: (_a, ctx) => …`) asserts
`ctx.host === options.host` on each of the three dispatch paths — `run()` (`:541`),
`runStructured()`/`convertExecutableTools` (`:697`), `stream()` (`:1312`) — and that omitting
`options.host` yields `undefined` (no accidental default).

**Acceptance gates (all must pass before PR):**

1. `bun run check` green (build + typecheck + lint + test, all packages).
2. Core purity: `packages/agent-core/src/molecules/toolbox.ts` gains no import — the `host`
   field is `unknown`; `rg -n '@agentic-patterns/runtime' packages/agent-core/src` stays 0 hits.
3. Existing `node-tool.test.ts` / `coordinator-step.test.ts` / `per-step-model.test.ts` pass
   **without modification** (additive-change proof).
4. `rg -n 'buildToolCtx' packages/agent-runtime/src` still shows exactly 1 definition + 3
   dispatch sites, each relaying `host`.

## Out of scope

- **Runner capability/policy objects** (`requires: { structuredOutput: "native" }`) — deferred
  until a second consumer exists (locked design). v1 override is a concrete `RunnerProtocol`.
- **Runner propagation across the agent-as-tool seam** — `host` carries `{ scratchpad, deps }`
  only; `nodeTool` keeps its construction-time runner.
- **`join()` / merge-back of subagent branch scratch** — OFF for v1 (no clean index order for
  call-and-return); revisit with a concrete use case.
- **Changing the closure-scratchpad aliasing** in `NodeToolbox`/`delegateTo` opts — existing
  documented behavior, untouched.
- **Version bump / lockfile** — #118 owns the stack's 0.8.0; `bun.lock` refresh is publish-only.
- **#117 (RunStore)**, the `Session` aggregate, AgentNode ↔ Node-world consolidation, `emit`
  bridging changes.
