- **Status:** PROPOSED — design review. **Supersedes specific statements in [ADR-0008](0008-compositional-memory.md)** (named in Decision 1); leaves [ADR-0007](0007-memory-store.md)'s store contract intact except for one named protocol extension (Decision 9). Program #414; epic #415.
- **Date:** 2026-08-08
- **Context owner:** Doug
- **Scope:**

  - `packages/agent-server`, `packages/agent-dashboard` — the two hand-mirrored `AgentPromptSectionData` declarations widen; `RolesPage.tsx:110` key-count fix.

## Context

The companion agent forgets things it demonstrably saved. "My name is Doug" then, in a fresh conversation, "what's my name?" works; "who am I?" returns nothing. `assembleRecall` has three tiers (`recall.ts:155-186`): a query-independent profile tier, an opt-in pinned-candidate tier, and a hits tier that passes the first user message verbatim to `store.search`. The hits tier is lexical — "who am I?" shares no content word with "The user's name is Doug" — and there is no zero-hit fallback. `kind:"profile"` records are phrasing-proof and that tier works; it is empty in practice because nothing taught the model to write them. **That half is already fixed on PR #451** (kind guidance in the Manual + a profile sub-budget) and is not relitigated here.

The residue #451 does not solve is the design problem: **a `fact` or `preference` whose wording misses the next question is unreachable, permanently.** ADR-0008's answer is right — identity and durable preferences should not be *retrieved*, they should be *composed*. `applyMemoryOverlay` is the mechanism and it does not exist. Two structural problems block writing it.

**Problem A — the Background atom is the wrong shape.** `BackgroundSchema` (`atoms/background.ts:9-14`) is four `z.record(z.unknown())` fields, rendered by `toPrompt()` (`:26-45`) as up to four fixed `## ` headings. All four are *project*-shaped. A companion has nowhere to put "the user's name is Doug" — the conformance kit's own canonical record files a **user's UI preference** under `conventions` (`memory/conformance.ts:78-82`). The census: 16 `new Background(...)` sites repo-wide, every one a library-internal default or a test; zero in `examples/`, `agents/`, or `presets/`; `conventions` is used exactly once, in a test proving the heading renders (`atoms.test.ts:250`). Nothing ships on this vocabulary. And Background renders as one undivided blob inside a single `{name:"Context", source:"instance"}` entry shared with Awareness (`organisms/agent.ts:138-153`), so ADR-0008 D3's fragment-level attribution is not expressible today.

**Problem B — the model decides where a memory lands.** `BackgroundTargetSchema` (`molecules/memory-record.ts:61-65`) pins a four-arm `section` enum plus a free-string `key`, and that enum is embedded in the model-facing `memory_save` schema (`memory/toolbox.ts:137`). Placement is a per-write judgment the model gets wrong, varies by model, and — under ADR-0008 D4's Auto tier (`0008:71`, "no approval") — a wrong `target` edits the agent's own system prompt with no human in the loop. A wrong `kind` merely costs recall quality; a wrong `target` costs prompt integrity.

The shape this ADR reaches for already exists in-repo. `workflows/backpack.ts` is a run-scoped accumulator where a developer-declared `BackpackSpec` owns the hooks and the *producer* never decides placement: `expand` (`:79`, null ⇒ skip, recorded; throw ⇒ fail loud at the write site), `identify` (`:88`), `merge` (`:94`), `finalize` (`:101`), `renderEntry` (`:104`) — all pure and synchronous, with `hydrateThenDrop` (`:643-651`) as the single named async escape hatch, and a structural test asserting the module emits nothing (`__tests__/backpack.test.ts:344-351`). Memory wants the same division of labour: **the model saves content; a developer-declared spec decides where.**

## Decision

1. **This ADR supersedes ADR-0008's atom-immutability promise, and says exactly which half.** Three statements are withdrawn:
   - `0008:7` — "no changes to any atom's schema or rendering", *and* the same line's parenthetical that `AgentPromptSectionData.source` gains `"memory"`. (`0008:7` and `0008:65` **contradict each other**: the Scope line puts `"memory"` on the section, D3 puts it "at the fragment level". D3 governs; the Scope line was shorthand.)
   - `0008:99` — "the anatomy absorbs memory with zero schema changes to atoms".
   - `docs/memory/evolution-cookbook.md:30-33` — "ADR-0008 adds **zero** schema or rendering changes to atoms".

   What replaces them: **`Background`'s schema changes; `Background`'s rendering does not.** The reshape is proven byte-identical for every legacy-constructed Background (Decision 3), so ADR-0008's actual claimed benefit — "No new render sections … facts land under existing `Background` headings" (`0008:98`) — survives whole. A new ADR rather than an amendment, because a fresh reader of 0008 must not inherit a promise that is false; and because 0008's own Rejected-alternatives section argues against structural rewriting, which an inline amendment would leave arguing partly against its own body. **ADR-0008 D3, D4, D5, D6 and D8 survive intact and are cited throughout.** Everything else in 0008 stands.

2. **Doug's three settled constraints, recorded not re-argued.**
   - **D-1 — vocabularies are opt-in presets, not schema defaults.** Section vocabularies ship in `packages/agent-runtime/src/presets/memory/`. The existing four become a project/company preset; a user-background preset ships beside it. The framework declares no opinion on user data until a developer opts in.
   - **D-2 — memory may FILL a declared section; it may NEVER DECLARE one.** Capability by declaration. This is verbatim the rule ADR-0008 already sets for judgment domains (`0008:61`: "a memory may not create a new judgment domain in v1 — that is a structural change reserved for humans").
   - **D-3 — backends must not diverge on search semantics.** The conformance kit exists to guarantee this. It **overrules** `docs/memory/guide.md:536-537`, which currently blesses the divergence ("Match granularity … deliberately NOT pinned … develop against the backend you ship on"). That bullet is deleted (Decision 13).

3. **`Background` gains `sections[]` + `entries[]`; the four legacy records stay, populated, forever.**

   ```ts
   BackgroundEntrySchema  = { section: string, key: string, value: unknown, memoryIds: string[] }
   BackgroundSectionSchema = { id: string, title: string, description?: string,
                               promotion: "locked"|"guarded"|"earned"|"auto" }   // default "locked"
   BackgroundSchema = { sections: [], entries: [], teamContext, projectContext,
                        conventions, currentState }   // legacy four retained
   ```

   `toPrompt()` iterates `sections`, emits `## ${title}` only for sections with entries, and formats each entry with the existing `_formatDict` recursion — **byte-identical output** for every legacy-constructed Background (verified against the real class over 16 render cases and 8 merge cases, 0 failures; the generated blocks appear verbatim in `rendering/__tests__/__snapshots__/renderer.test.ts.snap:65` and `organisms/__tests__/__snapshots__/agent.test.ts.snap:82,87`). Three traps the implementation must honour: legacy render order is a *fixed* four-way order, not input key order; an empty nested object emits a trailing newline; an empty section is skipped, not headed.

   `normalizeBackgroundInput()` runs in the ctor **before `super()`** — forced by C1, since `AgenticModel` stores a `ZodObject` and parses in the ctor (`atoms/base.ts:42-49`), so `.transform()`/`z.preprocess` are impossible. It declares the four legacy sections with the *same* tiers the project preset ships (not `locked` — see the critic finding below), folds legacy keys into `entries`, and **leaves the legacy records populated**. Idempotent under `replace()` (`base.ts:63-67`) because the fold skips any `(section,key)` already in `entries`.

   *Adopting a critic refutation:* an earlier design **cleared** the legacy records after folding. That breaks four live non-snapshot assertions in `packages/agent-server/src/__tests__/composition.test.ts` (`:321`, `:741`, `:742`, `:759`) which read the raw blob the server ships at `routes/composition.ts:710,871` — that blob *is* the composition wire contract, and the dashboard renders it (`AgentLensPage.tsx:309`). The stated reason for clearing (base `merge()` would double-count) is void: `Background` overrides `merge()` wholesale (below), so base merge never runs. Retention also removes both dashboard regressions at a stroke.

   `merge()` is overridden — `AgenticModel.merge()` is type-directed (`base.ts:87-89`: arrays CONCAT, records SPREAD), so moving to arrays would silently flip "other overwrites key" into "same key rendered twice". The override merges by identity (`section.id`; `${section}\0${key}`) reproducing JS object-spread positioning exactly. `Awareness` already overrides `replace()` for the same class of reason (`ADR-0005:129-132`). **Corollary, found empirically:** the normalizer must declare *all four* legacy sections whenever any is non-empty, not just the populated ones — a legacy Background implicitly declares all four in canonical order, and declaring only the populated ones fails a merge section-order case (`{currentState}` merged with `{teamContext}` renders in the wrong order).

   `AgentConfig`'s ctor pre-normalizes `data.background` — **mandatory, not optional.** C2 is real: `background: BackgroundSchema` is `.parse()`d without the ctor at `atoms/agent-config.ts:63`, `:136` and `organisms/agent.ts:30`. Without ctor-side normalization, every legacy-authored config presents `sections: []` and the overlay declines *every* record as `undeclared-section` — a silent total no-op of the feature.

4. **`MemoryTarget` is DERIVED BY THE ROUTING SPEC AT PROMOTION, not authored by the model at save. (R-1 — adopted, with its first rationale discarded.)**

   R-1's determinism argument is **unsound and must not appear in this ADR**: `target` is a frozen field on a frozen record (`memory-record.ts:202`, deep-frozen at `:231-245`), so the fold is deterministic no matter who produced the value; `content` is equally model-authored and is rendered verbatim. Non-determinism at write time is not non-determinism at fold time. The three arguments that survive:

   - **Blast radius.** ADR-0008 D4 puts `background.*` in the Auto tier — "written + reconciled (audited via events; no approval)" (`0008:71`). Auto sections are real and shipped: the user-background preset declares `promotion: "auto"` precisely so the motivating case ("my name is Doug", no human in the loop) works. A model-authored address into an auto section is an unapproved edit to the agent's own system prompt.
   - **Model-independence, sharpened by D-1.** `MemoryTargetSchema` is a static module-level Zod value (`memory-record.ts:101-108`) embedded in the tool schema (`toolbox.ts:137`). Per-agent vocabularies cannot be expressed there without minting a per-toolbox tool schema, and `section` would have to widen to `z.string()` for persistence anyway. Once the vocabulary is developer-declared there is no stable enum left to show the model.
   - **Reversibility.** Adding a model hint later is additive. Withdrawing authority later breaks stored records *and* the tool contract.

   **`target` is removed from `SaveParamsSchema` (`toolbox.ts:137`) and from `MemoryRecordViewSchema` (`toolbox.ts:128`).** It stays on `MemoryWriteInput` (`store.ts:57`) for host/import paths, and stays on `MemoryRecord` untouched — already-stored model-authored values are reinterpreted as routing **input** (an advisory signal a spec may read, exactly like `tags`), never obeyed as output. No migration, no backfill, no re-parse risk.

   **Consequence to own:** `0008:55`'s "`target` is a *proposal*, not a promotion" becomes vestigial — there is no longer a stored proposal to be. The sentence's spirit survives (nothing pre-promotion is a promotion); its mechanism does not. Retire it rather than preserve it, or a reader of 0008 will assume the model still writes it.

5. **The model authors a `label`; the spec authors the address. (Closing the hole the critic found.)**

   `target` carried *two* things — a section **and** a `key`. Withdrawing model authority over the section is well-argued; withdrawing it over the key was not, and every pure-sync alternative fails: one fixed key per `kind` makes "the user's name is Doug" and "the user lives in Denver" collide at one address (the rekeyed D2 gate then demands a supersede that destroys the first fact — a catastrophic regression on the exact motivating scenario); a content hash makes nothing ever collide, so `reconcile` is dead code and the section grows until budget spill; deriving a key from prose is the thing a pure spec explicitly cannot do.

   Therefore: **`memory_save` gains `label?: string` (≤64 chars) — a NAME for the thing learned ("name", "timezone", "theme"), carrying no section, no primitive, and no addressing authority.** The spec may slugify it into the key segment, or ignore it. If absent, the spec falls back to a content-derived key (append-only, `reconcile` inert for that record). This is *not* the rejected "model proposes placement" hybrid — the model names the thing it learned; the spec still decides where it goes — and it restores the "change the key" remedy the D2 gate's guidance offers today (`toolbox.ts:333`), which Decision 4 would otherwise have to delete.

   `label` is an **additive optional field** on `MemoryRecordSchema`, `MemoryWriteInputSchema` and `SaveParamsSchema`. Every existing row parses. Unlike a union widening, an additive optional field does not break an exhaustive switch. See Decision 15 for the external precondition.

6. **The routing spec: type in core, instances in runtime presets, resolved by name at the instantiate seam.**

   `molecules/memory-routing.ts` (Layer 2, beside `memory-record.ts`) declares `Placement`, `placementKey`, and the spec interface. Preset **instances** live in `packages/agent-runtime/src/presets/memory/` per D-1. Resolution mirrors `capabilities: z.array(z.string())` + `CapabilityResolver` (`atoms/agent-config.ts:68`, docblock `:13-16`) exactly — a spec is a bag of *functions*, so it cannot live in `AgentConfig`, which is "declarative, serializable" by its own docblock (`agent-config.ts:1-3`).

   ```ts
   interface MemoryRoutingSpec {
     readonly key: string;  readonly version: string;
     readonly route:     (r: RoutableRecord, ctx: RoutingContext) => Placement | null | undefined;
     readonly reconcile?: (a: RoutableRecord, b: RoutableRecord) => "a" | "b" | "both";
     readonly finalize:  (placed: readonly PlacedRecord[], report: RoutingReport) => OverlayPlan;
     readonly renderEntry?: (placed: PlacedRecord) => string;
   }
   ```

   All hooks **pure and synchronous**, mirroring `backpack.ts:19-25`. Mapping: `route ← expand` (same null-means-skip contract), `reconcile ← merge`, `finalize ← finalize` (pure, idempotent, memoisable), `renderEntry ← renderEntry` — now load-bearing, because ADR-0008 D3 needs a per-fragment attribution unit. **Dropped from the backpack shape:** `identify` (`backpack.ts:88`) — backpack needs it because entries are opaque, but a `Placement` is typed, so identity is a framework function (`placementKey`), not a spec hook; also `absorb` (no branch scope) and the `[#N]` IndexedView machinery (memory's handles are record ids, which D3 already requires). **Added:** a frozen `ctx` second argument (purity survives — `RoutingContext` is a value, not the pad), and `version` (a spec outlives runs; its identity must land in the ledger, `0008:82`).

   `placementKey(p)` — total, injective, stable — **replaces `sameTarget` (`toolbox.ts:92-107`) entirely**, and fixes a live bug in doing so: `sameTarget` returns `true` for *any* two `awareness` targets and *any* two `recovery` targets (`toolbox.ts:100-101`, "discriminant-only arms"), so today all awareness memories collide as one address and the D2 gate lets exactly one through per scope, forever.

   The routing module **emits nothing**, per the backpack precedent (`backpack.ts:15-17`), pinned by a ported structural source-scan test (`backpack.test.ts:344-351`). Instrumentation lives in the promotion Play, which owns `agent.memory.promote` / `agent.memory.overlay` (`0008:80`).

7. **v1 routes `background` only.** *Adopting a critic finding:* an earlier design gave `RoutingContext` a declaration list for background sections and judgment domains, and none for `example`, `awareness`, `recovery` or `manual` — so D-2 was mechanically enforced for two of six arms, and `recovery` (guarded tier, `0008:73`) had the highest blast radius with no declaration gate at all. Rather than invent four declaration mechanisms speculatively, **`PlacementSchema` in v1 admits the `background` arm only.** This narrows `0008:130`'s Phase B ("auto-tier only — background/awareness") to background; awareness placement lands with its own declaration surface in a later phase. `section` is `z.string().min(1)` — forced by D-1 regardless of authorship, and harmless now that the value is system-derived.

8. **B-2 settled: NEWEST-CREATED WINS, tiebreak `id` ascending.** The merged specs contradict. `0008:62` says the overlay "renders the **newest** deterministically"; `docs/memory/guide.md:354` says "Conflicts between learned records resolve by `createdAt` (older wins)". `guide.md:635-641` and `evolution-cookbook.md:830-835` partly reconcile this — conflicts are **supersede-first**, enforced at write in #421 — and that half is settled and not in dispute. What remains contradictory is the *residual arbitration direction*, which both docs give as older-wins and the ADR gives as newest.

   Newest wins. Three reasons: newest is already the shipped resolution at the write-time collision picker (`toolbox.ts:322-327` takes the newest `createdAt` — stated here as an *inference* about intent, since that reducer chooses which record to *report*, not which renders); it matches every other recency semantic in memory (`store.ts:130-133`, `sqlite-store.ts:239`, the profile tier at `recall.ts:155-158`); and under older-wins a corrected fact loses to the one it corrects whenever the agent forgets `supersedes` — permanently unfixable by the agent or the user, which reproduces the exact bug class this program exists to close.

   **The equal-`createdAt` case is common, not exotic:** both reference stores assign one `now` per batch (`store.ts:139`, `sqlite-store.ts:258-259`) and the conformance kit ships a `tick()` helper *because* ties are the default (`conformance.ts:16-22`). So any multi-record write ties exactly. `id` ascending, compared with raw `<`/`>` (never `localeCompare` — locale- and ICU-dependent), is arbitrary but **total and stable**, which is the entire requirement. Order by `createdAt`, never `updatedAt` (`conformance.ts:286-298` pins that `updatedAt` moves only on invalidate).

   *Adopting a critic finding:* pin this in **`applyMemoryOverlay`'s own unit tests**, not the store conformance kit. D-3 governs *search* semantics across backends; the overlay tiebreak is a pure core fold and no backend can diverge on it.

   **Documents corrected in the same PR:** `guide.md:354` (older-wins → newest-wins + id-asc); `guide.md:641` and `evolution-cookbook.md:835` (the last-resort tiebreak is now `id` ascending, not `createdAt` ascending); `guide.md:578-586`, which states in bold that "the model *may* propose targets" and that "`memory_save` **does** expose `target` to the model" — reworded to "the model contributes content signals; the routing spec derives placement".

9. **Routing is EVALUATED freely and COMMITTED once, at promotion.** `route()` is pure, sync and cheap, so it may be evaluated wherever useful: at `memory_save`, to compute the address for the rekeyed D2 gate; inside `assembleRecall`, because ADR-0008 D4's candidate exposure currently identifies candidates by `record.target !== undefined` (`recall.ts:168`) and that predicate dies with model authorship — candidacy becomes "routing would place it", computable in-process with no store change; and in the dashboard / `lintComposition` preview (`0008:88`). It is **committed exactly once**, at promotion, onto the ADR-0008 D5 promotion row as `placement` + `specKey` + `specVersion` + `promotedAt` + tier. `MemoryRecord`'s schema is untouched by this.

   Why the promotion row and not the record: recomputing at instantiate means a spec edit silently re-places memories a human approved under the old address; and a create-only `MemoryWriteInputSchema` (`store.ts:51-61`) could only write a placement at *birth*, i.e. before promotion, which is the semantics being removed.

   **Two consequences stated rather than buried.** (a) `applyMemoryOverlay(config, records)` as written at `0008:7` is unimplementable — the signature becomes `applyMemoryOverlay(config, placed: PlacedRecord[], spec) → { config, report }`, with the runtime performing the record ⋈ promotion-row join. (b) **Store precondition:** rekeying the D2 gate onto a derived address means essentially *every* `memory_save` now routes, and today's gate pays an unfiltered 500-record recency page (`COLLISION_SCAN_LIMIT`, `toolbox.ts:67-75`, whose own docblock documents that past 500 newer records "its collision slips past the gate"). A **placement-keyed lookup on `MemorySearchQuery`** — an ADR-0007 protocol extension, exact-equality, conformance-pinned from day one — is a *precondition* of this decision, not a follow-up. It removes the blind spot and the per-write cost together.

10. **Routing outcomes are three-way, all recorded, none silent, and none a throw on the normal path.**
    - `route()` returns `null` ⇒ **declined**, reason `spec-declined`. The record stays recall-tier forever — which `0008:116` already calls the correct failure mode.
    - The placement names a section not in `ctx.sections`, or a committed placement's section was later removed ⇒ **declined**, reason `undeclared-section`.
    - The address is already held by authored config ⇒ **declined**, reason `authored-wins` (`0008:60`). This is a *fold-time* decline, not a route-time one — authored config can change after promotion — and the report separates the two.
    - A `Placement` that fails `PlacementSchema.parse` ⇒ **throw**. That is the only throw, and it is a spec bug by construction.

    *Adopting a critic refutation:* an earlier design made an undeclared section a **throw**, framed as "the mechanical enforcement of D-2". It inverts D-2. D-2 says memory may fill a declared section; the correct consequence for an agent with no user-background section is "this fact stays recall-only". Concretely: one shared preset spec, two agents, agent B opts out per D-1 — every `memory_save` and every turn-1 `assembleRecall` for agent B would throw. A developer following D-1 exactly as written would brick agent B. Backpack's throw is safe because it is confined to one write site (`backpack.ts:322-334`); here evaluation is spread across three sites, one of them on the first-user-message critical path.

    **The outcome is never reported back to the model.** A `memory_save` return that says `composed: false` teaches the model to rephrase until it gets composed — the placement-gaming authority Decision 4 withdraws, re-acquired through a feedback channel. Outcomes go to the report, the event, and the dashboard.

11. **Async classification is a named separate function, never an async hook.** `classifyThenRoute(records, ctx, spec, classify)` mirrors `hydrateThenDrop` (`backpack.ts:637-651`) exactly, including that the client comes from the tool's own deps and never from the spec. The classifier may only **enrich advisory signals**; it may never produce a `Placement` — otherwise every argument in Decision 4 returns through a side door. Signals persist on the promotion row, not by mutating the record (the store has no annotate/update path: `store.ts:51-61` is create-only, and `store.ts:69-119` has no update operation).

    *Stating a critic finding rather than smoothing it:* signals on the promotion row do **not** exist at `memory_save` or `assembleRecall` time, so under the async path the address used by the D2 gate and by recall candidacy is computed *without* signals while the committed address is computed *with* them. They disagree by construction. v1 resolves this by **shipping the shape unused**: `classifyThenRoute` is exported, no preset uses it, and the pure path is the only live path. Enabling it requires either confining evaluation to promotion only, or a pre-promotion annotation operation on the store protocol. Named, not solved.

12. **Attribution: fragments beside sections, never instead of them.** `AgentPromptSectionData` (`organisms/agent.ts:44-48`) keeps `name` / `source: "role" | "instance"` / `text` **unchanged** and gains `fragments?: readonly AgentPromptFragmentData[]` — a plain TS discriminated union on `source`, with a `"memory"` arm carrying non-empty `memoryIds` plus `memoryChannel: "overlay" | "recall"`. The channel is an addition to ADR-0008 D3 and is load-bearing: the recall block *already* injects memory prose into the Context section via `Awareness.recallRender` and is attributed `"instance"` today, so without a channel the dashboard cannot distinguish "composed into the self" from "narrated this turn" — the exact distinction the tier table rests on (`0008:67`).

    Invariant, pinned in `agent.test.ts`'s existing `renderSections` block: separators fold **into** the fragment slices, so `(s.fragments ?? [{text: s.text}]).map(f => f.text).join("") === s.text`. No configurable separator — a `fragmentSeparator` field would be a second source of truth, and the two real producers already disagree (`background.ts:44` joins blocks with `\n\n`, `:60` joins lines with `\n`). Structural text — the `## Context` wrapper (`rendering/sections/context.ts:21`) and section headings — is `source: "instance"` **by rule**, so the partition stays total.

    `ContextSection` does **not** split, and `Background` does **not** get its own section: the list stays the exact six entries asserted at `agent.test.ts:333-341`, and zero snapshot bytes change. `PromptSection` (`rendering/sections/base.ts:11-27`) gains an **optional** `renderFragments?` — required would break external implementers of an exported interface — and the inline tuple type at `agent.ts:139-141` widens to admit it.

    Per-entry provenance lives **on the entry, as schema data** (`BackgroundEntry.memoryIds`), not in a side map: `AgenticModel` freezes `schema.parse(data)` (`base.ts:48`), zod strips unknown keys, and `buildAgentFromConfig` reconstructs via `new Background(cfg.data.background)` (`:99`) — a side map does not survive one instantiate. The server also calls `renderSections()` **nullary** (`routes/composition.ts:687`) and never builds a `RenderContext`, so a ctx-threaded map would yield zero attribution on the one surface D3 exists to feed. Two consequences: overlay-derived fragments appear in introspection while recall-derived ones do not (defensible — introspection shows the agent, not one turn — but it must be documented); and because `source`/`memoryIds` are now authorable data, **the overlay report is the display authority** — the dashboard must not resolve memory chips for attribution that merely appears in stored config.

    **Drift guards.** The server mirror (`routes/composition.ts:112`) widens loosely and gets an *exact-shape* compile check in `composition.test.ts` (which already imports core directly): a plain assignability assertion cannot work — core's widened return is assignable to the narrow mirror *and* the reverse holds because the new field is optional — so it must be an `Equals<A,B>` helper, and `AgentIntrospect` must be exported. The dashboard mirror (`api/composition.ts:20-25`) has **no** cross-package import anywhere and stays hand-maintained; say so rather than pretend otherwise. `RolesPage.tsx:110` counts top-level keys and is fixed here, not deferred: it reports "4 keys" for an empty Background today and would report a constant "6 keys" after this change — a regression this ADR causes.

13. **Conformance: Tier 1 universal, Tier 2 per capability class; both backends change.** D-3 is enforced by splitting `runMemoryStoreConformance` into a universal tier and a `caps.search`-keyed tier over one shared corpus, asserting **match sets** (ids sorted), never total order.

    Measured divergences between the two shipped backends: `InMemoryMemoryStore.search` matches substrings (`store.ts:223-228`, `haystack.includes(token)`) so `"am"` hits `"name"` and `"prefer"` hits `"Prefers"`, while FTS5 matches whole tokens and returns zero; FTS5 folds diacritics (`"cafe"` hits `"café"`) and in-memory does not. **The in-memory store adopts token semantics** — FTS5 is what the shipped companion runs on, and the future Postgres tsvector backend is token-based too, so aligning in-memory aligns 3-of-3 rather than 1-of-3.

    *Adopting two critic findings.* (a) **SQLite changes too.** `sqlite-store.ts:377-385` tokenizes the *query* on whitespace and OR-joins each token as a quoted FTS5 **phrase**; if in-memory splits on punctuation while SQLite keeps a punctuated token as an adjacency phrase, the fix *creates* a new divergence. Lift one shared exported `tokenize()` used by both, and have SQLite OR-join the resulting sub-tokens individually. (b) **The multi-token boolean combinator is the most portability-critical axis and was missing.** `sqlite-store.ts:380-383` documents OR as deliberately chosen against FTS5's implicit AND; Postgres `plainto_tsquery` defaults to AND. Tier 2 must contain a case whose tokens do *not* co-occur in one record, or a Postgres backend declaring `"keyword"` passes every test and is still non-conformant.

    Tier 1 additionally pins: batch-tie ordering (`write([a,b,c])` in one call, then a limited query-less listing — today in-memory returns `[a,b]` and SQLite returns `[c,b]`, **different records**, which `sqlite-store.ts:243-248` currently blesses as "outside the contract"); and unknown-target tolerance (Decision 14). **Total ranking order is explicitly NOT pinned** — in-memory ties at score 1 and falls to recency while FTS5 uses bm25; pinning it would force in-memory to reimplement bm25 and then fail a `ts_rank` backend, relocating the divergence rather than removing it. D-3 is honoured on match semantics and on the two ordering invariants already in the kit (`conformance.ts:244-260`); it is *narrowed* on total rank order, and that narrowing is stated here rather than left implicit.

    `guide.md:536-537` is deleted and replaced by the Tier-1/Tier-2 statement plus this carve-out.

14. **A malformed stored `target` must degrade, not detonate — and this ships one release before any vocabulary change.** Reproduced: rewrite one row's `target.section` to an unrecognised value and *every* query-less listing on that partition throws, because `_rowToRecord` (`sqlite-store.ts:477-495`) runs `memoryRecord()` → `MemoryRecordSchema.parse` inside `rows.map`. One bad row kills the partition's recall, it does not skip a record. So `MemoryRecordSchema.target` (`memory-record.ts:202`) widens to a union with a tolerant `{ primitive: string }` passthrough arm, pinned in Tier 1, **before** anything else in this ADR lands. Three call sites widen with it and must keep their exhaustiveness via a narrowing helper rather than by loosening: `targetPayloadSchema` and its `never` guard (`memory-record.ts:146-167`), `sameTarget` (`toolbox.ts:92-107`, deleted by Decision 6 anyway), and `MemoryRecordViewSchema` (`toolbox.ts:128`), which is what gets handed back to the model. No SQL migration and no `PRAGMA user_version` bump: `target` is opaque JSON TEXT (`sqlite-store.ts:105`) and the break is purely at the Zod boundary.

15. **B-3 is a PRECONDITION, not a resolved fact.** ADR-0008 names an external `codegen-patterns` `agents` subsystem that persists overlays (`0008:10`, `0008:83`) — and `0008:10` itself reads "**External (design alignment only)**", which is the strongest available evidence that this is forward-looking alignment rather than an installed base. Probes run from here found no `MemoryTarget` reference, no `@agentic-patterns/*` dependency, and no `agents` or `memory` subsystem on the branches inspected. **That is not proof.** GitHub code search indexes default branches only; two of ~40 branches were walked; private checkouts and anonymous npm consumers of `core@0.17.0` / `runtime@0.38.0` are invisible.

    The named checks, to be run by someone with repo access **before this ADR is accepted**: (1) grep for `MemoryTarget` / `MemoryTargetSchema` / `BackgroundTargetSchema` imports from `@agentic-patterns/core`; (2) grep for any exhaustive switch on a `target.primitive` discriminant; (3) confirm whether that repo writes `target` on its own rows or mirrors `MemoryRecord` columns; (4) **grep for `runMemoryStoreConformance`** — ADR-0007 D11 (`0007:94`) asserts that subsystem imports and runs the kit, and Decision 13 changes its shape; (5) grep for persisted `AgentPromptSectionData` payloads. One correction to the record: `MemoryTarget` is exported from `@agentic-patterns/core` (`molecules/index.ts`) but is **not** re-exported by `@agentic-patterns/runtime` — the external surface is narrower than previously believed, though `MemoryWriteInputSchema` (`store.ts:57`) still embeds it structurally. Until (1)–(5) are answered, every claim here reads "additive in this repo, **unverified externally**".

16. **Version and landing order.** `bash scripts/bump.sh --lockstep 0.39.0 --core 0.18.0` — absolute versions, not `minor`. This worktree reads core 0.16.0 / lockstep 0.37.0 and `origin/main` agrees, but npm `latest` is already core 0.17.0 / runtime 0.38.0 (the release commit is on the unmerged `mem/*` stack), so a relative bump lands on already-published versions which `scripts/publish.sh:127-131,160-163` **skips silently**. Precondition: the `mem/*` release stack must merge to `main` first.

    **No codemod.** ADR-0002's 0.9.0 precedent (hard break + `scripts/migrate-to-camelcase.ts`) does not transfer: it renamed keys in *source* this repo owns; the equivalent here would have to reach persisted `AgentConfig` rows in another repo's database, which a repo script cannot do. That asymmetry is the strongest independent argument for Decision 3's keep-the-legacy-fields choice. The 16 `new Background(...)` sites are all internal defaults and tests — a human edits them in one sitting. An exported `migrateBackgroundData(raw)` helper ships as the deprecation seam for owning apps.

    **Landing order, and the first item is not negotiable:** (1) point the eval harness at the shipped backend — it constructs `new InMemoryMemoryStore()` per family and per case while the companion boots `loadMemoryStore()` → SQLite, so the recall family currently scores the *substring* matcher and the budget family's truncation depends on a batch-tie order that is reversed between backends. Pass an explicit temp `path` (never a process-wide `AP_MEMORY_DB_PATH`, which would point evals at the user's real db), and **exit 2** if `loadMemoryStore` reports `unavailable` — it silently returns an in-memory store on both failure paths, which is precisely the bug being fixed. Then (2) conformance Tier 1/Tier 2 + tokenizer; (3) tolerant target read (Decision 14); (4) `label` + routing spec + derived placement; (5) Background reshape + attribution. Steps 1–3 contradict no merged ADR and can land as a small stack while this ADR is in review.

## Consequences

**Good**

- Identity stops depending on phrasing. A `kind:"profile"` record routed by a user-background preset composes permanently, and the lexical hits tier becomes irrelevant for identity questions — which is the reported bug, closed structurally rather than by better search.
- The framework ships no opinion about user data. A companion declares a user vocabulary; a code agent declares a project one; neither inherits the other's headings (D-1).
- Placement stops being a per-write model judgment. It becomes a developer-declared, versioned, testable pure function, with the same discipline the backpack already proves in-repo.
- Rendered prompt bytes do not move. The reshape is proven byte-identical, so it can land under a strict no-`-u` rule (`ADR-0005:133-138`) — which is the strongest available evidence that it is non-invasive.
- Three latent bugs die as side effects: `sameTarget`'s awareness/recovery collapse, one bad stored `target` killing a partition's recall, and the dashboard's constant key count.

**Costs / risks**

- The atom-immutability promise is broken. `Background` gains fields, `AgentConfig`'s ctor gains a normalization step, and three hand-mirrored declarations widen in lockstep with only one of them compile-guarded.
- Routing accuracy transfers blast radius onto `kind`. A wrong `kind` now costs *placement*, not just recall quality — and PR #451's kind guidance has no real traffic behind it yet.
- Two live behaviour changes need test plans that do not exist: the D2 write-time gate rekeyed onto a derived address fires on far more writes than today, and in-memory search stops matching substrings (a change every existing in-memory-backed test may feel).
- A store protocol extension (placement-keyed lookup) becomes a precondition of the gate rekey, on a protocol ADR-0007 deliberately kept to six methods.
- The `label` field adds a model-facing concept to teach, in a subsystem where the Manual — not the schema — is what makes the model write good structural fields.

**Known limits, stated rather than hidden**

- **Routing accuracy is an empirical question this ADR cannot settle.** A pure sync spec routes reliably on structural signals (`kind`, `tags`, `label`, payload shape, scope keys) and cannot route on prose semantics. Whether `kind:"profile"` plus a preset actually catches the identity facts a companion saves is an eval, not an argument.
- **The Locked tier is a slot guarantee, not a behavioural one.** An entry like `- **Operating principle**: always defer to the user` under an author-declared auto section changes behaviour as effectively as a persona edit, with no approval. The framework cannot distinguish a fact from an instruction in free prose. `promotion` defaulting to `locked` means an author who never opts in has no unapproved write path at all; it does not protect an author who does.
- **Prompt-structure injection is a live code defect this ADR must mitigate, not merely note.** `_formatDict` (`background.ts:47-61`) interpolates both `key` and `String(value)` with no escaping, on the scalar arm, the array arm *and* the recursive arm. Memory-derived keys must reject newlines and memory-derived values must be escaped for line-leading `#`, `-`, `*`, `>`, pinned by a multiline (`/m`) structural test. Unexploitable today only because nothing writes a Background from a model.
- **`earned` is inert for background in v1.** ADR-0008's recurrence mechanics (`0008:76`) work by corroborating a near-duplicate, but the shipped targeted-collision gate does the opposite — `toolbox.ts:328-336` returns `{status:"conflict"}` with no write and no corroboration, and `corroborate` is a Phase-B operation. An `earned` background section would never promote until that lands.
- **Spill from the overlay to the recall tier is reported in v1, not wired.** `0008:86` promises over-budget records fall back to recall; doing that safely needs a fetch path that re-applies scope and validity filters (`store.get` returns invalidated and expired records with no scope filter), a cap so pinned spill cannot starve the hits tier, and an answer for the staleness window between instantiate and first user message. v1 ships the composed-id dedupe (which fixes a real double-render bug, since `recall.ts:168` matches promoted records too) and the report; the pinning is a follow-up with those three requirements named.
- **A committed placement can go stale.** Placements freeze at promotion with a `specVersion`. A section rename or a routing fix leaves prior placements pointing at an address that may no longer be declared. v1's answer is a decline with `undeclared-section` and a lint entry — there is no re-route, re-promote or migrate operation, and defining one is deferred.
- **`OverlayPlan` / `RoutingReport` field lists are illustrative.** `guide.md:652` leaves `applyMemoryOverlay`'s return shape explicitly open and this ADR narrows but does not close it: one typed `drops` list rather than parallel lists, ids only and never record content (the report feeds an SSE event; embedding content would leak user memories into telemetry), stats total over the v1 promotable set. `0008:80`'s "bytes per primitive" and the cookbook's `bytesPerPrimitive` (`:175, :181, :321, :443, :571, :710, :737`) contradict the chars pin and must be renamed `charsPerPrimitive`.
- **Budget numbers have no empirical basis.** The only figure anywhere is illustrative ("say 1,000 chars for background", `evolution-cookbook.md:730-731`). The *policy* is defensible — per-primitive, chars not tokens, overlay-background below `DEFAULT_RECALL_BUDGET_CHARS = 4000` (`recall.ts:35`), whole-entry granularity, spill order `supports.length` DESC → `createdAt` DESC → `id` ASC. The digits are not. Two constraints that are not negotiable: the composition-wide ceiling must sit **strictly below** the sum of the per-primitive budgets or `ceilingBreached` is unreachable dead code; and the accounting counts only memory-derived entry text, which is a **departure** from recall's scaffold-inclusive accounting (`recall.ts:236`), not a reuse of it.
- **Spill priority does not use `kind`.** `evolution-cookbook.md:802-806` records that `kind` is a recall concern and `target` alone governs composition. Protecting `kind:"profile"` from spill would also invert the substantive argument: profile records are the one kind with a guaranteed always-injected recall tier, so they are the *safest* to spill.

## Rejected alternatives

- **Model proposes, spec decides (hybrid placement).** The proposal is worthless if the spec is authoritative, and non-worthless only if the spec is tempted to obey it — which re-opens exactly the authority being withdrawn. `label` is not this: it names the thing learned, it does not name a section.
- **A second free-text hint parameter.** The hint channel already exists and is called `tags` (`toolbox.ts:136`) — model-authored, persisted, searchable. A second one adds a surface to teach and validate for zero new capability.
- **Keep model authorship and gate every background write.** Defeats ADR-0008 D4's Auto tier, whose entire point is that settled facts land without approval.
- **Widen `MemoryRecord.target.section` to `z.string()` and add `targetSource`.** Additive for this repo's readers, breaking for any external exhaustive switch, and it leaves two semantics living in one field forever. Moving the derived address to the promotion row avoids the question entirely.
- **Recompute placement at every instantiate, store nothing.** Cheapest to build; destroys ADR-0008 D5's point-in-time reconstruction (`0008:82`) and makes gate approval meaningless — a human approves an address the next spec edit changes.
- **Make the routing spec Zod-serializable data so it can live in `AgentConfig`.** Appealing for persistence and dashboard editing, but a declarative rule table is a DSL that will grow into a language. The backpack precedent is that developer-declared hooks are code.
- **Remove the four legacy `Background` fields.** Silently drops stored config data at three `.parse()` sites that bypass the ctor, and breaks four live wire-contract assertions in the server's composition tests. Zod strips unknown keys with no diagnostic, so even a deprecation window would be invisible.
- **Split `ContextSection`, or give `Background` its own prompt section.** Changes every existing agent's delivered prompt, breaks the exact-section-list test and two snapshots, and buys nothing fragments do not already buy.
- **Fix the `##`-inside-`## Context` nesting and the `## Current State` / `State`-atom collision here.** Both are real (`background.ts:29-41` vs `rendering/sections/context.ts:21`; `atoms/state.ts:43`), and both are prompt-*bytes* changes requiring `-u`, cache invalidation and an eval re-baseline. Bundling them destroys the byte-identity proof that is this reshape's entire safety argument, and makes an intentional diff indistinguishable from a regression. Separate PR, deliberate snapshot update. Note the reshape *shrinks* the collision to near zero: `title` is now data.
- **`promotable: boolean` on a section.** Cannot express "learnable, but a human confirms" — which is ADR-0008's existing Guarded tier and the right posture for most sections. The four-state `promotion` enum reuses `0008:69-74`'s own tier names, so no new vocabulary enters the system.
- **Change `SqliteMemoryStore` to substring matching.** Abandons FTS5/bm25, is the production backend, and diverges from the future Postgres backend.
- **Implement bm25 in `InMemoryMemoryStore` to pin total order.** Would then fail a Postgres `ts_rank` backend — relocates the divergence instead of removing it.
- **Mark ADR-0008 Rejected.** Overkill. D3, D4, D5, D6 and D8 all survive intact and are load-bearing here.

## Open questions for Doug

1. **`label` on `MemoryRecord` — accept the additive field?** It is the only pure-sync answer to key derivation that neither collides every profile fact at one address nor makes `reconcile` dead code. It is an additive optional record field, which is a materially smaller external exposure than a union widening — but it *is* a record change, and Decision 15 is unverified.
2. **Default `promotion` for a declared section: `locked` or `guarded`?** `locked` is honest ("declared for authoring, not for memory") and matches D-1's opinion-free posture. `guarded` is more useful but requires a `HumanApprovalGate`, and **no agent has one wired today** — so a guarded default means "the agent saves a fact and the fact never reaches the agent", which is the originating bug shipped as the framework default. This ADR picks `locked`; both are defensible.
3. **Should memory fragments be visibly marked in the prompt?** `0008:98` states the goal as "indistinguishable from authored composition in the prompt while remaining fully distinguishable in the tooling". That is a values position, not a technical one, and it is the one thing that would make the semantic Locked-tier bypass legible to the model itself.
4. **Budget digits.** The relationships are defensible; the numbers are invented. Ship as tunable defaults with the ~10k-char worst-case memory-attributable prompt spend stated, or measure first?
5. **Does ADR-0008 change status?** It stays `PROPOSED` today. Options: leave it, mark it `SUPERSEDED IN PART (see ADR-0009)`, or add a one-line header pointer. A fresh reader hitting `0008:99` unaided is the failure mode this ADR exists to prevent.
6. **Is the semantic Locked-tier bypass (Known limits, bullet 2) an accepted limit or a blocker for the auto tier?** If it is a blocker, the user-background preset must ship `guarded`, and question 2 answers itself.
